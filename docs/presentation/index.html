데이터 질문 어시스턴트

말하듯 물어보면, 안전하게 확인된 ‘조회 전용’ 결과를 돌려드립니다
누구나 물어본다 고칠 수는 없다 모든 행동이 기록된다
사내 데이터 질문을 돕는 AI 어시스턴트 · 여러 데이터베이스(MySQL·MSSQL)를 한곳에서
왜 필요한가

데이터가 궁금한 사람과 데이터베이스 사이의 다리

지금까지 불편한 점

· 현업은 데이터베이스 질의문(SQL)을 몰라 매번 담당자에게 부탁합니다.
· 담당자는 단순 조회 요청을 처리하느라 시간을 뺏깁니다.
· 그렇다고 직접 접속 권한을 주면 — 실수로 데이터를 바꾸거나 지우는 사고 위험이 있습니다.

DQA 가 중간에서

· 말로 한 질문을 데이터베이스가 알아듣는 문장으로 자동 번역합니다.
· 세 단계 안전장치로 ‘조회만’ 가능하게 막습니다.
· 역할별로 할 수 있는 일을 나누고, 모든 행동을 기록합니다.

현업: 질문만 하면 끝 담당자: 반복 요청에서 해방 보안: 수정 불가 + 전부 기록

안전장치 1/2 — 적용된 방어

‘조회만’ 가능하게 막는 세 단계 안전장치

✅ ‘조회만’ 3단계로 강제

①문장 검사 — AI 가 만든 문장을 실행 전에 살펴, 수정·삭제·구조변경 명령이면 자동으로 거부합니다.
②읽기 전용 접속 계정 — 데이터베이스 접속 계정 자체가 ‘읽기 전용’ 이라, 설령 수정 명령이 통과해도 데이터베이스가 거부합니다.
③볼 수 있는 범위 제한 — 제품마다 접근 가능한 데이터 범위를 미리 정해, 그 밖은 차단합니다.

✅ 그 밖의 안전장치

✓권한을 잘게 나눔 — 할 수 있는 일을 43가지로 분리 + 최상위 잠금 + 사람별 예외.
✓접속 비밀번호 이중 잠금 암호화 — 원문은 어디에도 남기지 않습니다.
✓모든 행동 기록 — 관리 변경은 ‘변경 = 기록’ 한 묶음, 민감 정보는 가림.
✓암호화 통신(HTTPS) + 위험한 내부 주소 차단 + 느린 연결 자동 격리.

AI 가 어떤 문장을 만들든 — 문장 검사·접근 범위·읽기 전용 계정 세 단계를 모두 통과해야 하고, 그래도 접속 계정 자체가 읽기 전용이라 데이터 수정은 아예 불가능합니다.

안전장치 2/2 — 부족한 점과 보완안 (정직하게)

완벽한 시스템은 없다 — 부족한 점과 보완안을 함께

로그인 시도 제한 없음
지금 · 비밀번호를 무한정 시도할 수 있음
시도 횟수 제한 + 여러 번 실패 시 잠금·확인절차
2단계 인증 없음

입력·결과 정제 + 분량 제한 (수정은 읽기전용 계정이 이미 차단)
공유 링크 만료 없음
지금 · 공유 주소가 무기한 유효
기본 만료(예: 7일) + 비밀번호·접속IP 제한 선택

지금 · 1인당 AI 사용량 제한 없음
하루 사용량 한도 + 비용 초과 시 알림
기록 변조 방지 강화
지금 · 기록이 운영 DB 안에만 저장
외부의 ‘고칠 수 없는’ 저장소에 이중 보관

아직 없는 기능은 ‘다음 단계’로 정직하게 말씀드립니다. ‘처음부터 안전하게’ 가 기본 원칙이고, 외부 공개처럼 환경이 바뀌면 더 엄격한 설정으로 강화합니다.
