# Decisions (feature-local ADR)

## ADR-0037-01 — 요청과 생성을 분리한다
- **결정:** grounding 은 요청만 기록하고, 합성은 insight tick 이 한다.
- **근거:** "사전 전량 생성 금지"(LazyGraphRAG)와 "답변 경로 런타임 합성 금지"(ADR-0034-07)는
  얼핏 모순인데, 요청과 생성을 분리하면 둘 다 지켜진다. 첫 질문은 요약 없이 답하지만 120번의
  헛된 합성을 치르지 않는다.
- **부수 효과:** 사용이 곧 우선순위가 된다 — 자주 찾히는 도메인이 먼저 채워진다.

## ADR-0037-02 — 해시에 커버리지 카운트를 넣는다
- **결정:** `cluster_set_hash` 가 라벨·요약뿐 아니라 멤버 수·근거 수도 포함한다.
- **근거:** 커버리지가 늘어 근거가 두터워지면 같은 문장이어도 도메인 그림의 신뢰도가 달라진다.
  그것을 반영하지 않으면 요약이 영원히 옛 커버리지 기준으로 남는다(codex).

## ADR-0037-03 — 해시는 cap 전 전체 집합으로 계산한다
- **결정:** payload 는 25개로 자르되 해시는 최대 300개로 계산한다.
- **근거:** cap 으로 자른 뒤 해시하면 **26번째 이후 클러스터의 변화를 영영 놓친다**. 그 스키마의
  대부분이 바뀌어도 재생성되지 않는 상태가 된다.

## ADR-0037-04 — advisory lock 을 얻은 tick 에서만 합성한다
- **결정:** `if lock_acquired:` 게이트.
- **근거:** 이 pass 에는 행 단위 claim 이 없다(노드 분석과 다르다). lock 없이 돌면 여러 워커가
  같은 스키마를 동시에 합성해 LLM 호출이 중복된다.
- **대안 기각:** 행 단위 claim 은 상태 전이(요청→합성중→완료)를 추가해야 하는데, pass 상한이
  3이라 lock 게이트만으로 충분하다.

## ADR-0037-05 — 대기 조회를 두 쿼리로 나눈다
- **결정:** 미생성분을 partial index 로 먼저, 남는 여유만큼 기존 생성분 재검사.
- **근거:** 한 쿼리로 합치면 인덱스 조건과 어긋나 생성된 행이 쌓일수록 전체 스캔에 가까워진다.

## ADR-0037-06 — 요청 기록은 별도 RW 연결로
- **결정:** grounding 의 조회 커넥션(RO)이 아니라 별도 RW 연결에서 UPSERT.
- **근거:** `agent_kb_ro` 는 SELECT 만 GRANT 돼 있어 거기서 INSERT 하면 **항상 실패**한다.
  요약이 있으면 이 경로에 오지 않으므로 정상 운영에서는 쓰기가 발생하지 않는다.

## ADR-0037-07 — 나열이 아니라 추상화를 요구한다
- **결정:** 프롬프트가 "그룹을 전부 나열하지 말고 2~3개 축으로 묶으라"고 명시한다.
- **근거:** 나열은 L2 의 반복이지 새 층이 아니다. 이 층의 값어치는 **접는 것**에 있다.
