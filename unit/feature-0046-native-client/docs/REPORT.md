# Report

## 1. 현재 상태

**2026-09-04 (19:30) — 「닫기 = 트레이로 · 종료 = 아이콘 우클릭 [종료]」가 세 껍데기 공통
계약으로 성립한다.** 창 [X] 는 알림 영역으로 숨고 프로세스·연결은 유지되며, 진짜 종료는 아이콘
우클릭 [종료] 하나다. 첫 닫기에 **어디로 갔는지 + 어떻게 끝내는지**를 1회 안내한다.

핵심은 **판정을 닫는 순간에 묻는다**는 것이다. 종전 배선은 기동 시점의 bool
(`allow_hide = tray is not None` · `resident = tray is not None`)이라, 아이콘이 뒤에 죽으면
(탐색기 재시작 후 재등록 실패) 계속 숨겨 **창도 알림 영역 아이콘도 없는 프로세스**가 남았다 —
이 기능이 막으려던 상태가 시점만 뒤로 밀려 재현되는 형태다. 판정을 `gui._tray_alive` 한 곳으로
모으고, `Bridge.resident` 는 **읽기 전용 property**로 만들어 대입 자리 자체를 없앴다(§16.7 G10).

실 Windows 실측: `verify_embedded_close.py` **hide 3연속 PASS · quit PASS**, tkinter 폴백
`verify_gui.py` 6단계 PASS. 단위 399건 · 뮤테이션 **16/16 KILL**.

이전(2026-09-04 오후): 앱 창을 WebView2 로 내장(PR #1576) · 인자 없는 실행 · 트레이 상주 ·

## 2. 남은 리스크

- **패널의 상주 문구는 아직 1회 스냅샷이다.** 브리지(`_do_status`)는 이제 매번 새로 판정하지만
  `client-bridge.js` 가 패널 초기화에서 `resident` 를 **한 번만** 묻는다. 아이콘이 창을 연 뒤
  죽으면 화면 문장은 「닫아도 유지됩니다」로 남는다 — 결정 순간에 화면이 거짓을 말하는 §P0-R
  잔여다(닫기 **동작** 자체는 이미 옳게 갈린다). 고치는 자리는 이미 도는 20초 ping 틱이고
  변경은 1~2줄. **이번 cycle 제외 사유**: `static/**` 변경은 check #13 시각검증 hard gate 를
  켜는데, 그 패널을 실제로 띄우면 `discover` 가 자동으로 돌아 **사용자의 AI 사용량을 쓴다**
  (`initClientPanel` → `refresh()` → `verify_answers`). PB-0008 을 치를 수 있는 cycle 에 묶는다.
- **설치본이 아직 구버전이다.** 사용자 머신의 `DQAConnect.exe` 는 2026-09-04 17:38 빌드로,
  PR #1576(내장 창)과 이번 변경 **둘 다 들어 있지 않다**. 재빌드·재설치 전에는 화면에서 이
  동작을 볼 수 없다.
- **브라우저 껍데기에는 첫-닫기 안내가 없다(의도).** 그 창은 브라우저의 것이라 닫힘 이벤트가
  오지 않고, 무신호를 「닫혔다」로 추정하면 **창이 열려 있는데** 안내가 뜬다(codex 2라운드
  적발 — 패널 ping 은 연결 모달을 열어야 시작한다). 그 껍데기 사용자는 패널 문구로 닫기 전에
  안내를 받는데, 그 문구가 **종료 경로를 말하지 않는다** — 한 줄 카피 수정이나 `static/**`
  이라 위 항목과 같은 cycle 로 묶는다.
- **풍선이 실제로 그려졌는지는 미측정.** 잰 것은 콜백 발화와 `Shell_NotifyIconW` 무예외까지다.

  **폴백**이 됐다. 즉 주 경로 사용자는 트레이를 만나지 못한다. **깜빡임 수정은 두 경로 모두에
  적용된다**(전부 `core` 를 지난다) — 두 요청의 도달 범위가 다르다.
  확장하려면 「창 닫힘 = 연결 종료」 계약과 **그것을 말하는 웹 페이지 문구**를 함께 바꿔야 하고,
  그 경로는 유효 토큰 + 실 서버 + 브라우저가 있어야 실측된다.
  **사용자 결정 2026-09-04: 별도 cycle 로 진행.**
