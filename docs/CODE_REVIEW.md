# Code Review 기준 (repo 정본)

이 문서는 **이 저장소의 리뷰 판정 기준 정본**이다. `AGENTS.md` §18.8.1 이 참조하며,
외부 리뷰 도구(`codex review`, IDE 통합 리뷰, 서드파티 리뷰 봇)가 이 저장소를 리뷰할 때
따르는 기준이기도 하다.

**왜 파일로 두는가.** §18.8 의 subagent panel 은 bundle-only(repo 접근 없음)라 리뷰 기준을
프롬프트에 실어 보낼 수 있지만, §18.8.1 의 **대체 경로**(codex-review 등)는 도구의 **기본
판정**으로 돌아간다 — 저장소 고유의 위험 축·금지 패턴을 모른 채 일반적 지적을 낸다.
기준을 repo 파일로 두고 `AGENTS.md` 에서 참조하면 그 판정 기준이 리뷰 채널과 무관하게
동일해지고, 소비자 fan-out 시 **기준이 코드와 함께 전파**된다.

---

## 1. 심각도 등급

| 등급 | 의미 | 처리 |
|---|---|---|
| **P1 (GATE)** | 머지하면 안 되는 결함 — 데이터 손상·보안 노출·조용한 오답·되돌리기 어려운 상태 변경 | **차단**. 수정 후 재리뷰 |
| **P2** | 실사용에서 드러날 결함 — 경계 조건 미처리, 실패 모드 미관측, 성능 회귀 | 같은 cycle 에서 수정하거나 근거와 함께 defer |
| **P3** | 개선 제안 — 가독성, 중복, 명명 | 선택 |

**P1 판정에서 흔한 오류**: "동작은 한다" 를 근거로 P2 로 낮추는 것. **조용히 틀린 결과를
내는 코드는 크래시보다 위험**하다 — 크래시는 관측되고 오답은 관측되지 않는다.

## 2. 이 저장소의 우선 확인 축

리뷰어는 아래 축을 **먼저** 본다. 일반적 코드 품질 지적보다 우선한다.

### 2.1 조용한 실패 (silent failure) — 최우선

- **무음 절단**: 데이터 취득·투영 경로의 `cap`/`limit`/`top-N`/샘플링 상한이 절단 사실을
  산출물·로그에 남기지 않는가. (AGENTS.md §16.7 **G9-b**)
- **fail-open 게이트**: 권한·검증 게이트의 `default`/`else` 가 조용히 통과시키거나
  빈 결과로 떨어지는가. `switch`/`dict` 의 무음 fall-through 는 그 자체로 P1 후보다.
  (§16.7 **G6**)
- **삼켜진 예외**: `except: pass`, 빈 `catch`, 에러를 빈 문자열/기본값으로 흘리는 경로.
  특히 **stdout 빈 문자열을 정상으로 오인**하는 shell 파이프라인.
- **항상 통과하는 검사**: 검사 대상이 비어 있을 때 PASS 를 반환하는 게이트. 검사가
  실제로 무언가를 봤는지 구분되는가.

### 2.2 차단 로직의 정상 경로

새로 추가·강화된 차단·거부·검증 로직은 **발동 정확성만 검증됐는지** 확인한다.
정상 워크로드가 통과하는 근거가 있는가. 차단됐을 때 남는 탈출구가 "안전장치 해제"
뿐이면 설계 미완이다. (§16.7 **G9-c**)

### 2.3 멱등성과 재실행

- 마이그레이션(`bin/migrations/*.sh`)·설치 스크립트·hook 배선은 **2회 이상 연속 실행**해도
  같은 상태인가. 삽입형 패치는 **삽입 문자열과 idempotency 가드 문자열이 정확히 같은가**
  (다르면 가드가 영원히 거짓이 되어 중복 누적된다 — 실측 사례 있음).
- 앵커 기반 삽입은 **구조 앵커**(heading, `## §N.`)를 쓰는가. 본문 문장·인라인 문구 같은
  fragile 앵커는 소비자 customization 으로 사라져 전체 fan-out 을 차단한다.

### 2.4 결정의 적용면

정책성 결정(금지·배제·기본값 변경)을 코드에 반영하는 변경은 **모든 호출 경로**에
적용됐는가. 별칭·프리셋 경로에만 적용하고 메타데이터·배치·관리자 경로를 빠뜨리지
않았는가. 코드 상수를 덮어쓸 수 있는 **런타임 데이터**(DB row·운영자 설정)가 있으면
그것도 적용면이다. (§16.7 **G8**)

### 2.5 사실 주장의 근거

주석·커밋 메시지·문서가 단정하는 사실(성능 수치, 외부 의존, 근본 원인)이
**실측 근거를 갖는가**. 단일 표본에서 얻은 수치를 일반 성질로 진술하지 않았는가.
(§16.7 **G7**)

### 2.6 격리 경계

- `repo/` 직접 mutation (§13.2.7 F0), worktree binding (§13.2 F1) 위반.
- 병렬 subagent 가 공유 checkout 을 건드리는 경로 — `git -C`/`--git-dir`/`GIT_DIR`/
  `GIT_WORK_TREE` 사용은 격리 우회 신호다 (§22.5).
- 검증 브라우저·외부 도구가 **자기 세션이 만들지 않은 표면**을 조작하는가 (§16.6).

### 2.7 비밀·경로 노출

로그·에러 메시지·hook 반환 사유에 secret·절대 경로·토큰이 그대로 실리는가.
**hook 출력에는 모델의 자기검열이 적용되지 않는다** — redact 는 작성자 책임이다 (§12).

## 3. 리뷰 산출물 형식

리뷰 결과는 다음을 포함한다.

- **등급별 목록** (P1 / P2 / P3), 각 항목에 `파일:라인` 앵커
- 각 P1·P2 는 **실패 시나리오**를 구체적으로 — "어떤 입력·상태에서 무엇이 잘못되는가".
  재현 경로 없는 지적은 P3 로 내린다.
- **확신도**: 코드를 읽고 확인한 것과 추정한 것을 구분해 표기한다 (§16.7 G7).

---

## 4. 지적하지 않을 것

아래는 이 저장소에서 **의도된 선택**이므로 리뷰 지적 대상이 아니다.

- 한국어 주석·문서·커밋 메시지 (프로젝트 언어 정책)
- 정책 문서의 긴 산문 — `AGENTS.md`/`docs/*.md` 는 판단 기준이라 근거를 길게 쓴다.
  단, **사용자 대면 UI 텍스트**는 반대로 §16.8 예산 규칙의 적용 대상이다.
- `bin/migrations/*.sh` 의 반복되는 boilerplate — hop 은 독립 실행 계약이라
  공통화보다 자기완결성을 우선한다.
- `_template_maintainer/` 하위 파일 — 소비자에 배포되지 않는 maintainer 전용 영역.
