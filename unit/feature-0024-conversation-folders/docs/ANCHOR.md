# ANCHOR: feature-0024 conversation-folders

## §1. 외부 관점 요약
대화 목록이 길어지면 날짜 그룹만으로는 관련 대화를 묶기 어렵다. "폴더(프로젝트)"는
관련 대화·파일·지침을 한곳에 모으는 사용자 조직 오버레이다. 왜 폴더가 계정별인가?
한 대화가 그룹으로 여러 멤버에게 보이는데, 각자 자기 방식대로 정리하고 싶기 때문이다
(소유자 폴더가 멤버에게 강요되지 않는다). 왜 폴더 지침·파일을 요청자 기준으로
주입하나? 폴더가 계정별이므로 "이 대화의 폴더 컨텍스트"는 지금 질문하는 사람의 폴더다.

## §2. 대안 분기
- **Alt-A: 대화당 단일 folder_id 컬럼(owner-global).** 페르소나: 단순·개인 위주 팀. 안 고른 이유: 그룹 대화에서 소유자 폴더가 멤버에게 강요돼 "각자 정리" 요구를 못 담는다(사용자 D2 결정이 계정별 배정).
- **Alt-B: flat 프로젝트(중첩 없음, ChatGPT/Claude 식).** 페르소나: 관행 우선·복잡도 최소 팀. 안 고른 이유: 사용자가 다중 깊이를 명시 요청. 대신 재귀를 지원하되 깊이 상한을 런타임 설정으로 둬 안티패턴을 완화(D1).
- **Alt-C: 폴더 파일 = 대화 생성 시 copy-on-create seed.** 페르소나: 정적 프로젝트 파일 팀. 안 고른 이유: 계정별·이동-후 재배치가 동적이라 생성시점 복사가 안 맞는다. ask-time 요청자 폴더 resolve 가 정합.

## §3. 가정된 사용 시나리오
데이터 분석팀 A 는 "KR_LIVE 매출" 폴더를 만들고 기본 데이터소스=KR_LIVE·지침="저장
datetime 은 UTC, 서버 TZ(Asia/Tokyo)와 별개; ENUM 코드는 사전 매핑만 사용"을 핀한다.
팀원이 이 폴더 안에서 새 대화를 열면 매번 DB·타임존·ENUM 규약을 재설명하지 않아도
assistant 가 그 컨텍스트로 답한다. 6개월 후 신규 팀원이 인수받아도 폴더를 열면 그
팀의 축적된 규약과 검증 맥락이 그대로 이어진다.
