### 3. Challenge to current spec

패널이 재논쟁하지 않도록, 깨끗하게 확인된 것부터: 러너 두 사본은 **byte-identity 가 강제된다**(`unit/feature-0043-external-llm-bridge/tests/test_bridge_agent_sync.py:21-25`, `read_bytes()` 위 SHA-256, skip 가드 없음); AC2 는 성립한다 — `_classify` 는 `listening`/`features`/`agent_version` 만 읽고(`routers/_console_llm.py:210-226`) `_runner_job_grants` 는 per-token features 를 읽으므로 콘솔 위임은 caps 게이트로 회귀할 수 없다; `runner_update.current` 는 어디서나 advisory 다 — 유일 소비처가 러너의 세션당 1회 로그(`bridge_agent.py:2274-2280`)이고 어떤 서버 경로도 `stale_build` 로 dispatch 를 게이팅하지 않는다; lazy import 도 저렴하고 비순환이다(`shared/bridge_tasks.py` 는 stdlib 만 import, 반복 호출은 `sys.modules` hit).

스펙 자체에 대한 도전 셋:

- **AC3 의 비대칭이 미명세다.** 「미신고 지문 = stale, unknown 배포본 지문 = 판정 없음」은 세 상태 중 둘만 이름한다. 신고 쪽에도 자기 「unknown」이 있다(B2). 스펙은 *네* 조합 중 어느 것이 판정하는지 말해야 하고, 술어는 `""` 를 과적재하는 대신 그것을 표현할 수 있는 타입을 받아야 한다.
- **lazy import 의 사유가 실제 의존 그래프가 아니다.** `_caps_trusted` docstring 은 지연이 「이 모듈이 저장 계층이라 `shared` 에 모듈 로드 의존을 만들지 않기 위해서」라고 하지만 `app.py:51,68,77` 이 이미 모듈 스코프에서 `shared` 를 import 하므로 웹 프로세스는 그것에 하드·비지연 의존을 갖는다. 여기서 지연은 아무것도 사지 못하고 B3 의 미테스트 `except` 분기를 지불한다. 모듈 레벨 import 로 만들어 패키징 파손이 관측 가능한 startup 에서 크게 실패하게 하거나, 사유를 정직하게 다시 쓰라.
- **게이트는 검증 없는 자기선언이고, 그 유일한 강제는 주석이다.** `test_builtin_model_table_never_reaches_the_report` 는 좋은 음성 테스트지만 `detect_runtimes(cached={})` 를 부른다 — `cached` 경로를 전혀 실행하지 않으며, 그 경로에서 `caps = probed.get(name) or cached.get(name)`(`bridge_agent.py:1585`)이 사용자가 쓸 수 있는 `config.json` 항목을 `source` 마커 재확인 없이 신고한다. 오늘 라이브가 아님은 확인했으나(캐시와 「폴백은 캐시하지 않는다」 가드가 같은 커밋 `9a1ecee9`, 2026-08-28 에 착륙해 필드 캐시에 builtin 항목이 있을 수 없다), 신고 경로에 provenance 검사가 없으므로 미래의 캐시 포맷 변경이 다시 연다. 한 줄 필터(`if (cached_entry.get("source") or "") == "builtin": skip`)로 선언이 커밋 고고학이 아니라 코드로 강제되게 할 가치가 있다.
