## 1. Findings (발견)

### F-0 (지시사항 전제 반증) 구분선 소실은 **발생하지 않는다** — 항목 1 의 전제가 사실과 다름
리뷰 지시 1번은 "제거된 label 의 `border-bottom` 이 헤더/목록 사이 구분선을 겸했으므로 제거 후 헤더 아래 경계가 사라진다"고 전제했으나, 코드 확인 결과 **거짓**이다.

- `styles.css:2976-2983` `.attach-side-panel-header` 는 **자체적으로** `border-bottom: 1px solid var(--border-subtle);` (2981행) 을 이미 보유한다.
- 제거된 `.attach-scope-all` 은 헤더 **아래**(index.html DOM 순서상 header → label → list) 에 위치하며 자기 자신의 `border-bottom` 을 가졌다. 즉 변경 전에는 `--border-subtle` 규칙이 **2줄 연속으로 쌓여** 있었다(헤더 하단선 + scopeAll 하단선).
- 변경 후 `.attach-side-panel-header`(2981) → `.attach-side-panel-list`(3005) 로 인접하며, 구분선은 **정확히 1줄** 남는다. 시각적으로 붙어 보이는 회귀는 없다.

추가로, 제거된 마크업은 `class="attach-scope-all hidden"` 로 **기본 hidden** 이었고 `styles.css:111` `.hidden { display: none !important; }` 이다. 따라서 첨부 0건 상태와 목록 fetch 해소 이전에는 **이미** 그 행이 `display:none` 이라 "헤더 하단선 1줄" 레이아웃이 기존에도 지배적 상태였다. 이번 제거는 그 상태를 **항상성으로 승격**시킨 것이다.

### F-0b (부수 개선) 로드 후 콘텐츠 점프(CLS) 제거
구 `app.js:9910` 은 fetch 성공 후 `scopeAllRow.classList.remove("hidden")` 로 행을 **뒤늦게 노출**시켰다. 즉 패널을 열면 `불러오는 중...` → (응답 도착) → scopeAll 행이 삽입되며 목록 전체가 약 40px 아래로 밀리는 레이아웃 점프가 있었다. 제거로 이 점프가 사라진다. 시각 회귀가 아니라 **회귀 해소**다.

### F-1 (핵심 결함, design 도메인) 스코프가 넓어졌는데 그 사실을 알리는 UI 가 **0** 이 되었고, 남은 어포던스가 거짓말을 한다
이번 변경은 서버가 대화 첨부 **전량**을 참조 스코프로 해소하도록 바꾼다 (`_conv_store.py` 신설 `_resolve_conversation_attachment_scope`, docstring 이 "D16 minimum exposure supersede" 를 명시). 그런데 사이드 패널에 남은 어포던스들은 여전히 **선택이 노출을 좁힌다**는 옛 계약을 말하고 있다.

- **`×` 제거 버튼이 무의미해졌다.** `app.js:9468-9476` 이 pill 마다 `.pill-remove`("첨부 제거") 를 붙이고, 핸들러 `_removeAttachmentPill`(`app.js:9499-9507`) 은 `bucket.items.splice(idx, 1)` 로 **로컬 bucket 에서만** 제거한다(백엔드 호출 없음).
  - 변경 **전**: 제거 → `_composerAttachmentSnapshot` 의 `attachment_ids` 에서 빠짐 → D16 minimum exposure 로 **실제로** assistant 노출에서 제외됐다.
  - 변경 **후**: 서버가 대화 첨부를 독립적으로 재해소하므로 제거해도 assistant 는 그대로 본다. "목록에서 지우면 AI 가 안 본다" 는 사용자 멘탈모델이 **이번 diff 로 인해** 깨진다. 이는 기존 결함이 아니라 **본 변경이 새로 만든** 오도(misleading) 어포던스다.
- **섹션 라벨이 무의미한 구분을 유지한다.** `app.js:9485` `"이번 요청에 첨부"` / `app.js:9493` `"세션 파일 (이전 첨부 — LLM 컨텍스트 유지)"`. 이제 두 그룹은 참조 스코프상 **완전히 동등**하다. 후자만 "LLM 컨텍스트 유지" 라 표기해 전자는 그렇지 않은 듯한 위계를 암시하는데, 사실과 반대 방향의 오해를 만든다.
- **유일한 스코프 고지가 삭제됐다.** 삭제된 핸들러가 띄우던 토스트 `"이 대화의 모든 ingested 첨부를 사용합니다. 별도 audit 이 기록됩니다."` 가 전체 스코프를 사용자에게 알리는 **유일한** 문구였다. 동작은 "항상 전체"로 넓어졌는데 고지는 0 이 되었다 — 방향이 반대다.

### F-2 (잔여 스타일) 클래스 잔재 없음 — PASS
`grep -n "attach-scope-all" styles.css index.html app.js` 결과 **셀렉터/마크업 잔재 0건**. 남은 것은 주석 3곳(`styles.css:2781`, `app.js:9342/9897/10787` 서술 주석)뿐으로 렌더 트리 영향 없음. 리포지토리 전역으로도 `#attachScopeAllRow`/`#composerAttachmentsScopeAll` 참조는 코드에 남아있지 않다(문서만 — F-4 참조).

### F-3 (주석 대체 적절성) HTML 은 적절, CSS 주석은 **위치가 잘못됐다**
- `index.html:363-364` 주석은 제거된 지점 그대로에 있고 사유("항상 자율 참조하므로 선택 구분이 무의미")를 담아 의도 전달이 충분하다. 적절.
- `styles.css:2781-2782` 주석은 **엉뚱한 블록에 고아로 남았다.** 바로 위는 `.profile-motion-select`/`.profile-notify-perm`(2778-2779), 바로 아래는 `.profile-audit-list`(2785) — 즉 **프로필 섹션 한복판**이다. 정작 attach 사이드 패널 규칙은 `styles.css:2927` 이후에 모여 있다. attach 패널을 수정하러 2927행으로 간 다음 사람은 이 묘비 주석을 절대 보지 못한다. 의도 전달 실패.

### F-4 (일관성 — 설계 문서 drift) 설계 정본이 삭제된 컨트롤을 계속 기술한다
- `docs/DESIGN-entry-points.md:59-62` **§4.3 scopeAll 체크박스** 가 통째로 남아 있다("위치: `#attachSidePanel` 헤더, 첨부 목록 위", "형태: 체크박스 + 라벨 …", "상태: 첨부 0개면 비활성/숨김. 대화 전환 시 `bucket.scopeAll` 반영"). 이 파일은 **staged 아님**(`git diff --cached --name-only` 미포함). 이 UI 의 디자인 정본이 존재하지 않는 컨트롤을 규정하는 상태다.
- `docs/FUNCTION.md:888` AC-0244 가 상태 스키마를 `{ items: [...], scopeAll: bool }` 로 명시 — 코드는 `{ items: [] }`(app.js:9331) 로 바뀌었다.
- `docs/FUNCTION.md:891` AC-0247 "scopeAll 토글 별도", `docs/FUNCTION.md:971` AC-0310 이 체크박스를 현존 진입점으로 기술. 신설 AC(`FUNCTION.md:2169`)가 제거를 선언하지만 구 AC 들에 supersede 표기가 없어 상충한다.
- `docs/TEST.md:798` 이 "Tier1 scopeAll — `#composerAttachmentsScopeAll` DOM 존재 eval=True (마크업 배포 확인)" 를 PB-0008 증적으로 기록 — 재현 불가능한 증적이 됐다.

### F-5 (시각 상태별 추론) 3 상태 모두 안전
- **로딩 중**: `app.js:9899` → `.attach-list-empty`(`styles.css:3249-3254`: `text-align:center; padding:32px 16px; color:var(--text-muted); font-size:13px`). 헤더 하단선 아래 중앙 정렬 안내. 정상.
- **0건**: `app.js:9904` 동일 클래스. 변경 전에도 scopeAll 행은 hidden 이었으므로 **픽셀 차이 0**.
- **다수**: `.attach-side-panel-list`(3005-3012) 가 `flex:1; overflow-y:auto; padding:10px 12px; gap:6px`, 헤더는 `flex-shrink:0`(2982). 헤더 고정 + 목록만 스크롤. 간격 리듬(헤더 `14px 16px 10px` → 목록 `10px 12px`)은 유지되며 제거된 행(`10px 14px`)이 끼어 있던 때보다 오히려 균질하다.
- **에러**: `app.js:9971` 동일 empty 클래스. 정상.

## 2. Risks (위험)

1. **[High] 신뢰 위험 — 삭제되지 않는 삭제 버튼.** 사용자가 민감 파일을 `×` 로 지우고 "이제 AI 가 안 본다"고 믿은 채 대화를 이어가면, 실제로는 계속 참조된다. 데이터 노출에 대한 **잘못된 안심**을 UI 가 적극적으로 조장한다. F-1 의 어포던스 문제 중 가장 위험한 축.
2. **[Med] 두 렌더러가 같은 컨테이너를 다툰다.** `_loadConversationAttachmentList`(9894, `.attach-list-entry` 다운로드 전용 뷰)와 `_renderComposerAttachments`(~9400, `.composer-attachment-pill` + 섹션 라벨 + `×`)가 **동일한 `#attachSidePanelList`** 에 `innerHTML=""` 후 각각 그린다. 나중에 실행된 쪽이 이긴다. 기존 조건이나, 사용자가 보는 패널이 두 가지 다른 시각 언어(항목 행 vs pill)로 갈리므로 F-1 고지 문구를 어디에 넣을지 결정할 때 **두 경로 모두**에 넣어야 한다는 제약이 된다.
3. **[Med] 설계 문서 신뢰도.** DESIGN-entry-points.md §4.3 이 남아 있는 한, 다음 진입점 감사(TASK-0158 계열 3축 감사)가 "문서엔 있는데 UI 에 없다" 를 **미구현 진입점으로 오판**해 삭제된 토글을 재구현할 실질 위험이 있다. TASK-0158 자체가 정확히 그 패턴("마크업만 부재")으로 이 토글을 만들었던 전례가 있다.
4. **[Low] 묘비 주석 위치.** F-3 의 CSS 주석은 프로필 섹션에 있어, 향후 프로필 스타일 정리 시 무관해 보여 삭제되거나 반대로 attach 패널 작업자에게 안 보인다.

## 3. Recommendations (권고)

- **R1 (F-1, 필수급)** `×` 버튼의 의미를 실동작에 맞춘다. 택일:
  - (a) pill 의 `×` 를 **실제 첨부 해제 API 호출**(대화에서 detach/supersede)로 승격 — 라벨 그대로 유지 가능. 가장 정직하나 백엔드 작업 필요.
  - (b) `×` 를 **이번 턴 목록에서만 제거**임이 드러나게 축소 — 세션(이전 턴) pill 에서는 `×` 를 아예 렌더하지 않고(`_buildPill(it, true)` 분기), 신규 pill 의 `title` 을 "이번 요청 목록에서 빼기(대화의 첨부는 유지)" 로 변경. 프론트만으로 가능, 최소 변경.
  - 최소한 (b) 는 이번 cycle 에 포함할 것을 권고.
- **R2 (F-1)** 삭제된 토스트를 대체할 **정적 고지 1줄**을 패널에 둔다. 제거된 label 이 있던 그 자리(`index.html:363` 주석 위치)에 비대화형 `.attach-scope-note` 를 두고 "이 대화에 올린 첨부는 모두 AI 가 참조합니다." (`font-size:11px; color:var(--text-muted); padding:8px 14px;`, **border-bottom 없음** — 헤더가 이미 구분선 보유, F-0 참조). 삭제한 컨트롤의 **정보 기능만** 되살리는 형태라 토글 부활이 아니다.
- **R3 (F-1)** 섹션 라벨 `"세션 파일 (이전 첨부 — LLM 컨텍스트 유지)"`(app.js:9493) 에서 이제 무의미한 한정어를 정리 — 예: `"이전 첨부"`. 두 섹션이 동등 스코프임이 R2 고지로 이미 전달되므로 라벨은 시간순 그룹핑 역할만 하면 된다.
- **R4 (F-3)** `styles.css:2781` 묘비 주석을 삭제하거나, 유지한다면 `.attach-side-panel` 블록 머리(2926행 근처)로 이동.
- **R5 (F-4)** `docs/DESIGN-entry-points.md` §4.3 을 제거 사유와 함께 취소선/superseded 표기로 갱신하고 **이번 커밋에 staged 포함**. `FUNCTION.md` AC-0244/0247/0310 에 `[SUPERSEDED by AC-20260729T140200-attach-full-scope-5]` 표기, `TEST.md:798` 증적에 무효화 각주.

## 4. Verdict rationale (판정 근거)

**CONCERN.** BLOCK 이 아닌 이유: 이 리뷰의 핵심 우려로 지목됐던 레이아웃 회귀(항목 1)는 코드 확인 결과 **성립하지 않는다** — `.attach-side-panel-header` 가 자체 `border-bottom`(styles.css:2981) 을 보유하므로 구분선은 그대로 1줄 남으며, 제거된 행은 애초에 기본 `hidden` 이라 0건·로딩 상태의 픽셀은 변하지 않는다(F-0). 오히려 fetch 후 행이 삽입되며 발생하던 콘텐츠 점프가 사라져 순개선이다(F-0b). 잔여 스타일도 0건(F-2), 3개 시각 상태 모두 안전(F-5)이므로 순수 시각 회귀 관점에서는 PASS 다.

PASS 가 아닌 이유: 이번 변경은 참조 스코프를 "프론트 선택분"에서 "대화 전량"으로 **넓히면서**, 그 사실을 알리던 유일한 UI(토글 + 토스트)를 **동시에 제거**했다. 그 결과 (i) 스코프 고지가 0 이 되고, (ii) 남은 `×` 버튼이 더 이상 노출을 줄이지 못하는데도 줄이는 것처럼 보이는 **오도 어포던스로 전락**했다(F-1). 이 어포던스 의미 변화는 기존 결함이 아니라 본 diff 가 새로 만든 것이며, 사용자가 민감 파일을 지웠다고 오인할 수 있는 신뢰 위험을 동반한다. 여기에 디자인 정본 문서(`DESIGN-entry-points.md` §4.3)가 삭제된 컨트롤을 계속 규정한 채 **unstaged** 로 남아, 차기 진입점 감사가 토글을 재구현할 구조적 위험까지 더해진다(F-4, R5).

시각·레이아웃은 통과, **의미·고지 계층이 미완**이라는 판단으로 CONCERN. R1(b)+R2 는 프론트 소규모 수정으로 이번 cycle 내 해소 가능하며, `×` 를 (a)로 승격할지 (b)로 축소할지는 제품 결정이므로 human approval 을 요청한다.
