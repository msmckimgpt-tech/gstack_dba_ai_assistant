### 3. Challenge to current spec

1. 매니페스트 **분리 서명**을 왜 배제했는가 — 서버 침해 시나리오의 잔여 방어가 0 이고, EV 코드
   서명보다 비용이 낮다. 의도된 기각인가 미검토인가?
2. 이미 **관리자 권한으로 설치된** 머신에 per-user 무음 업데이트가 두 번째 사본을 만들지 않는가?
3. `mark_checked()` 를 실패에도 부르는 것이 의도인가 — CA 만료로 조용히 실패하는 머신이 최신인
   머신과 구분되지 않는다.
4. 세 곳의 `SETUP_NAME_RE` 를 `fullmatch` 로 두지 않은 근거는? (`$` 는 말미 개행에도 매치한다)
5. `is_dir()` 기동 판정이 만드는 운영 상태를 어떻게 관측하는가 — override compose·compose 무변경
   배포에서 릴리스 채널이 **영구 404** 이고 신호가 없다.
6. **트레이가 없는 머신의 업데이트 입구는 0개**다 — 그 사실을 잔여로 기록할 것인가?
7. `update_check` 가 `DANGEROUS` 밖이라 확인창이 떠 있는 사이 `pending_update` 가 교체될 수 있다.
