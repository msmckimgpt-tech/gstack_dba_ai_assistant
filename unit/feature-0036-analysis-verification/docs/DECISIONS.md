# Decisions (feature-local ADR)

## ADR-0036-01 — 판정 실패는 "검증됨"이 아니다 (핵심 불변식)
- **결정:** LLM 오류·계약 위반 응답·근거 없는 응답·증거 부재·저장 실패는 **행을 만들지 않는다**.
- **근거:** 확인 도장이 잘못 찍히면 그 도장을 근거로 위층(요약·답변)이 더 확신한다. 검증층이
  틀린 확신을 증폭하면 없느니만 못하다. 이 모듈의 fail-soft 는 "통과"가 아니라 "침묵"이다.
- **강제:** 테스트 파일의 절반이 이 명제를 지킨다.

## ADR-0036-02 — 예산을 못 읽으면 중단한다 (fail-soft 방향 반전)
- **결정:** `llm_budget`·`resource_budget` 을 import 할 수 없으면 pass 를 중단한다.
- **근거:** 다른 fail-soft 와 방향이 반대인 이유는, 계량 장애로 기능이 멈추는 것보다 **상한을
  모른 채 자동 지출을 계속하는 쪽이 위험**해서다. "모르면 하지 않는다"는 원칙은 지출에 특히 강하게
  적용된다.

## ADR-0036-03 — red-team 재사용 금지, pass_no 재사용 금지
- **결정:** 신규 프롬프트 + 신규 테이블.
- **근거:** feature-0021 은 `question + draft + evidence` 답변 전용 구조다. `pass_no` 는
  back-refine 세대라 검증 세대와 직교한다. 억지로 겹치면 한쪽을 고칠 때 다른 쪽이 깨진다.

## ADR-0036-04 — analysis_hash 가 재판정의 축이다
- **결정:** 이전 판정의 해시를 조회해 현재 분석문 해시와 비교한다. 저장 시 같은 노드의 다른 해시
  행을 삭제해 노드당 1행을 유지한다.
- **근거:** "판정 행이 있으면 제외"로 두면 분석이 갱신돼도 옛 판정이 남아 **재판정되지 않는다** —
  문서에 적은 계약과 정반대다(codex P1). 1행 유지는 무한 증식과 LEFT JOIN 행 증가를 함께 막는다.

## ADR-0036-05 — 배치하지 않는다 (1건 1콜)
- **결정:** 판정은 분석문 1건에 LLM 1콜.
- **근거:** 배치하면 한 건의 오판이 같은 응답 안의 다른 건으로 번지고, 응답이 길어져 잘린다.
  L2 요약(feature-0033)이 배치 6인 것과 다른 판단인 이유는 **판정은 서로 독립이어야** 하기 때문이다.

## ADR-0036-06 — 근거 없는 판정은 기록하지 않는다
- **결정:** `reason` 이 비면 판정을 버린다.
- **근거:** 프롬프트는 "판정을 가른 구체적 숫자·필드"를 요구한다. 그것이 없으면 사람이 그 판정을
  재확인할 방법이 없고, 재확인할 수 없는 확인 도장이야말로 이 층의 최악의 실패다.
- **경계:** 길이 하한은 두지 않는다 — 자의적이고, 짧아도 숫자를 지목하면 유효한 근거다.

## ADR-0036-07 — 판정자는 모순 쪽으로 기울되 날조하지 않는다
- **결정:** 프롬프트에 "prefer contradicted over supported when a real conflict exists" 와
  "do not invent conflicts to look thorough" 를 함께 넣는다.
- **근거:** 한쪽만 있으면 rubber-stamp 판정자 또는 트집쟁이 판정자가 된다. 증거가 **표본**임을
  명시해 표본 유일성을 전역 제약으로 오해하지 않게 하는 것도 같은 균형이다.
