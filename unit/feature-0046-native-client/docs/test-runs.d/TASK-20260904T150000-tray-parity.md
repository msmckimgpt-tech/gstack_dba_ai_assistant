# Run — 재구성: 웹 셸 주 경로에도 트레이 상주

## 1. 단위 — 256 passed (+11)

새 단정은 **소스 검사가 아니라 구동**이다. 「상주 중에는 유휴가 종료 사유가 아니다」는
소스로 확인할 수 없어, `_serve_confirms` 를 스레드로 돌려 2초간 살아 있음을 단정한다.

### ⚠ 이 실행이 **하네스 결함 두 건**을 먼저 잡았다 (기록 가치)

1. **테스트가 실패 대신 «행(hang)» 이었다.** M23 을 적용하자 `_serve_confirms` 를 **주
   스레드에서 동기 호출**하던 테스트가 무한루프에 빠져 **뮤테이션 실행 전체가 멎었다**
   (pytest CPU 0%, 무한 대기). 행은 실패보다 나쁘다 — 원인을 아무것도 말해 주지 않고
   자동화를 통째로 막는다. → `_serve_until_done()` 헬퍼로 **끝나야 하는 호출은 전부
   스레드 + join timeout** 으로 바꾸고, 「끝나야 하는 모든 경우가 끝나는지」를 한 자리에서
   단정하는 테스트를 추가했다.
2. **M24 의 첫 판이 «문법 파손» 이었다.** `if` 블록의 본문을 지워 `IndentationError` 를
   만들었고, 그 KILL 은 **행동 결함을 잡은 것이 아니다**(FAILED 0건 + 수집 오류). 조건만
   죽이는 형태(`if False:`)로 바꿔 재실행 → 2 FAILED 로 **행동** KILL 확인.
   ⚠ 뮤테이션 점수는 «몇 개 죽었나» 가 아니라 «무엇으로 죽었나» 로 읽어야 한다.

## 3. 패널 문구 — DOM 렌더 확인 + 대조군

`tests/verify_residency_dom.mjs` (jsdom). 문자열 검사가 아니라 **실제 DOM 에 그려진 결과**:

| 입력 | 렌더 결과 |
|---|---|
| `resident=true` | 「이 창을 닫아도 알림 영역에서 연결이 유지됩니다. 완전히 끝내려면 알림 영역 아이콘에서 [종료] 를 누르세요.」 |
| `resident=false` | 「이 창을 닫으면 연결이 끝납니다.」 |

- 문구가 가리키는 `#clientResidency` 가 **실제 마크업에 존재**함을 함께 확인(P0-R).
- **대조군**: 두 분기를 같은 문구로 바꾸면 exit=1(FAIL) — 검사가 실제로 결함을 잡는다(G11-b).
- ⚠ **대조군이 처음엔 엉뚱한 사유로 실패했다.** 추출 건전성 가드가 문구까지 검사해
  「추출 파손」과 「결함」이 같은 실패로 뭉개졌다. 가드를 **구조 표지만** 보도록 분리하고
  종료코드를 갈랐다(2=추출 파손 / 1=결함).

## 4. 미수행 (과장하지 않는다)

- ⛔ **PB-0008 실 Windows 시각검증 — 미수행.** 이 패널은 `?client_port=&client_nonce=` 가
  붙었을 때만 나타나고, 그 값은 **Windows 에서 도는 브리지**가 만든다. 즉 화면을 띄우려면
  ① 유효 토큰으로 클라이언트를 Windows 에서 기동하고 ② 그 브리지에 붙은 앱 창을 열어야
  한다. 이 세션에는 유효 토큰이 없다.
  또한 변경된 `static/` 을 라이브에 보이려면 **공유 web 컨테이너**를 건드려야 하는데,
  그 트리는 병렬 세션들이 함께 쓰므로 §13.2.9 가 금지한다.
  대신 위 **DOM 렌더 확인 + 대조군**으로 「무엇이 그려지는가」를 실측했다 — 픽셀 배치가
  아니라 **문구 분기**가 이 변경의 위험 축이기 때문이다. 그래도 이것은 PB-0008 을
  **대체하지 않는다**. 라이브 왕복이 가능한 다음 cycle 에서 수행해야 한다.
- ⛔ **웹 셸 종단간(패널 닫고 러너가 계속 답한다) — 미수행.** 같은 이유(유효 토큰·실 서버).
  Win32 층은 tkinter 판과 **같은 `tray.py`** 를 쓰므로 이미 실측됐다.
