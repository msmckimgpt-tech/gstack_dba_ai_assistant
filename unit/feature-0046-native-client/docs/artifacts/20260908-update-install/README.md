# 실제 DQA 업데이트 설치 실측 — 2026-09-08

`measurement-summary.json`이 결과 요약이다. 최초 실패(`failed-1.2.0-*`)와 수정 후 성공(접두사 없는 파일)을 함께 보존한다. 증적 텍스트의 CRLF/BOM만 정규화했으며 실제 설치기·앱 SHA-256은 원본 바이너리로 계산했다.

- 실패: 기존 Windows per-user1.1.2의 실제 트레이 메뉴→확인창→앱 자체 다운로드→설치기. 기존앱exit0 뒤 고아 내장 Python 때문에 종료 요청 실패, suppressed Abort로exit5/롤백. 진단 설치기 직접 실행은 별도 실패 원인 확인이며 메뉴 성공 증거로 계산하지 않았다.
- 성공: 같은 설치본에서 공개된1.2.1을 실제 메뉴로 받았다. 기존 고아PID48536은 수동 제거하지 않았고 설치기가 종료했다. 새DQA PID29004, setup둘exit0, 버전/설치경로/지문/pending/성공로그를 대조하고5초이상 안정 상태를 확인했다.
- `select_update_menu.py`는 실제 Win32 popup 항목 이름과 ID를 읽어 해당 선택 이벤트를 전달했다. `accept_and_observe.py`는 실제 예 버튼을 수락하고 프로세스/대화상자/레지스트리/설치 파일을 관찰했다. updater함수·API·다운로드·installer를 mock하지 않았다. 기록된 PID는 당시 실행의 값이며 스크립트를 그대로 재실행하면 안 된다.
- `installer.log.gz`는 전체 설치 로그(UTF-8 텍스트)를 압축 보존한다. `installer-excerpt.log`는 반복 파일복사 기록을 생략한 발췌본이다.
- `latest-version-confirmation.json`: 재실행된 실제 앱의 업데이트 메뉴가 “이미 최신입니다 (버전1.2.1)”로 응답했다. 확인창을 닫고 사용자 앱은 실행 상태로 남겼다.
- 판정은 실제 네이티브 메뉴·대화상자 및 설치 결과 기반이다. 앱 화면의 픽셀 캡처 검증으로 확대하지 않는다. 약30초의 Windows 종료 대기는 유지됐으므로 속도 단축을 주장하지 않는다.
