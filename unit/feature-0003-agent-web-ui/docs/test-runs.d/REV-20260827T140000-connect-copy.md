# Run — 안내 문구·연결 화면

Environment: **Windows-browser 미수행**

## 왜 미수행인가

`bin/win-browser.py` relay 가 이 환경에서 도달하지 않는다(사유·해소조건은
`REV-20260827T000500-bridge-poll-ui.md` 와 동일, 이번 cycle 이 그 상태를 바꾸지 않았다).

## 이 변경에서 브라우저 검증이 특히 대체 불가인 이유

이 cycle 의 본체는 **사용자 대면 문구**다. 자동 검증이 확인할 수 있는 것은 "그 문자열이 파일에
있는가" 뿐이고, 정작 판정해야 할 것 — **일반 사용자가 이 문구로 연결에 성공하는가** — 은
사람만 답할 수 있다. 직전 cycle 이 정확히 그 지점에서 실패했다: 모든 테스트가 green 인 채로
"외부 AI 연결(/ai/connect)" 이 라이브에 나갔고, 사용자가 "의미 자체를 인지하지 못한다" 고 알려
줬다. **테스트가 통과했다는 사실은 문구가 통했다는 증거가 아니다.**

## 자동으로 잠근 것 (문구 품질이 아니라 회귀 방지)

| 대상 | 검사 |
|---|---|
| 상태별 안내 2종 | 연결 없음/있음 상수 존재 + 연결 없음 첫 줄이 '설정' 을 말하는가 |
| 링크 | `[AI 연결하기](/ai/connect)` — 경로 문자열이 아니라 마크다운 링크 |
| 용어 | 화면 텍스트(주석 제외)에 설명 없는 `MCP` 부재 · '열쇠' 같은 2차 용어 부재 |
| 판정 | 요청당 1회(`_account_has_connected_ai` 호출 1회) · 실패 시 fail-open |
| **DOM 계약** | `ai-connect.js` 가 참조하는 id **13개** 가 HTML 에 전부 존재 |

DOM 계약 테스트가 이 cycle 에서 가장 실질적인 방어다. 문구를 고치다 `id="issueToken"` 하나를
지우면 **발급 버튼이 조용히 죽는다** — 화면은 멀쩡해 보이고 클릭만 무반응이라, 다음 사람이
"연결이 안 된다" 는 제보를 받고서야 안다.

## 해소 조건

win-browser relay 복구 시 또는 사용자 확인으로:

1. 연결 없는 계정으로 질문 전송 → 안내 말풍선이 **설정 안내** 이고 링크가 눌리는가
2. 링크 → `/ai/connect` 도착 → **방법 ①** 을 따라 실제로 연결이 되는가
3. 연결 후 다시 질문 → 안내가 **대기 안내**로 바뀌는가(상태 전환)
