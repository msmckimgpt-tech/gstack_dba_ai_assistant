## 1. Findings (발견)

### D1 (CONCERN) — `.attach-list-item-meta` 의 말줄임 방어가 이제 **상호작용 컨트롤을 삼킨다**, 그리고 그 근거 주석은 이 diff 로 사실이 아니게 됐다

지시 3번(직전 cycle 의 레이아웃 방어를 유지한 판단이 옳은가)에 대한 답이다. **이름줄 분리는
유지가 옳고, 메타줄 nowrap 은 유지가 옳지 않다** — 둘을 갈라야 한다.

`styles.css:3280-3290` 은 그대로 남았다:

```css
.attach-list-item-meta {
  /* feature-0003 attach-list-delete: 행에 삭제(×)가 붙어 info 가용폭이 줄었다. ... */
  overflow: hidden; text-overflow: ellipsis; white-space: nowrap;
}
```

문제는 이 컨테이너가 **텍스트만 담고 있지 않다**는 것이다. `app.js:10075-10082` 가
`버전 N개 ▾` **버튼**(`.attach-list-item-vertoggle`)을 메타줄 안에 인라인으로 넣는다.
`white-space:nowrap` + `overflow:hidden` 이면 넘치는 인라인 자식은 잘리는데, 잘리는 것이
글자가 아니라 **버전 이력을 여는 유일한 진입점**이다. 스크롤도 없고 대체 경로도 없다.

폭 계산(패널 `min-width:240px`, `.attach-side-panel-list` padding 10/12 ·
`.attach-list-item` border 1 + padding 8/10 · icon ~18 · gap 8×2 · `.attach-list-item-dl`
~24):

| 패널 폭 | `.attach-list-item-info` 가용폭 | 메타줄 `120KB · 읽기 완료 · 버전 3개 ▾` 실폭(10.5px) | 결과 |
|---|---|---|---|
| 280px (기본) | ~176px | ~149px | 들어감 (여유 ~27px) |
| 240px (`min-width`) | ~136px | ~149px | **~13px 초과 → `3개 ▾` 절단** |

패널은 `.attach-side-panel-resizer` 로 사용자가 직접 좁힐 수 있고(240px 까지), 이 패널은
본문 위에 얹히는 fixed overlay 라 좁히려는 유인이 크다. 즉 도달 가능한 상태다.

그리고 이 diff 가 삭제 × (`padding 4px 6px` + 14px 글리프 ≈ 26px)를 걷어내면서 **주석이
말하는 압박 요인 자체가 사라졌다** — 근거는 없어졌는데 규칙과 그 근거 주석은 남았다.
그렇다고 규칙을 그냥 지우면 직전 design 리뷰가 잡았던 2줄 터짐이 재발한다. 올바른 해소는
같은 파일이 **이름줄에서 이미 쓴 패턴**(`.attach-list-item-ver { flex-shrink: 0 }`,
styles.css:3321)을 메타줄에도 적용하는 것이다: 메타를 `display:flex; align-items:baseline`
로 만들고 크기·상태 텍스트만 말줄임, 토글은 `flex-shrink:0`. 행 높이는 1줄로 유지되면서
컨트롤은 살아남는다.

### D2 (a11y/label, CONCERN) — 실패 항목의 accname 이 실제 동작과 어긋난다

`app.js:9604-9605`:

```js
cancelBtn.setAttribute("aria-label", "업로드 취소");
cancelBtn.title = it.status === "failed" ? "실패한 항목 치우기" : "업로드 취소";
```

`title` 은 상태별로 갈리는데 `aria-label` 은 상수다. accessible name 계산에서 `aria-label`
이 `title` 을 이긴다 → 실패 항목에서 스크린리더는 **"업로드 취소"** 라고 읽는다. 취소할
업로드는 이미 끝났고(실패), 실제 동작은 "실패한 항목 치우기"다. 하필 **가장 오래 화면에
남는 상태**(uploading 은 수 초, failed 는 사용자가 치울 때까지)에서 어긋난다.
`staged`(첫 메시지와 함께 업로드 대기) 도 엄밀히는 아직 업로드가 시작되지 않은 상태라
"취소"가 느슨하다. 라벨 문자열 하나를 만들어 `aria-label`·`title` 이 같이 쓰면 끝난다.

### D3 (PASS) — pill 행의 ×유무 비대칭은 우측 정렬을 무너뜨리지 않는다 (지시 1번)

`.attach-side-panel .composer-attachment-pill` 은 `display:flex`(styles.css:3054) 이고
`.pill-name` 이 `flex:1`(3064), `.pill-size` 와 `.pill-remove` 는 `flex-shrink:0`(3073, 3082)
이다. pill 은 `.attach-side-panel-list`(`display:flex; flex-direction:column`, 기본
`align-items:stretch`) 의 자식이므로 **모든 행이 동일 폭으로 늘어난다** — × 유무와 무관하게
행의 우측 경계는 일직선이다. ×가 없는 행은 `.pill-name` 이 그만큼 넓어질 뿐이다.

남는 것은 행 **내부** trailing 콘텐츠(KB 텍스트 / 버전 배지)의 들여쓰기 차이뿐이다:
×있는 행 = 우측에서 8(pill padding) + 12(버튼 폭: 글리프 ~8 + `padding:0 2px`) + 6(gap)
= 26px, ×없는 행 = 8px → **약 18px 계단**. 다만 × 가 붙는 행은 이미
`[data-uploading="true"] { opacity:.6 }`(3087) 또는 `[data-error="true"]` 의 danger
border(3086) 로 시각 상태가 다르게 읽히므로, 이 계단은 "이 행엔 컨트롤이 하나 더 있다"로
해석되지 조판 사고로 읽히지 않는다. 반대로 모든 행에 고정 폭 슬롯을 예약하면 **일시적
상태 하나를 위해 영구적 죽은 여백**을 지불하게 되므로 더 나쁘다. 현 선택이 맞다.

행 높이도 흔들리지 않는다: `.pill-remove` 는 `font-size:14px; line-height:1` → 14px,
이름줄은 11.5px × `line-height:1.2`(base 규칙) ≈ 13.8px, 버전 배지는 12+2 = 14px. 즉
Δ≈0.2px 이고 버전 배지가 붙은 행은 이미 14px 라 변화가 없다. 서브픽셀.

### D4 (PASS) — 안내 문구는 교체 전보다 **짧아졌고**, 최소 폭에서도 2줄이다 (지시 4번)

`.attach-side-panel-note` = 11px / `line-height:1.4` / `padding:8px 14px`(styles.css:2784).
콘텐츠 폭은 기본 280px → 252px, 최소 240px → 212px.

- 신규: "AI 는 이 대화에 올린 파일 전체를 참고합니다. 첨부는 대화에 계속 쌓입니다." ≈ 371px
- 기존: "… 필요 없는 파일은 × 로 삭제하세요." ≈ 393px

교체 결과가 **22px 더 짧다**. 252px 에서 2줄, 212px 에서도 어절 경계로 끊으면 2줄
(1행 "…파일 전체를" ≈163px, 2행 "참고합니다. 첨부는 대화에 계속 쌓입니다." ≈205px ≤ 212px).
총 높이 ≈ 2×15.4 + 16 = 47px — 100vh 패널 상단의 6% 남짓. 과점유 아니다.
**직전 배포본과 동일한 줄 수에 폭은 더 여유롭다** → 회귀 없음.

부수 효과로 구조적 결함 하나가 사라진다. `#attachSidePanelNote` 는
`_loadConversationAttachmentList`(app.js:10044-10055) 만 노출/은닉을 관리하고
`_renderAttachmentPills` 는 건드리지 않는다 — 같은 `#attachSidePanelList` 를 두 렌더러가
번갈아 쓰므로 **목록 뷰에서 켜진 안내가 pill 뷰에서도 그대로 남는다**. 구 문구는
"× 로 삭제하세요"라며 뷰마다 존재 여부가 다른 컨트롤을 가리켰고(그래서 직전 cycle 이
목록에도 ×를 추가해야 했다), 신규 문구는 **어떤 컨트롤도 가리키지 않으므로 두 뷰 어디서
보든 참이다**. 버튼을 추가해서 문구에 맞추는 대신 문구를 뷰-불변으로 만든 것이 옳은 방향.

### D5 (PASS) — 빨간 hover 는 과하지 않다. 오히려 지금이 **더 정확한** 무게다 (지시 5번)

`.attach-side-panel .composer-attachment-pill .pill-remove:hover` 는 `color` 만 danger 로
바꾼다(styles.css:3085) — 배경 채움 없음. 같은 파일의 더 강한 처리
(`.pill-toggle:hover { background: rgba(239,68,68,.08) }`, 2023-2026) 는 여기 쓰이지 않는다.

주목할 점은 방향이다. **직전 배포본에서는 이 약한 색상 변화 하나가 되돌릴 수 없는 서버
`DELETE` 를 대표했다**(확인 모달이 유일한 방어). 지금은 같은 시각 무게가 로컬 임시 항목
정리라는 훨씬 가벼운 동작을 가리킨다. 즉 이번 변경은 시각 언어를 과하게 만든 것이 아니라
**과소 신호였던 것을 정합화**했다. 취소·해제 어포던스에 muted→danger 색상 hover 는 널리
쓰이는 관용이며, 이 이상 톤을 낮추면 클릭 가능성 자체가 흐려진다. 변경 불필요.

### D6 (PASS, 지시 2번) — `.attach-list-item-del` 제거는 깨끗하다. 다만 이웃의 선재 죽은 CSS 는 그대로다

repo 전역 grep 결과 `.attach-list-item-del` 의 **실코드 참조 0건** (남은 히트는
`docs/reviews/*`·`docs/TASK.md` 등 이력 기록 산문뿐 — 정상). 테스트도 안전:
`tests/` 어디에도 `attach-list-item-del`·`attachSidePanelNote`·안내 문구 문자열 assertion 이
없어 **이번 diff 로 깨지는 테스트는 없다**. 반대로 "쓰이는데 지워진 규칙"도 없다 —
`.pill-remove` 는 여전히 `app.js:9603` 이 생산하고 스타일(3075-3085)은 보존됐다.

다만 같은 청소 반경 안에 **선재 죽은 CSS** 가 남아 있다(이번 diff 가 만든 것 아님):
`_renderAttachmentPills` 가 유일한 pill 생산자이고 사이드패널에만 렌더하므로 —
`.composer-attachments-pills`(1960, 컨테이너가 index.html 에 없음),
`.composer-attachment-pill` base 의 `display:inline-flex`/`max-width:280px`(1965-1978, 사이드
패널 규칙이 덮음), `.pill-toggle`(+`:hover`) (2012-2026, TASK-0161 로 생산자 소멸),
`[data-selected="false"]` ×2 (2027-2034, `data-selected` 를 세팅하는 코드 없음). 범위 밖이라
BLOCK 요소는 아니지만, 죽은 규칙을 지우는 커밋에서 바로 옆의 죽은 규칙을 남기면 다음
독자가 "이건 살아 있나 보다"로 오독한다.

### D7 (latent, 정보) — `deleted` 서버 첨부가 `isPendingLocal` 을 통과하는 잠복 경로

`isPendingLocal = !(Number(it.id) > 0) || it.status !== "ready"` (app.js:9599) 는 로컬 상태
어휘 {staged, uploading, ready, failed} 기준으로는 정확하다. 그런데
`_loadConversationAttachments`(app.js:9964) 가 서버 상태를 이렇게 매핑한다:

```js
status: String(a.status || "ready") === "deleted" ? "failed" : "ready",
```

즉 서버측 `deleted` 첨부는 **양수 id + status "failed"** 로 들어와 ×가 렌더되고,
`_discardPendingAttachmentPill` 의 가드(`id>0 && status==="ready"`) 도 통과해 목록에서
빠진다. 실제로는 발현하지 않는다 — `GET /api/conversations/{cid}/attachments` 가
`WHERE ... DeletedAt IS NULL`(conversations.py:2232) 로 걸러 `deleted` 를 애초에 반환하지
않는다. 또 그 경우 UI 동작(이미 삭제된 항목을 로컬 목록에서 치움)이 append-only 를 어기는
것도 아니다. **현행 결함 아님** — 다만 "양수 id = 서버 확정 = ×없음" 이라는 이번 계약이
`ready` 라는 단일 문자열에 걸려 있고, 그 문자열은 다른 함수의 매핑 규칙에 의존한다는
접합부만 기록해 둔다.

## 2. Risks (위험)

- **R1 (D1)** — 패널을 좁힌 사용자가 `버전 N개 ▾` 를 못 누른다. 대체 경로가 없어(목록 행이
  버전 이력의 유일한 진입점) AI 수정본 이력 확인 기능이 조용히 소실된다. 조건부(패널
  좁힘 + 버전체인 ≥2)라 재현이 산발적이고, 그래서 배포 후 오래 살아남는 종류의 결함이다.
- **R2 (D2)** — 스크린리더 사용자가 실패 항목의 ×를 "업로드 취소"로 듣고, 진행 중인
  업로드를 끊는 버튼으로 오해해 누르지 않을 수 있다 → 실패 pill 이 영구히 남는다.
- **R3 (D6)** — 죽은 CSS 잔여물이 다음 첨부 UI 작업에서 "살아 있는 규칙"으로 오독될 여지.
  낮음.
- **R4 (설계 수용 위험, 정보)** — append-only 자체의 귀결: 잘못 올린 파일이 화면에서
  치워지지 않는다. 안내 문구가 이를 명시하고(D4) 사용자 결정이므로 리뷰 대상 아님. 다만
  시각적으로는 "지울 수 없는 목록"이 길어질수록 패널 스크롤이 유일한 탐색 수단이 된다 —
  현재 정렬은 `ORDER BY Id ASC`(오래된 것이 위)라, 첨부가 수십 건 쌓인 대화에서 방금 올린
  파일이 스크롤 맨 아래로 밀린다. **이번 cycle 범위 밖이지만 append-only 를 확정한 이상
  이후 실사용에서 가장 먼저 마찰이 날 지점**으로 기록해 둔다.

## 3. Recommendations (권고)

1. **(D1, 권장)** `.attach-list-item-meta` 를 `display:flex; align-items:baseline; gap:0`
   로 바꾸고 크기·상태 텍스트를 감싼 요소만 말줄임, `.attach-list-item-vertoggle` 에
   `flex-shrink:0` 을 준다 — `.attach-list-item-ver`(styles.css:3321) 가 이름줄에서 이미
   쓰는 검증된 패턴. 동시에 주석의 "삭제(×)가 붙어 info 가용폭이 줄었다" 를 현재 근거
   (좁힌 패널 폭에서 메타줄이 2줄로 터지는 것 방지)로 갱신한다.
2. **(D2, 권장)** 라벨을 한 번만 만들어 둘 다에 쓴다:
   `const label = it.status === "failed" ? "실패한 항목 치우기" : "업로드 취소";`
   → `setAttribute("aria-label", label)` · `title = label`.
3. **(D6, 선택)** 같은 커밋에서 `.pill-toggle`(+`:hover`) · `[data-selected="false"]` ×2 ·
   `.composer-attachments-pills` 를 함께 정리하거나, 남긴다면 "생산자 없음(TASK-0161)"
   주석을 달아 둔다.
4. **(R4, 이월)** 첨부 목록 정렬을 최신 우선으로 두거나 "이번 요청에 첨부" 섹션을 목록
   뷰에도 유지하는 안을 별도 항목으로 표면화 — append-only 확정의 직접적 귀결이므로
   이번 cycle 이 아니라 후속 판단 대상.
5. **(검증)** PB-0008 실기 확인 시 **패널을 최소 폭(240px)까지 좁힌 상태**에서 (a) 버전
   체인 ≥2 첨부의 `버전 N개 ▾` 가 보이고 눌리는지, (b) 안내 문구가 2줄인지, (c) 업로드
   중 pill 과 저장 완료 pill 이 섞인 상태의 우측 정렬을 함께 본다. 기본 폭에서만 보면
   D1 은 통과로 보인다(기본 280px 에서는 ~27px 여유로 들어감).

## 4. Verdict rationale (판정 근거)

지시받은 5개 검증 항목 중 **4개는 실측으로 PASS** 다. 우측 정렬 비대칭(D3)은
`.pill-name{flex:1}` + column-stretch 구조상 행 경계가 일직선으로 유지되고 내부 계단 18px
