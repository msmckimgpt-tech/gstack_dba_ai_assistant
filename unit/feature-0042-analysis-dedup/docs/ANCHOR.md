# ANCHOR: feature-0042-analysis-dedup 분석 요청 경제성

## §1. 외부 관점 요약

이 feature 디렉토리에는 **코드가 없다**. 처음 열어본 사람은 "왜 unit 이 문서만 갖고 있지?"라고
물을 것이다. 이 cycle 의 산출물이 구현이 아니라 **판정**이기 때문이다 — 후보 3개 중 하나는
라이브 실측으로 기각됐고, 하나는 프로브로 실현 가능성만 확정했으며, 하나는 안전망이 없어 보류됐다.

또 하나 의아할 지점: 이름이 `analysis-dedup` 인데 정작 dedup 은 기각됐다. 착수 시점의 1순위
후보에서 이름이 유래했고, 브랜치·REGISTRY 가 이미 그 slug 로 생성돼 개명 마찰이 더 컸다.

## §2. 가정된 사용 맥락

- 이 프로젝트의 LLM 은 **종량제가 아니라 OAuth 구독 토큰**으로 서빙된다. 따라서 "토큰 절감"의
  가치는 요금이 아니라 **계정 사용량 한도(5시간 창) 압박 완화**다. batch API 의 50% 할인이
  가치 0 인 이유이자, 절감 효과를 금액으로 환산하지 않는 이유다.
- 분석 워커는 사람이 진행률을 보며 기다리는 준실시간 잡이다(tick 60초·lease 900초).
  24시간 SLA 를 갖는 비동기 배치와는 성립하는 계약 자체가 다르다.
- 분석문은 대화 답변에 grounding 으로 주입된다(feature-0034). 따라서 분석 품질 저하는
  조용히 답변 품질로 번진다 — 프롬프트 변경에 안전망을 요구하는 근거다.

## §3. 방향성 stable reference

- **절감은 품질보다 우선하지 않는다.** 형제 dedup 을 기각한 이유가 이것이다 — 요청 수는 줄지만
  부모 테이블 맥락이 사라진다. 절감안이 정보를 지우면 그것은 절감이 아니다.
- **전제는 착수 직전에 측정한다.** 등재는 착수 허가가 아니다(ADR-001).
- **관측할 수 없는 것은 판정하지 않는다.** 구독 한도 회계는 미확정으로 남겼다 — 추정으로
  채우면 이후 결정이 그 추정을 사실로 인용한다.
- **프롬프트는 계약이다.** `NODE_ANALYSIS_PROMPT` 의 각 블록은 특정 회귀(운영자 불만·인젝션·
  refine override)에 대응해 추가됐다. 축소는 "다듬기"가 아니라 계약 축소이며 안전망을 요구한다.
