# Function: 분석문 사실성 판정 (ITEM-10)

## 개요

노드 분석문을 **L0 통계 증거와 대조**해 `supported` / `contradicted` / `unverifiable` 중 하나로
판정하고 근거 한 문장과 함께 저장한다. AI 의 말을 AI 가 평가하는 게 아니라, **AI 의 말을 실제
측정값과 대조**한다.

지금까지 생성된 분석문의 사실성을 아무도 확인하지 않았다. 1만여 건이 클러스터 요약(L2)의
입력이 되고 대화 답변에 주입되는데(feature-0033·0034), 아래층이 틀렸는데 아무도 모르면 그
오류가 위로 전파되며 오히려 더 그럴듯해진다.

## 1. 정직성 계약 — 이 모듈의 전부

```
판정 실패는 "검증됨"이 아니다.
```

LLM 오류·타임아웃·계약 위반 응답·근거 없는 응답·증거 부재·저장 실패·예산 소진 —
**전부 행을 만들지 않는다(= 미검증)**. `supported` 로도 `unverifiable` 로도 기록하지 않는다.

확인 도장이 잘못 찍히면 그 도장을 근거로 위층이 더 확신하게 되고, 그러면 이 층은 없느니만
못하다. 그래서 이 모듈의 fail-soft 는 **"통과시킨다"가 아니라 "침묵한다"** 다.

세 상태가 구분되어야 운영자가 무엇을 믿을지 정할 수 있다:

| 상태 | 뜻 |
|---|---|
| `supported` | 증거가 주장을 뒷받침한다 |
| `contradicted` | 증거가 주장과 **모순된다** |
| `unverifiable` | 증거가 그 주장을 다루지 않는다(실패가 아니라 정직한 "숫자가 말해주지 않음") |
| (행 없음) | **아직 확인되지 않음** |

**예외 하나**: 예산 모듈을 읽을 수 없으면 pass 를 **중단**한다. 다른 fail-soft 와 방향이 반대인
이유는, 계량 장애로 기능이 멈추는 것보다 상한을 모른 채 자동 지출을 계속하는 쪽이 위험해서다.

## 2. 왜 기존 인프라를 재사용하지 않았나

- **feature-0021 red-team**: `question + draft + evidence` 구조의 **답변 전용** 프롬프트다.
  노드 분석문에는 question 이 없고 evidence 의 성격도 다르다(대화 근거 vs 테이블 통계).
- **`node_analysis_jobs.pass_no`**: back-refine 세대(재분석 몇 번째)를 뜻한다. 검증은 직교하는
  축이라 같은 컬럼에 얹으면 "3번째 재분석"과 "3번째 검증"이 구분되지 않는다.

## 3. 대상 선정

분석문(`status='done'`)과 증거(`metadata_table_stats`, `error IS NULL`)가 **둘 다** 있고,
**그 분석문 버전**으로 아직 판정되지 않은 것. 한 번도 판정된 적 없는 노드를 먼저, 그다음 증거가
깊은 것(stage) 부터.

`analysis_hash` 가 재판정의 축이다. 이전 판정의 해시를 함께 조회해 현재 분석문 해시와 비교한다 —
"판정 행이 있으면 제외"로 두면 분석이 갱신돼도 옛 판정이 남아 **재판정되지 않는다**.

저장 시 같은 노드의 다른 해시 행을 삭제해 **노드당 1행**을 유지한다(무한 증식·중복 판정 차단).

대상도 **노드당 최신 분석문 1건**이다(`DISTINCT ON`). 저장이 노드당 1행인데 대상이 행 단위이면
판정이 무한 순환한다 — 같은 노드에 여러 분석 run 의 done 행이 쌓이므로, A세대를 저장하면
B세대가 미판정으로 남고 B세대를 저장하면 A행이 지워져 다시 미판정이 된다. 2026-08-05 라이브에서
이 순환이 7일간 7,896콜(배경 LLM 호출의 62.8%)을 태우고도 판정 행은 91개로 고정돼 있었다
(노드당 평균 87회 재판정). 두 정책이 같은 단위를 볼 때만 순환이 닫힌다 — ADR-0036-08.

"최신"의 기준은 **`id`(삽입 순)** 다. `updated_at` 은 모든 UPDATE 가 트리거로 올리기 때문에 과거
run 행이 재분석 행보다 최신으로 역전된다 — 이 저장소가 이미 겪고 `id DESC` 를 정본으로 삼은
결함이다(`node_analysis.get_node_analysis` 와 같은 기준을 써야 판정 대상과 상세 패널이 같은 문장을
가리킨다). 순회 순서는 **판정이 오래된 것부터**(미판정이 맨 앞) — "미판정 우선"만 두면 갱신된
분석문의 재판정이 두 겹으로 밀려 굶는다.

telemetry 는 `attempted`(실제 LLM 콜) · `rejudged`(이전 판정이 있는데 다시 판정) 를 `checked` 와
나란히 낸다. `attempted ≫ checked` 는 판정 실패가 예산을 먹는 중이라는 뜻이고, `rejudged` 가 pass
마다 상한을 채우면 대상 선정이 다시 도는 중이라는 신호다. 두 값은 `insight.py` 의 명시 payload
allow-list 에 등재돼야 운영자에게 도달한다(dict 는 telemetry sweep 이 버린다).

## 4. 비용

| 장치 | 값 |
|---|---|
| pass 당 판정 수 | 20 (콘솔 live) |
| 배치 | **없음 — 1건 1콜** (배치하면 한 건의 오판이 다른 건으로 번진다) |
| 상위 게이트 | 백그라운드 토큰 예산(항목마다 재확인) · `acquire("llm")` · kill-switch |

호출측 `limit` 인자는 설정 상한을 **넘을 수 없다** — 인자로 우회하면 콘솔 knob 이 거짓 컨트롤이 된다.

## 5. 판정 프롬프트의 기울기

판정자는 **모순을 찾는 쪽으로 기울어야** 한다("prefer contradicted over supported when a real
conflict exists"). 확인 도장을 남발하는 판정자는 없는 것보다 나쁘다. 동시에 "do not invent
conflicts to look thorough" 로 반대 방향 과잉도 막는다.

증거가 **표본**임을 명시한다 — 표본 유일성을 전역 제약의 증명으로 다루지 않고, 분석문이
신중하다는 이유로 틀렸다고 하지 않는다.

`reason` 은 **판정을 가른 구체적 숫자·필드를 지목**하는 한 문장이다. 근거 없는 판정은 사람이
재확인할 방법이 없으므로 **기록하지 않는다**.

## 6. 격리

조회·적재를 savepoint 로 감싸고, `cursor()` 획득도 try 안에서 한다. `conn` 이 없으면 자체
agent_kb 연결을 연다(insight tick 스코프에는 그 커넥션이 없다). 어떤 실패도 분석 흐름을 막지 않는다.

## 7. 표시 (판정의 소비처)

그래프 뷰 노드 상세의 'AI 능동 분석' 박스에, 그 분석문의 판정을 배지 + 근거 한 줄로 보여준다
(`get_node_analysis` 응답의 `verdict`). ANCHOR §3 이 그리는 장면 — *"그 분석문 옆에
`contradicted` 와 함께 '어떤 숫자가 판정을 갈랐는지' 한 줄이 붙어 있다"* — 이 여기서 실현된다.

**표시도 해시가 일치할 때만 한다**(ADR-0036-09). 판정은 노드당 1행이라 분석문이 갱신되면 그 행은
지금 보이는 문장이 아닌 다른 문장에 대한 판정이다. 조회 조건에 현재 분석문 해시를 넣어 불일치를
0행으로 만든다 — 생성 단계에서 막은 실패(확인하지 않은 서술에 도장)를 표시 단계에서 되풀이하지
않기 위해서다.

미판정·판정 실패·해시 불일치는 **모두 표시 없음**으로 수렴한다. 운영자가 구분해야 할 것은
"판정이 있다/없다"이지 없는 이유가 아니다. 판정 조회가 실패해도 상세 패널은 그대로 뜬다
(판정만 사라진다).

**대조 기준을 라벨이 말한다.** 증거 stage 0 은 표본이 0행이라 컬럼 통계가 하나도 없다(컬럼명·타입·
행수 추정만 있다). 그 판정을 "표본 통계와 모순 없음"으로 부르면 없는 표본을 근거로 내세우는 것이라,
stage 0 이면 라벨이 "구조와 모순 없음"이 되고 tooltip 이 "표본 없이 구조만 대조"를 명시한다.
라이브 판정의 대다수가 stage 0 이므로(적대 패널 실측 95건 중 82건) 이 구분이 곧 정직성이다.

증거가 깊어지면 **재판정한다**. 판정은 (분석문, 증거) 두 입력의 함수인데 해시는 분석문만 고정하고
증거는 테이블당 1행이 제자리 갱신되므로, 해시만 보면 stage 0 판정이 stage 1 수집 후에도 "대조했다"는
얼굴로 남는다. 대상 선정이 저장된 `evidence_stage` 와 현재 stage 를 비교해 그 창을 닫는다.

라이브 실측(2026-08-05): 표시 대상 2,052 노드 중 판정 보유 94~95개. 관측 중 한때 92/95 가 일치했는데,
그 3건은 재분석으로 분석문이 바뀐 노드였다 — 배지가 즉시 사라졌고, 워커가 재판정한 뒤 되돌아왔다.
해시 불일치는 결함이 아니라 **재판정 대기 상태**이며 라이브에서 자동 회복된다(설계대로 동작한 실증).
