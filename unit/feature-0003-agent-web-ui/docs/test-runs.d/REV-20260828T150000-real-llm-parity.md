## 사전 분석이 틀렸다 (정직 기록)

이 Run 직전, 코드만 읽고 **괴리 3건을 예측**했다:

> `tool_call_usage` 에 SQL 본문도 결과 행도 없으므로 브리지 답변은 인라인 "쿼리 결과" 테이블을
> 그릴 수 없고, `rationale`·결과 CSV 도 없다.

**세 건 다 틀렸다.** 실제로는 전부 렌더된다 — 형제 cycle 들이 `agent_runtime.steps` 의
`sql_text`·`reason_text`·`result_summary_json` 을 채우도록 이미 확장해 두었고, 나는 `tool_call_usage`
한 테이블만 보고 결론을 냈다. **원장 한 곳이 비었다고 해서 그 정보가 어디에도 없는 것은 아니다.**

교훈: 괴리를 **읽어서** 판정하려 한 것이 실수였다. 사용자가 "써 보고 느끼는" 것을 묻는 질문에는
써 보는 것이 유일하게 정확한 답이다. 이 Run 이 그 예측을 3/3 뒤집었다.

## 잔여 괴리 1건 — 모델·추론 조작면

기존 서비스에는 컴포저에 **모델·추론 강도 선택**이 있었다. 지금은 `+` 메뉴에 `파일 첨부 /
첨부파일 목록` 만 있고 두 선택지는 사라졌다(형제 cycle P0-T 결정).

그 결정 자체는 옳다 — 웹에서 고른 값은 서비스 내부 litellm alias 라 어느 CLI 도 모르고, 사실상
**모든** 요청이 "못 맞췄다" 고지를 달고 기본 모델로 돌았다. 있으나 마나 한 조작면이었다.

다만 **사라진 자리에 아무 설명이 없다**. 쓰던 사람은 선택지를 찾다가 그냥 없어진 것을 본다.
실제 통제권은 러너의 `--cmd 'claude --model opus -p {prompt}'` 로 옮겨갔는데, 화면 어디에도
그 사실이 없다.

> 판단 보류: 무엇을 어디에 쓸지는 UX 결정이라 사용자 확인 후 진행한다. 가짜 조작면을 되살리는
