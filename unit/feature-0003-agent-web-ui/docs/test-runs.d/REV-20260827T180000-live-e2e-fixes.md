# Run — 라이브 e2e 제보 조치

Environment: **Windows-browser 미수행** / 그러나 **실 AI 연결 e2e 는 다른 세션에서 수행됨**

## 이번엔 브라우저보다 강한 증거가 있었다

`win-browser` relay 는 여전히 불가하다. 그런데 이번 cycle 의 입력은 **실제 AI 가 실제로 연결해
도구를 호출한 결과**다 — 브라우저 시각검증보다 이 축에서는 더 강한 증거다:

| 확인된 것 | 결과 |
|---|---|
| MCP streamable HTTP 핸드셰이크 | 200, 세션 발급 |
| `mat_` 토큰 통과 | **브라우저 승인 불필요** → 방법 A·B 설계가 맞았다 |
| `tools/list` | **13종** 확인 |
| REST 축 `POST /api/ai/tools/open_task` | 200 (account=admin) |
| `list_open_requests` | **500 (100% 실패)** ← 이번 수정 대상 |

## 문구 변경분(웹 자산)의 시각검증은 미수행

`ai-connect.html`·`.js`·`.css`·`ai-api-guide.md` 문구를 줄였다. 렌더 확인은 못 했으나:

- HTML 파서 통과 · JS 구문 통과 · **지시문 텍스트를 격리 실행해 완성본 육안 확인**
- JS 가 참조하는 DOM id 전수 존재 확인(문구 수정이 버튼을 죽이지 않게)
- 토큰 경고 3요소는 **기존 계약 테스트가 지켰다** — 줄이다 "남에게 주지 마세요" 를 빠뜨렸고
  그 테스트가 잡아 복원했다. 문구를 줄이는 작업에서 테스트가 실제로 값을 한 사례다.

## 해소 조건

그 답변이 웹 대화 화면의 대기 말풍선을 **덮어쓰는지** 확인.
