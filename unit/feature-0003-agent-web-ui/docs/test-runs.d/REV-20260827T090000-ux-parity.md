# Run — 사용감 패리티 프론트 변경

Environment: **Windows-browser 미수행**

## 왜 미수행인가

`bin/win-browser.py` relay 가 이 환경에서 도달하지 않는다(`win_host` 오탐지 → CDP 연결 불가).
사유·해소조건은 `REV-20260827T000500-bridge-poll-ui.md` 와 동일하며 이번 cycle 이 그 상태를
바꾸지 않았다. **통과로 표시하지 않는다** — 보지 않은 것을 봤다고 적는 것이 가장 비싼 거짓이다.

## 대체 검증한 것

이번 프론트 변경은 두 갈래이고, 각각 다른 방식으로 잠갔다.

| 변경 | 대체 검증 |
|---|---|
| `handleBridgePending` 단일 헬퍼 신설 | 구문 검사(ES module) + 존재 단정 |
| 재답변·AI로 고치기 배선 | 소스에서 **호출 위치와 인자**를 단정. 성공 토스트가 `_bridged` 분기 **뒤**에 오는지까지 검사 — 순서가 뒤집히면 거짓 성공 보고가 되살아난다 |
| 전송 경로 통일 | 중복 로직 제거를 단정(두 벌이면 갈린다) |

## 잔여 위험 (정직하게)

자동 검증이 **잡지 못하는** 것:

1. **폴링이 실제로 화면을 갱신하는가.** `_pollBridgeAnswer` 자체는 이전 cycle 부터 있었고 이번에
   호출부만 늘렸다. 그 함수가 `loadHistory({preserveScroll:true})` 를 쓰는 것은 소스로 확인했으나
   (활성 대화에서 `selectConversation` 이 no-op 이 되는 결함을 이미 고친 경로), **재답변 문맥에서**
   브랜치 전환과 함께 동작하는지는 화면으로만 확인 가능하다.
2. **토스트 문구가 실제로 하나만 뜨는가.** 분기는 잠갔지만 상위 호출자가 별도 토스트를 띄우면
   두 개가 겹칠 수 있다.

해소 조건: win-browser relay 복구 시 `/?conversation=<cid>` deep-link 로 진입해 (a) 재답변 →
대기 말풍선 → 개인 AI 제출 → 자동 갱신, (b) 그룹 대화에서 발신자 이름 표시를 확인한다.
