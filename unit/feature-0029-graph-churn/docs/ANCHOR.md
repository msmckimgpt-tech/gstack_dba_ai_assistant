# ANCHOR: feature-0029-graph-churn

## §1. 외부 관점 요약
- "그래프가 덜 최신이 되는 것 아닌가?" — 아니다. 빠지는 것은 **값이 바뀌지 않은 행**의
  재투영이다. 값이 같으면 그래프 상태도 같으므로 투영 결과가 달라지지 않는다.
- "히스테리시스가 틀린 관계를 살려두지 않나?" — 파단이 1주기 늦어질 수 있지만 음성 감쇠가
  양성 상승보다 큰 비대칭(자기교정 방향성)은 그대로다. 오히려 145회 왕복하던 참인 관계가
  안정된다.
- "프로브가 broken 을 못 살리면 학습이 죽나?" — 프로브는 애초에 candidate 만 뽑는다. broken
  을 건드리던 건 이름 매칭으로 새어 들어간 것(교차오염)이지 설계된 학습 경로가 아니다.
  실행 성공한 대화 JOIN 은 여전히 부활시킬 수 있다.

## §2. 대안 분기
- **sync 대상에서 weight-only 변경 제외(lever d)** (성능 우선 페르소나): 효과는 있으나
  UI 신뢰 가중치 시각화가 최대 24h 지연 — (a)(b)(e) 후 잔여량을 보고 판단(이연).
- **cron 주기를 60분으로 늘리기** (운영 페르소나): 증상 완화일 뿐 원인(무의미 재투영)은
  그대로고 신선도만 잃는다 — 기각.
- **무방향 중복 행 dedupe 선행** (데이터 위생 페르소나): 근본적이나 UNIQUE 제약 변경 +
  기존 7,663행 병합이라 blast radius 가 크다 — 별도 cycle 로 분리하고, 이번엔 그 영향
  (교차오염)만 게이트로 차단.

## §3. 가정된 사용 시나리오
운영자가 `artifacts/metadata-graph/cron.log` 를 보면 30분 주기의 `relationships` 카운트가
수백~수천에서 실제 변경분 수준으로 떨어지고 `duration_ms`(feature-0026 계측)가 함께 줄어든다.
그래프 뷰의 관계 표시·신뢰 실선/추정 점선은 종전과 동일하게 유지된다.
