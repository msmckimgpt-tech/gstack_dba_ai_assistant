# Report

## 진행 요약 (2026-07-31)

ITEM-11(결정적 플래너) 구현 완료. codex 적대 리뷰 P1 2건 반영, 출하 중.

## 왜 이것을 먼저 했나

ROADMAP 의 T3 는 ITEM-10(검증층)·ITEM-11(플래너) 병렬인데 ITEM-11 을 먼저 잡았다. 직전
cycle 들의 라이브 검증에서 같은 수치가 반복해서 병목으로 나타났기 때문이다:

| 관측 | 수치 |
|---|---|
| 분석 완료 테이블 | **2,040 / 17,192 = 11.9%** |
| 클러스터 요약 중 "상세분석 근거 0" | **85%** |
| 대화 grounding 에 주입되는 요약 | 대부분 추정 |

세 수치가 같은 원인을 가리킨다 — **아래 층의 커버리지**. 그리고 그 커버리지는 사람이 우연히
클릭한 것만 채워져 있어 중요도와 무관하다. 여기를 고치면 위 세 층이 함께 올라간다.

## 설계 요지

- **결정적** — 관계 차수 + 대화 조인 이력의 가중합(50:1). LLM 없음. 재현 가능하고 설명 가능하다.
- **큐잉 재구현 없음** — `enqueue_change_analysis` 를 `reason` 만 바꿔 재사용. 자격·그래프
  실재·cap·쿨다운·busy 가드가 이미 거기 있다.
- **2중 상한** — 스키마당 3 + **사이클 전체 9**. 후자가 이번 리뷰의 P1 이었다.

## 리뷰에서 배운 것

codex 가 P1 2건을 잡았다:

1. **`DISTINCT` 누락** — `rag_objects` 유니크 키에 `conversation_id` 가 있어 같은 테이블이 여러
   행일 수 있다. 상한 3이 같은 테이블 3개가 되어 실제로는 하나만 시드된다.
2. **사이클 전역 상한 부재** — 재사용한 큐잉 경로의 가드가 **스키마 단위**라, 스키마 수만큼
   비용이 곱해진다.

2번은 feature-0033 에서 지적받은 것과 같은 계열이다. 이번에 나는 "검증된 경로를 재사용하니
안전하다"고 판단했는데, **그 경로의 가드가 어느 단위인지 확인하지 않았다**. 재사용은 가드의
범위까지 확인해야 성립한다 — ADR-0035-04 에 남겼다.

반면 `LIKE` 와일드카드 함정(`_` → 임의 1문자)은 feature-0034 에서 겪은 것을 이번엔 구현 중
스스로 잡았다.

## 남은 것

- 배포 후 라이브 검증(TEST.md §4) — 특히 **사이클 1회 시드 총합이 상한 이하인지**(이번 P1).
- 며칠 후 커버리지 재측정 + 클러스터 요약 `analyzed_count` 분포 개선 확인.
