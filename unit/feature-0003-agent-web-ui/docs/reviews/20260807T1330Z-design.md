## 1. Findings

### F1 · P2 — identical 배너가 절단을 반영하지 않는 **완결성 주장**을 한다 (자기모순 화면)

`_renderBody` 의 배너는 `data.truncated` 를 전혀 보지 않는다. 두 절단 축 모두에서 거짓이 된다.

**(a) 행 상한** — `row_cap=6000` 은 이번 변경으로 **identical 에도 처음 도달 가능**해졌다.
종전엔 identical → gap 1행이라 넘을 수 없었다. 8,000줄 동일 CSV 두 버전을 비교하면:

- warn: "**차이가 많아** 앞쪽 6000행만 표시했습니다."
- is-same: "두 버전의 내용이 동일합니다 — 아래는 문서 원문(**8000줄**)입니다."
- 표: **6000행** / 배지: "**차이 없음** — 원문 표시"

**(b) 원본 1MB 절단** — 라우터는 `raw[:1MB]` 만 비교한다. 1MB 이후만 다른 두 버전이
`identical=True` 로 나오고, 새 배너가 그 prefix 를 "문서 원문" 이라고 이름 붙인다. 종전 문구보다
주장이 강해졌다.

검증 공백: 하네스 B8 은 `.is-warn` **존재만** 확인하고 문구를 보지 않는다. 파이썬 B7b 는 서버
플래그만 본다. 두 배너의 상호모순은 어느 테스트에도 걸리지 않는다.

### F2 · P2 — "거짓 어포던스 금지" 를 본문 없는 4상태 중 1개에만 적용했다

`syncHlToggle` 은 무-본문 4상태를 전부 커버하는데(`comparable !== false` · `rows.length > 0` ·
`Boolean(data)`), 새 함수는 `identical` 만 본다. 바이너리 메타 비교 화면에서 "단일열" 을 누르면
`syncModeButtons()` 가 활성 pill 을 **눈에 보이게 옮기고** `rerender()` 는 같은 메타 표를 다시
그린다 — 컨트롤은 반응했는데 화면은 그대로. 이 모듈이 hl 토글에서 스스로 P1 로 판정해 봉인한
결함과 정확히 같은 계열이다.

### F3 · P3 — 원문 표에 추가한 CSS 가 **전부 no-op** 이고, 테스트가 그것을 고정한다

`.attach-diff-table.is-source .attach-diff-code { border-right: none; }` —
`.attach-diff-code` 에 `border-right` 를 주는 규칙은 파일 전체에서
`.attach-diff-table.is-split .attach-diff-code.side-left` **하나뿐**이다. 원문 표는 `is-split` 도
아니고 셀에 `.side-left` 도 없다. **끌 것이 없다.** 주석 스스로 "기본 스타일 그대로다" 라고
말하면서 규칙을 선언하는 자기모순이다. 하네스 D8 은 셀렉터 **문자열 존재**만 본다 —
CODE_REVIEW.md §2.1 "항상 통과하는 검사" 계열.

### F4 · P3 — `is-source` 가 table modifier 와 row modifier 두 계층에 동시에 쓰인다

이 모듈의 어휘는 table: `is-split`/`is-unified`, row: `is-equal`/`is-insert`/… 로 분리돼 있었다.
같은 토큰을 두 계층에 얹으면 후속 규칙이 두 곳에 걸린다. `tr.attach-diff-row.is-source` 는 현재
어떤 CSS 도 매치하지 않는 dead class 다.

### F5 · P3 — 같은 파일의 토큰 강도가 화면마다 다르다 (문서 미기재)

`.attach-diff-row.is-equal .attach-diff-code [class^="code-tok-"] { opacity: 0.78 }` 를 원문 행은
받지 않는다. 원문 뷰에는 억눌러야 할 델타가 없으므로 1.0 이 **설계상 옳다**고 본다. 문제는 그
판단이 어디에도 기록돼 있지 않다는 것.

### F6 · P3 — 새 CSS 블록이 표 블록이 아니라 컨트롤 바 블록 한가운데 놓였다

표 전용 규칙(`is-source`)이 표 블록에서 30줄 위, 컨트롤 바 규칙 사이에 있다. 다음 편집자가
`.attach-diff-table` 블록만 읽으면 못 본다.

### F7 · P3 — `[hidden]` 트랩을 **클래스 열거**로 막는 패턴이 4파일·9지점 재발 중

이번 수정의 specificity·순서는 **정확하다**(확인함: `.attach-diff-viewtoggle{display:inline-flex}`
2746 (0,1,0) → override 2790 (0,2,0), 후순위 + 고특이성). 그러나 같은 함정이
`profile.css:394-396`, `shell.css:187`, `search-audit.css` 5곳, 이번 `chat.css` 로 흩어져 있다.
컨트롤이 하나 더 추가되면 조용히 재발한다.

### F8 · P3 — identical 배너의 초록이 "추가된 줄" 어휘와 한 화면에 공존한다

`.attach-diff-notice.is-same` 의 `--tag-ok-*` 는 "추가된 줄" 배경과 같은 초록 12% 다. 종전에는
배너 아래에 표가 없어 충돌이 없었으나 이제는 초록 띠 바로 아래에 코드 표가 붙는다.

### F9 · P3 — 컨트롤을 지우면 부재의 이유가 화면에 남지 않고, 컨트롤 바가 흔들린다

`.attach-diff-stats{margin-left:auto}` 때문에 뒤따르는 요소가 좌우로 이동한다. 또 최대 6,000행
원문 벽 앞에서 사용자가 쥘 수 있는 조작이 "구문 색" 하나뿐이 된다.

## 결함이 아님 (적대적으로 확인하고 통과한 축 — 기록)

- **`_applySplitRatio` 가 원문 표에 닿지 않는다**: `_renderBody` 가 `_attachSplitHandle` 을
  호출하지 않고, 호출되더라도 `is-split` 셀렉터 null + `cols.length !== 4` 로 이중 방어. ✔
- **`source` kind col 폭이 Chrome 함정을 피한다**: 퍼센트 없는 `calc(Nch + 12px)` 만 인라인,
  본문은 auto — `unified` kind 와 동형. ✔
- **미디어쿼리 `is-source` 누락은 옳다**: `min-width:720px` 는 4열 표의 요구. 원문은 2열 +
  `white-space:pre-wrap` 이라 좁은 폭에서 줄바꿈으로 흡수. `is-unified` 도 같은 이유로 빠져 있다. ✔
- **`splitwrap` 재사용은 load-bearing**: `.attach-diff-splitwrap > .attach-diff-scroller{flex:1;
  min-height:0;overflow-y:auto}` 가 **자식 결합자**라, 래퍼 없이 두면 높이·스크롤 계약이 깨진다. ✔
- **원문 무손실**: `r.right ?? r.left` 가 `??` 라 빈 문자열/0 을 보존. ✔
- **다크/테마**: 신규 CSS 가 색상 값을 쓰지 않아 변수 체계와 충돌 없음. ✔
- **캐시버스터**: `?v=dev` 는 빌드가 스탬프로 치환 — 수기 bump 불필요. ✔

## 2. Risks

- F1 은 사용자 요청의 정면이다. 6,000행을 넘는 문서에서 화면이 "원문" 이라 부르는 것은 원문이
  아니며, 이 상태는 이번 변경으로 **새로 만들어졌다**.
- F3 + D8 은 다음 사람이 "원문 표에는 전용 스타일이 있다" 고 믿게 만든다. 규칙을 지워도 D8 만
  빨개지고 화면은 안 변한다 — 어느 쪽이든 테스트가 사실을 말하지 않는다.
- 잠재 a11y(현재 도달 불가): `hidden = true` 시 포커스가 그 안에 있으면 `<body>` 로 떨어진다.

## 3. Recommendation

R1 배너 두 개를 절단에 게이트(하네스 B8 강화 + source-cap 케이스 추가).
R2 `syncDiffOnlyControls` 판정면을 `syncHlToggle` 과 동일하게 + 초기 호출.
R3 dead CSS 삭제 · row dead class 제거 · D8 을 DOM 구조 단언으로 교체.
R4 `base.css` 에 `[hidden]` 계열 종결 규칙(후속 cycle 로 기존 9지점 회수).
R5 identical 배너를 중립색으로(초록은 "추가" 에 예약).
R6 모드 토글은 지우지 말고 **비활성 + 이유(title)** — 컨트롤 바 흔들림 제거.
R7 colgroup 표에 `is-source` 행 추가 · opacity 비대칭 명시 · MODIFY.md Files 정정.
