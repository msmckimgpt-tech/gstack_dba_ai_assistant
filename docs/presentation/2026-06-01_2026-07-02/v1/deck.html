개발 배경 · 왜 이 일을 했나

"보고 싶은 데이터는 많은데, 안전하게·정확하게·안 끊기게가 어렵다"

상황

  • SQL을 모르는 현업도 데이터를 직접 보고 싶어 함 → 자연어 어시스턴트 도입.
  • 대상 데이터가 MySQL 한 종류, 웹은 단일 인스턴스였음.
  • 메타데이터(테이블·컬럼 뜻)가 평면 목록 — 대규모 스키마(수천 테이블) 탐색이 어려움.

문제

  • 배포할 때마다 화면이 잠깐 끊김 — 주 채팅까지 영향.
  • 계정 보호(2단계 인증)·악용 방어·기록 변조 방지 등 운영 신뢰 요소 미흡.
  • 답의 정확도를 측정·개선할 수단과, 여러 DB·회사 용어를 이해할 근거가 부족.
그래서 이번 기간의 목표 — (1) 배포·재시작에도 안 끊기게, (2) 더 많은 데이터(＋MSSQL)를 더 정확하게, (3) 안전하게·함께 쓰고 운영자가 관제할 수 있게. 아래는 사용자가 화면을 만나는 순서로 설명합니다.

1. 안전하게 접속·인증 신규

"들어오는 문"을 신뢰할 수 있게 만들었습니다

1배경·문제

사내 접속 시 인증서 경고가 뜨고, 로그인은 아이디·비밀번호 단일 인증이라 계정 도용·무차별 시도에 취약했습니다.

2화면 흐름
주소 접속(https)›로그인›2단계 인증›작업 화면

첫 접속 시 사내 인증서를 원클릭으로 신뢰 등록 → 이후 경고 없음.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

보안·신뢰가 도입의 전제. 표준(TOTP·자체 인증서)을 택해 추가 비용 없이 사내 환경에 맞췄고, 2단계 인증은 사용자가 스스로 등록(운영 부담 최소)하도록 했습니다.

5기대 효과 고도화 예정

계정 도용·무차별 로그인 위험 감소, 접속 신뢰 확보. 기능 개발 완료 — 실제 사고 예방 효과는 운영 데이터로 확인하며 계속 강화합니다.

2. 물어보고 답 받고 다듬기 (작업 화면) 신규

답을 "받는" 데서 "함께 다듬는" 화면으로

1배경·문제

답변·첨부 SQL을 고쳐 달라고 하면 무엇이 바뀌었는지 알기 어려웠고, 큰 결과는 화면을 무겁게 했으며, 처리 중 조작이 애매했습니다.

2화면 흐름
질문›진행(전송↔중단)›표 답변›변경점 비교›첨부 새 버전
3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

사용자 영향 우선 — 검토 신뢰(무엇이 바뀌었나)와 조작감. 기존 채팅 화면과 호환되게 얹어 학습 부담을 줄였습니다.

5기대 효과 개발 완료

검토 시간 단축·오해 감소, 첨부 반복 수정 추적. 개발 완료. 사용자 체감 개선폭은 실사용 관찰 후 보고.

3. 더 정확한 답 (정확도) 신규

"잘 나온 답"이 다음 답을 더 정확하게 만드는 선순환

1배경·문제

정확도를 측정할 수단이 없고, AI가 회사 고유 용어·코드값(예: 상태 1=결제완료)을 몰라 오답 여지가 있었습니다.

2선순환 흐름
질문·답변›좋은 답 등록›관리자 검수›참고 예시↻정확도↑

＋ 회사 용어/코드값 사전, 의미＋키워드 혼합 검색.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

측정 선행 — 개선을 증명할 잣대부터. 자동 학습이 아니라 사람 검수를 거쳐(데이터 오염 방지) 안전하게 정확도를 올립니다.

5기대 효과 수치 측정 예정

답변 정확도 향상 기대. 측정·환류 수단 확보 완료 — 정확도 향상 수치는 다음 기간에 측정해 성과로 제시합니다.

4. 더 많은 데이터 (멀티 데이터소스) 신규

MySQL 전용에서 여러 데이터베이스 분석 플랫폼으로

1배경·문제

대상이 MySQL 한 종류였고, 접속 정보 관리·접근 통제가 미흡했습니다. 현업 데이터는 MSSQL에도 있습니다.

2접근 구조
제품›데이터소스(MySQL·MSSQL)›허용 DB 목록›조회

바인딩 없으면 접근 0 — 기본이 "차단".

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

보안·안정성 우선(기본 차단·엔진별 가드·불안정 DB 격리) + 운영 편의(관리 화면에서 추가·연결 테스트).

5기대 효과 개발 완료

분석 대상 확대·안전한 다중 연결. 개발 완료. 각 엔진 운영 효과는 확대 적용하며 확인합니다.

5. 함께 쓰기 (그룹 대화) 신규

데이터 점검을 "여럿이 한 대화"에서

1배경·문제

데이터 점검은 혼자보다 함께가 많은데, 대화는 1:1 뿐이었습니다. 공유 시 권한·읽음 표시가 애매했습니다.

2화면 흐름
공유 링크 초대›사람끼리 의논›@어시스턴트 멘션›AI 응답(요청자 권한)
3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

사용자 영향＋보안 — "열람은 되지만 조회는 권한 있는 사람만". 단일 권한 대신 세분 권한으로 실제 협업 요구에 맞췄습니다.

5기대 효과 개발 완료

협업 점검·지식 공유. 개발 완료. AI 조회는 항상 요청 본인 권한으로만 — 권한 확장 없음.

6. 운영·관제 강화 + 메타데이터 지식그래프 신규

운영자가 "한눈에 보고 통제"하고, 대규모 스키마를 그래프로 탐색

1배경·문제

사용량·AI 동작·권한을 한눈에 볼 화면이 부족했고, 수천 개 테이블을 평면 목록으로 탐색하기 어려웠습니다.

2관리 화면 영역
사용량 대시보드AI 운영 현황권한 편집기사용량 한도지식그래프

＋ 감사 기록 변조 방지(연결 검증).

3변경 전 → 후 (메타데이터 탐색)
실제 화면 대신 개념 도식
4왜 이 방향

운영 편의·안전 — 표준 그래프 기술로 관계를 다루고, 관계 정보가 없어도 관계를 추론하되 추정/신뢰를 구분 표시(과대표현 방지).

5기대 효과 검증＋고도화

운영 가시성↑·대규모 스키마 탐색. 지식그래프 서버 조회가 약 60배 빨라진 것은 검증됨. 화면 렌더 속도·시각검증은 실측으로 확인해 완성도를 높입니다.

7. 끊김 없는 서비스 (안정성·인프라) 완료 · 고도화 진행

배포하고 재시작해도, 사용자는 끊김을 느끼지 않게

1배경·문제

배포할 때마다 화면 끊김이 났고, 재시작 시 진행 중 작업이 중단됐으며, 거대한 단일 코드 파일은 유지보수가 어려웠습니다.

2무중단 처리
2대 웹(A·B)›한 대씩 교체›최소 1대 정상›무중단

＋ 질문은 "작업 대기열"에 넣어 재배포에도 생존.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

안정성·운영편의 — 표준 분배기로 간결하게. 코드 분할은 겉보기 동작을 바꾸지 않는 방식으로 안전하게 진행.

5기대 효과 배포·실증 검증

배포 중 중단 0 실증(부하 104건 정상)·코드 모듈화 완료. 자동 롤백·백업 자동화는 검증을 거쳐 순차 적용합니다.

기대 효과 · 성과 종합

검증된 성과와, 앞으로 더 키울 발전 과제

검증됨 근거 있는 성과

  • 무중단 배포: 롤링 부하 104건 전부 정상, 최대 0.27초, 접속 중단 0.
  • 지식그래프 서버 조회: 이웃 조회 약 60배 빨라짐(9.5초→0.15초).
  • DB 무중단 재시작: 재시작 중 읽기/쓰기 오류 0건.
  • 백업 복원 리허설 통과 · 코드 모듈화 완료·적용.
  • 다중 데이터소스·보안 강화·그룹 대화·정확도 수단 개발 완료.

발전 과제 앞으로 더 키울 영역

  • 정확도 향상 수치 — 측정 수단 확보 완료, 다음 기간에 향상폭 제시.
  • 그래프 화면 속도 — 개선 설계 반영, 실측으로 확인.
  • 일부 기능 라이브 확대 적용(무중단 보조·6월 전반 기능).
  • 실제 화면 시각검증·자동 롤백 — 검증으로 완성도 강화.
보고 원칙 — 성과는 검증된 것만 수치로, 발전 과제는 성장 로드맵으로 제시합니다. 과장 없이, 앞으로 더 나아질 방향을 분명히 합니다.
