개발 배경 · 왜 이 일을 했나

"보고 싶은 데이터는 많은데, 안전하게·정확하게·안 끊기게가 어렵다"

상황

  • SQL을 모르는 현업도 데이터를 직접 보고 싶어 함 → 자연어 어시스턴트 도입.
  • 대상 데이터가 MySQL 한 종류, 웹은 단일 인스턴스였음.
  • 메타데이터(테이블·컬럼 뜻)가 평면 목록 — 대규모 스키마(수천 테이블) 탐색이 어려움.

문제

  • 배포할 때마다 화면이 잠깐 끊김(502) — 주 채팅까지 영향.
  • 계정 보호(2단계 인증)·프롬프트 악용 방어·기록 변조 방지 등 운영 신뢰 요소 미흡.
  • 답의 정확도를 측정·개선할 수단과, 여러 DB·회사 용어를 이해할 근거가 부족.
그래서 이번 기간의 목표 — (1) 배포·재시작에도 안 끊기게, (2) 더 많은 데이터(＋MSSQL)를 더 정확하게, (3) 안전하게·함께 쓰고 운영자가 관제할 수 있게. 아래는 사용자가 화면을 만나는 순서로 설명합니다.

1. 안전하게 접속·인증 신규

"들어오는 문"을 신뢰할 수 있게 만들었습니다

1배경·문제

사내 접속 시 인증서 경고가 뜨고, 로그인은 아이디·비밀번호 단일 인증이라 계정 도용·무차별 시도에 취약했습니다.

2화면 흐름
주소 접속(https)›로그인›2단계 인증(선택)›작업 화면

첫 접속 시 사내 인증서를 원클릭으로 신뢰 등록 → 이후 경고 없음.

변경 전

단일 웹 진입(경고 있음) · ID/PW 단일 인증 · 로그인 무제한 시도.

변경 후

사내 자체 인증서 HTTPS(경고 제거) · 2단계 인증(TOTP) · 로그인 시도 제한/계정 잠금 · 프롬프트 악용 방어.

◐ 실측 화면 미확보(도식 재구성)
4왜 이 방향

보안·신뢰가 도입의 전제. 표준(TOTP·자체 CA)을 택해 추가 비용 없이 사내 환경에 맞췄고, 2단계 인증은 사용자가 스스로 등록(운영 부담 최소)하도록 했습니다.

5기대 효과 효과 확인필요

계정 도용·무차별 로그인 위험 감소, 접속 신뢰 확보. 기능 개발·머지는 확인(E-004·E-005) — 재발방지 실효·라이브 적용은 운영 확인 필요(U-005).

2. 물어보고 답 받고 다듬기 (작업 화면) 신규

답을 "받는" 데서 "함께 다듬는" 화면으로

1배경·문제

답변·첨부 SQL을 고쳐 달라고 하면 무엇이 바뀌었는지 알기 어려웠고, 큰 결과는 화면을 무겁게 했으며, 처리 중 조작이 애매했습니다.

2화면 흐름
질문›진행(전송↔중단)›표 답변(인라인 로더)›변경점 비교(diff)›첨부 새 버전
변경 전

변경점을 글로만 설명 · "전체 N행" 별도 화면 · 처리 중 상태 모호 · 첨부 수정 이력 불명.

변경 후

답변에 +/− 색 diff 블록(줄번호, 복사 시 마커 제외) · 인라인 표 로더·접기/펼침 · 전송→중단 버튼 모핑 · 첨부 버전 배지.

◐ 실측 화면 미확보(도식 재구성)
4왜 이 방향

사용자 영향 우선 — 검토 신뢰(무엇이 바뀌었나)와 조작감. 기존 채팅 UI와 호환되게 얹어 학습 부담을 줄였습니다.

5기대 효과 개발 확인

검토 시간 단축·오해 감소, 첨부 반복 수정 추적. 개발·머지 확인(E-007). 사용자 체감 개선폭은 실사용 관찰 권장.

3. 더 정확한 답 (NL→SQL 정확도) 신규

"잘 나온 답"이 다음 답을 더 정확하게 만드는 선순환

1배경·문제

정확도를 측정할 수단이 없고, AI가 회사 고유 용어·코드값(예: 상태 1=결제완료)을 몰라 오답 여지가 있었습니다.

2선순환 흐름
질문·답변›좋은 답 등록›관리자 검수›참고 예시(KB)›정확도↑

＋ 회사 용어/코드값 사전, 벡터＋키워드 혼합 검색.

변경 전

정확도 측정 없음 · 자동 학습 없음 · 회사 용어 미반영.

변경 후

정확도 평가 도구 · 좋은 답 검수 후 환류(flywheel) · 용어/ENUM 사전 · 자가수정 루프 · 혼합 검색.

◐ 실측 화면 미확보(도식 재구성)
4왜 이 방향

측정 선행 — 개선을 증명할 잣대부터. 자동 학습이 아니라 사람 검수를 거쳐(데이터 오염 방지) 안전하게 정확도를 올립니다.

5기대 효과 수치 확인필요

답변 정확도 향상 기대. 수단 도입은 확인(E-003) — 단, "정확도 X%→Y%" 수치는 아직 미측정(U-006). 목표치로만 언급.

4. 더 많은 데이터 (멀티 데이터소스) 신규

MySQL 전용에서 여러 데이터베이스 분석 플랫폼으로

1배경·문제

대상이 MySQL 한 종류였고, 접속 정보 관리·접근 통제가 미흡했습니다. 현업 데이터는 MSSQL에도 있습니다.

2접근 구조
제품›데이터소스(MySQL·MSSQL)›허용 DB 목록›조회

바인딩 없으면 접근 0 — 기본이 "차단".

변경 전

MySQL 단일 · 접속정보 관리 취약 · DB 단위 통제 없음.

변경 후

MySQL＋MSSQL · 데이터소스 레지스트리(자격증명 암호화) · DB 단위 화이트리스트 · 연결 상태 정상/불안정/끊김 표시·격리.

◐ 실측 화면 미확보(도식 재구성)
4왜 이 방향

보안·안정성 우선(기본 차단·엔진별 가드·불안정 DB 격리) + 운영 편의(관리 콘솔에서 추가·연결 테스트).

5기대 효과 개발 확인

분석 대상 확대·안전한 다중 연결. 개발·머지 확인(E-002). 각 엔진 라이브 운영 효과는 운영 확인 권장(U-005).

5. 함께 쓰기 (그룹 대화) 신규

데이터 점검을 "여럿이 한 대화"에서

1배경·문제

데이터 점검은 혼자보다 함께가 많은데, 대화는 1:1 뿐이었습니다. 공유 시 권한·읽음 표시가 애매했습니다.

2화면 흐름
공유 링크 초대›사람끼리 의논›@어시스턴트 멘션›AI 응답(요청자 권한)
변경 전

1:1 대화만 · 협업·멘션·읽음 표시 없음.

변경 후

멤버십·발신자 표시 · @멘션한 글에만 AI 응답 · 열람과 발화 권한 분리 · 실시간 알림·피멘션 하이라이트.

◐ 실측 화면 미확보(도식 재구성)
4왜 이 방향

사용자 영향＋보안 — "열람은 되지만 발화(조회)는 권한 있는 사람만". 단일 권한 대신 세분 권한으로 실제 협업 요구에 맞췄습니다. (설계 과정은 개발 기록 기준 — U-007)

5기대 효과 개발 확인

협업 점검·지식 공유. 개발·머지 확인(E-006). AI 조회는 항상 요청 본인 권한으로만 — 권한 확장 없음.

6. 운영·관제 강화 + 메타데이터 지식그래프 신규

운영자가 "한눈에 보고 통제"하고, 대규모 스키마를 그래프로 탐색

1배경·문제

사용량·AI 동작·권한을 한눈에 볼 화면이 부족했고, 수천 개 테이블을 평면 목록으로 탐색하기 어려웠습니다.

2관리 콘솔 영역
LLM 사용량AI 운영 현황권한 편집기사용량 한도지식그래프

감사 기록 변조 방지(해시 체인) 포함.

변경 전

사용량 가시성 낮음 · 권한 설정 복잡 · 메타데이터 평면 목록(관계 안 보임).

변경 후

사용량 대시보드(비용·모델·drill-down) · AI 운영 현황 패널 · 권한 단계적 노출 편집기 · 지식그래프(관계 탐색·능동 분석).

◐ 실측 화면 미확보(도식 재구성)
4왜 이 방향

운영 편의·안전 — 그래프 DB(표준 Cypher)로 관계를 다루고, FK가 없어도 관계를 추론하되 추정/신뢰를 구분 표시(과대표현 방지).

5기대 효과 일부 확인

운영 가시성↑·대규모 스키마 탐색. 지식그래프 배포·서버 조회 60배 개선 확인(E-010). 단 화면 렌더 속도(FPS)·시각 검증은 확인필요(U-003·U-002).

7. 끊김 없는 서비스 (안정성·인프라) 완료·일부 배포대기

배포하고 재시작해도, 사용자는 끊김을 느끼지 않게

1배경·문제

배포할 때마다 화면 끊김(502)이 났고, 재시작 시 진행 중 작업이 중단됐으며, 거대한 단일 코드 파일은 유지보수가 어려웠습니다.

2무중단 처리
2대 웹(A·B)›한 대씩 교체›최소 1대 정상 보장›무중단

＋ 질문은 "작업 대기열"에 넣어 재배포에도 생존.

변경 전

단일 웹(배포 시 502) · 재시작 시 작업 중단 · 29,000줄 단일 파일.

변경 후

2-replica 롤링 배포(무중단) · 재시작 우아한 종료·DB 무중단 재시작 · 코드 21개 모듈로 분할.

◐ 인프라 영역(도식 재구성)
4왜 이 방향

안정성·운영편의 — 표준 로드밸런서로 간결하게. 코드 분할은 겉보기 동작을 바꾸지 않는(byte-동치) 방식으로 안전하게 진행.

5기대 효과 배포·실증 확인

배포 중 중단 0 실증(부하 104건 200 OK, E-011)·라우터 배포 완료(E-012). 자동롤백·일부 보조기능(백업 cron)은 확인필요(U-004·U-001).

기대 효과 · 성과 종합

확인된 성과와, 아직 "확인 필요"한 것을 나눠서

확인 근거 있는 성과

  • 무중단 배포: 롤링 부하 104건 전부 정상, 최대 0.27초, 502 = 0. (E-011)
  • 지식그래프 서버 조회: 이웃 조회 약 60배 빨라짐(9.5초→0.15초). (E-010, 서버 실측)
  • DB 무중단 재시작: 재시작 중 읽기/쓰기 오류 0건. (E-014)
  • 백업 복원 리허설 통과 · 코드 모듈화(29K→18.9K줄) 배포. (E-015·E-012)
