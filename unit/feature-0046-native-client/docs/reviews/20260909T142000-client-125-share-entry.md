## 조치하지 않고 남긴 것 (근거)

- **L4 (sec) — `ca_sha256` 이 비면 사설 CA 를 평문 HTTP 로 무검증 설치**(`core.py:1050`).
  이 diff 밖의 **선재** 결함이고, fail-closed 로 바꾸면 신규 머신의 첫 연결 동선이 바뀐다 —
  버전 올리기 cycle 에서 함께 넣을 변경이 아니다. 별도 cycle 로 이연한다.
- **MED-3 (be) — 매니페스트/실물 불일치의 진단 표면 0**(5가지 원인이 모두 `return None` → 404).
  같은 이유로 이연. 클라이언트가 404 를 「아직 배포 없음」으로 읽는 것과 짝이라 양쪽을
  함께 바꿔야 하고, 그것은 이 cycle 의 범위가 아니다.
- **L2·L3·L6 (be) — `--prune` 미실행(174MB) · `os.replace` 의 디렉토리 fsync 부재 ·
  `.worktrees/artifacts` 심볼릭 링크의 출처 불명.** 앞의 둘은 운영 위생, 셋째는 H1 조치로
  기본 경로에서 도달 불가가 됐다(명시 `--dir` 만 남음).
- **LOW-3 (qa) — worktree 의 `dist/` 102MB root 소유 잔재.** cycle 마무리에서 제거한다.
- **미검증 5종**(설치본·OS 스킴 발사·브라우저 버튼 종단·창 실제 표시·`show.path` 권한)은
  Run 4·6 의 「확인하지 않은 것」에 그대로 적었다.

## 이 라운드가 남기는 관찰

- **세 reviewer 가 서로 다른 축에서 같은 결론에 닿았다**: 「초록인데 아무도 안 보고 있던
  단정」이 이 저장소에 **3건**(L1 · L2 · FUNCTION.md 문장) 있었다. 두 건은 항진명제이고
  한 건은 봉인 자체가 없었다.
- **qa 가 지적한 §16.6 위반이 이 라운드의 핵심이다.** 내가 조립한 정상 입력으로 여섯 칸을
  채우고 「전건 통과」를 적었는데, 상류가 실제로 만드는 입력은 검증 지점을 **하나 더** 지난다.
  그 하나가 바로 1R-F3 이 만든 토큰 배제 분기였다 — 즉 **가장 최근에 추가한 방어가 실행으로
  확인되지 않은 유일한 것**이었다.
