# 발표 스크립트 — DBA AI Assistant 개발 진척 보고 (2026-06-17 ~ 2026-07-22) · v1

> 동반 자료: [`deck.html`](./deck.html) (14 슬라이드, 자기완결 offline). 근거: [`EVIDENCE.md`](./EVIDENCE.md).
> **발표 원칙(정직성)**: "개발 완료"와 "라이브 검증/효과 실측"을 구분한다. 확인필요 항목은 "완료/검증"으로 단정하지 말고
> "개발 완료 · 효과/실화면은 다음 기간 측정" 으로 말한다. 청중 슬라이드에는 내부 식별자·근거 코드를 노출하지 않는다
> (근거 코드·확인필요 색인은 본 문서 §발표자 전용 Q&A 와 EVIDENCE.md 에만).

## 발표 개요

- **대상 청중**: 기획·운영·관리(비전문가 포함) + 개발. 데이터베이스·AI 세부 용어를 몰라도 이해되도록 업무 언어로.
- **소요**: 압축 8~10분 / 풀 18~22분.
- **핵심 메시지 (1문장)**: "직전 기간이 개별 대화 화면을 다듬는 시기였다면, 이번 약 5주는 **협업·신뢰·지도·운영**이 붙어 **플랫폼으로 도약**한 시기 — 핵심은 라이브 검증까지 마쳤고, 남은 것은 정직하게 '발전 과제'로 구분해 보고한다."
- **두 경로**:
  - **압축 발표**: 슬라이드 0→1(요약)→2(배경)→3(개요)→ 헤드라인 2장(4 대화편집 · 8 관계도) → 11(성과)→12(발전과제)→13(마무리).
  - **풀 발표**: 0~13 전부.
- **전환 장치**: →/Space(다음), ←(이전), 상단 '목차'(☰) 또는 Esc(목차 열고닫기), 주소 끝 `#feat-graph` 식으로 특정 장 직행.

## 구간별 스크립트

### 슬라이드 0 · 표지
- **화면**: 제목, 기간(6/17~7/22), 직전 대비(5/19~6/17), 버전 v1, 배지 범례(신규/이어받음/완료/검증됨/발전예정).
- **대사**: "지난 약 5주간 DBA AI 어시스턴트의 개발 진척을 보고드립니다. **직전 등길이 기간(5/19~6/17)과 비교**하며, 각 항목이 새로 시작한 것인지·이어온 것인지·마감한 것인지를 배지로 함께 표시합니다. 무엇보다 **검증된 성과와 앞으로 더 키울 과제를 구분**해 과장 없이 말씀드리겠습니다."
- **전환**: "먼저 결론부터."

### 슬라이드 1 · 핵심 요약 (BLUF)
- **화면**: "개별 대화 다듬기 → 협업·신뢰·지도·운영 플랫폼" + KPI 4개.
- **대사**: "한 줄 결론 — **직전엔 개별 대화 화면을 다듬었고, 이번엔 플랫폼의 격을 올렸습니다.** 진척한 기능 영역이 직전 8개에서 **18개**로 늘었고, 개발 작업 단위 **229건**이 반영됐습니다. 데이터베이스 지도에는 테이블·함수 등 **23,465개** 객체가 자동으로 담기고 묶였으며, 배포 중 접속 중단은 **0회**입니다."
- **정직 문구**: "KPI 중 '18개 영역'과 '중단 0회'는 **검증된** 수치이고, '229건'은 **개발 이력 집계**(산식이 있습니다), '23,465개'는 **서버측 적재** 수치입니다 — 화면 체감이 아니라 담긴 양입니다."
- **전환**: "왜 이 일들을 했는지 배경부터."

### 슬라이드 2 · 개발 배경 (SCQA)
- **화면**: 상황(직전까지 개별 대화 다듬기) → 문제(고칠 수 없음·검증 없음·전체 노출·평면 목록·뒤쪽 끊김) → 목표.
- **대사**: "직전 기간까지 우리는 **혼자, 한 대화**를 잘 쓰는 데 집중했습니다. 그런데 실제로 쓰다 보니 — 보낸 말을 **못 고치고**, 답변이 근거에 맞는지 **스스로 점검하지 않고**, 공유하면 **전부 노출**되고, 수천 테이블은 **평면 목록**이라 관계 파악이 어렵고, 재배포 때 **뒤쪽이 끊길** 수 있었습니다. 그래서 이번엔 이 일곱 가지를 풀었습니다."
- **전환**: "사용자가 화면을 만나는 순서로 보겠습니다."

### 슬라이드 3 · 이번 기간 개요
- **화면**: 7가지 변화 목록 + 상태 배지.
- **대사**: "대화를 **편집·조율**하고, 답변을 **스스로 검증**하고, **안전하게 나눠** 보고, 지식이 **스스로 쌓이고**, 데이터베이스를 **지도로 탐색**하고, **AI를 관제**하고, **끊김 없이 배포**합니다. 배지를 보시면 1·2는 이번에 새로 시작한 축, 3~6은 지난 기간에서 이어받아 키운 축, 7은 이번에 마감한 기반입니다."
- **전환**: "첫 번째, 대화 편집부터."

### 슬라이드 4 · 대화를 편집하고 조율한다 (헤드라인)
- **화면**: 5블록 + 전/후 도식(수정 불가·한 갈래 → 수정·분기 재답변·버전 페이저).
- **대사**: "이번 기간의 첫 헤드라인은 **메시지 편집**입니다. 이제 보낸 말에 마우스를 올려 **수정**할 수 있습니다. 1:1 대화에서는 단순히 고치거나, **요청을 바꿔 다시 답변**받을 수 있는데, 이때 이전 답변이 사라지지 않고 **‹1/2› 버전으로 남아 비교**됩니다. 여기에 생각 깊이 4단계 선택, 진행 상황 실시간 표시, 지연 시 화면을 막지 않는 조용한 자동 재연결까지 더했습니다."
- **왜/효과**: "대화를 통째로 새로 만들지 않고 **대화 안에서 가지를 치는** 방식이라 깔끔하고, 가지가 없는 대화는 **기존과 똑같이** 동작합니다. 그룹·공유 대화는 답변 근거 보호를 위해 단순 수정만 허용합니다. **1:1·그룹 모두 실 화면 검증을 통과**했고, 적대적 보안 리뷰로 결함 3건을 미리 잡아 봉인했습니다."
- **정직 문구**: "다만 그룹 편집의 세부 보안 동작(잠금·권한 격리)은 코드 검토로는 문제없음을 확인했고, **실화면 재확인은 예정**입니다."
- **전환**: "두 번째, 답변을 스스로 검증합니다."

### 슬라이드 5 · 답변을 스스로 검증한다 (헤드라인 · 신뢰)
- **화면**: 5블록 + 전/후 도식(무검증·과단정 → 자가 5축 검증·첨부 코드대조).
- **대사**: "두 번째 헤드라인은 **답변 자가검증**입니다. 이제 AI는 답을 내기 전에, 초안을 만든 맥락과 **분리된 별도 리뷰어**가 다섯 가지 축 — 근거 정합·SQL 정확성·권한/정보누출·완전성·정직성 — 으로 **스스로를 비판**하고, 문제가 있으면 고쳐서 전달합니다. 특히 **첨부파일 검증**에서, 예전에는 일부만 본 결과를 전부로 단정해 실재하는 항목을 '누락'이라 잘못 말하는 환각이 있었는데, 이제 **코드가 대소문자까지 직접 대조**해 그 오류를 막습니다."
- **왜/효과**: "검증은 답을 막는 관문이 아니라 **품질을 높이는 계층**입니다 — 문제가 있어도 최소한 답은 나옵니다. 그리고 근거를 못 대면 지어내지 말고 **'미확인'이라고 정직하게** 말하도록 계약했습니다. 개발과 배포는 마쳤습니다."
- **정직 문구**: "**중요한 구분** — 이 기능이 '라이브에서 결함을 실제로 잘 잡는가', '환각이 정말 줄었는가'는 **아직 수치로 측정하지 않았습니다.** 다음 기간에 실제 대화를 감사해 확인하겠습니다. 오늘은 '개발·배포 완료'까지입니다."
- **전환**: "세 번째, 안전한 공유입니다."

### 슬라이드 6 · 안전하게 나눠 본다
- **화면**: 5블록 + 전/후 도식(전체 노출 → 창만·물리 배제).
- **대사**: "대화를 공유할 때 예전엔 처음부터 끝까지 전부 보였습니다. 이제 말풍선 메뉴에서 **'여기부터/여기까지'** 범위만 공유합니다. 핵심은 — 가린 구간을 화면에서 숨기는 데 그치지 않고 **AI가 읽는 데이터 자체에서 빼버렸다**는 점입니다. 없는 것은 아무리 캐물어도 나오지 않습니다."
- **정직 문구**: "기능과 보안은 개발 완료이고, 적대적 리뷰로 초기 누출 1건을 찾아 봉인했습니다. **실 화면 시각검증은 배포 후 예정**입니다."
- **전환**: "네 번째, 스스로 쌓이는 지식."

### 슬라이드 7 · 스스로 똑똑해지는 지식
- **화면**: 5블록 + 전/후 도식(전수 수동 → 채택 인박스·자동/검토 게이트).
- **대사**: "회사 고유 용어, 코드값(예: 상태 1은 결제완료), 그리고 제품 분류를 예전엔 사람이 일일이 등록했습니다. 이제 AI가 대화와 분석에서 **후보를 제안**하고, 신뢰도가 높으면 자동 등록, 낮으면 검토 큐로 모아 관리자가 **한곳에서 승인**합니다. 제품 분류는 AI가 **제안까지만** 하고, 접근 경계에 영향을 주는 **최종 승인은 사람이** 합니다."
- **정직 문구**: "지식은 답변에 직접 쓰이므로 원래 자동 학습을 막아왔는데, 전수 기록·되돌리기·사람 검토를 붙여 안전하게 열었습니다. 제품 분류 제안은 라이브 실증, 용어 사전은 실화면 검증 통과, 코드값·채택 인박스 실화면은 배포 후 예정입니다."
- **전환**: "다섯 번째, 이번 기간 가장 큰 화면 변화 — 데이터베이스 지도."

### 슬라이드 8 · 데이터베이스를 지도로 (헤드라인 · 렌더 엔진 교체)
- **화면**: 5블록 + 전/후 도식(팬 버벅임/톱니 → GPU 상주/매끄러움).
- **대사**: "운영 데이터베이스는 테이블이 수천 개인데 예전엔 평면 목록이었습니다. 지난 기간에 관계·역할이 보이는 **대화형 지도**를 만들었는데, 노드가 많아지자 **화면 이동이 계속 버벅여** 사용자가 반복해서 신고했습니다. 이번에 **렌더 엔진을 전면 교체**했습니다 — 화면을 **GPU에 상주**시키는 방식으로요."
- **왜/효과**: "무거운 게임 엔진으로 갈아탈지도 검토했지만, 성능 이득의 원천은 'GPU 상주'라는 **웹 표준 방식으로도 얻을 수 있어** 그쪽을 택했습니다. **보이는 화면은 그대로** 유지하는 계약 아래 옮겼고, 비상 시 옛 엔진으로 되돌릴 안전장치도 남겼습니다. 여기에 컨텐츠 군집·검색 강화까지 더했습니다."
- **정직 문구(중요)**: "성과를 정확히 — **실 화면에서 60fps를 검증한 규모는 약 400개 노드 수준**입니다. 정작 문제였던 **수천 테이블 대규모에서의 실 체감은 아직 라이브로 확증하지 못했습니다.** '60fps'는 이 중간 규모의 실측치이고, 대규모 체감은 다음 기간 과제입니다. '23,465개 적재'는 화면 속도가 아니라 서버에 담긴 양입니다."
- **전환**: "여섯 번째, 운영자 화면 — AI 관제와 콘솔 정돈."

### 슬라이드 9 · AI 관제·콘솔
- **화면**: 5블록 + 전/후 도식(흩어짐·혼재·평면권한 → 운영현황·서브탭·권한계층).
- **대사**: "운영자를 위해 **AI 운영 현황** 한 화면을 만들었습니다 — 상태·비용·지연·활동을 모아 보고, 활동을 클릭하면 어떤 모델이 얼마의 비용과 지연으로 처리했는지, 어느 대화였는지까지 이어집니다. 관리 콘솔도 **관측용과 설정용을 성격대로 분리**하고 유사 탭을 서브탭으로 묶었으며, 권한은 **화면 구조와 정합하는 계층** + 등록·수정·삭제 같은 실제 액션 단위로 나눴습니다."
- **정직 문구**: "지연은 '답변 전체 시간' 대신 **'단계 사이 간격'**으로 재정의해 진짜 신호를 봅니다. 콘솔 정보구조·권한 계층은 실화면 검증을 통과했고, **패널 실화면과 재정의한 지연 지표는 배포 후 실트래픽으로 확인 예정**입니다."
- **전환**: "마지막 축 — 이 모든 게 끊김 없이 돌게 하는 기반."

### 슬라이드 10 · 끊김 없는 기반
- **화면**: 5블록 + 전/후 도식(웹만 무중단 → 웹+워커+게이트웨이+엣지 무중단 + AI 격리 공간).
- **대사**: "지난 기간엔 **웹 화면만** 무중단이었는데, 이번에 **워커(응답·분석 처리기)·AI 게이트웨이·엣지까지** 모두 무중단으로 확장했습니다. 문제가 생기면 **직전 정상본으로 복귀**합니다. 또 AI가 여러 데이터를 모아 분석할 **전용 격리 공간**을 별도 데이터베이스로 만들어, 사고가 나도 운영 데이터에 닿지 않고 대화별로 나뉘며 자동 정리됩니다. 거대한 코드 한 파일도 **21개 모듈로 정리**(겉보기 동작 그대로)하고, AI가 코드를 스스로 찾는 지도를 붙였습니다."

## 발표자 전용 Q&A 대비 (청중 비노출)

> 아래는 발표자만 본다. 청중 슬라이드에는 내부 식별자·근거 코드가 없다. 공격적 질문에 근거로 방어하되, 확인/확인필요를 정직히 구분한다. 상세 근거는 EVIDENCE.md 참조.

**Q. "23,465개"·"18개"·"229건"·"60fps"는 믿을 수 있나?**
- 18개 = 범위 커밋의 고유 기능 영역(feature-id) 토큰 집계 — 검증 가능(git 재현). 활동 강도가 아니라 영역 수임(활동은 관계도에 집중).
- 229건 = 커밋 메시지의 고유 작업(TASK) 토큰 수 — **개발 이력 집계**(검증됨 아님). 반영 PR 은 521건. 직전 기간(159)과는 범위 길이가 달라(2주 더 김) 직접 비교 금지.
- 23,465개 / 군집 3,652 = content-cluster 배포 후 **서버측 파이프라인** 집계(테이블·컬럼·함수·프로시저 통합) + 밴드 렌더 실 Windows 검증. (E-000c)
- 60fps / p95 16.8ms = **실 Windows Chrome, 약 409개 객체 규모** 실측. 11k/수천배 등 다른 수치는 headless 실험치이니 혼용 금지. (E-012, U-016)

**Q. "무중단 0회"는 프로덕션 SLA 인가?**
- 아니다. **단일 호스트·라이브 사용자 1명 조건의 부하 시험**(웹 롤링 104/104 정상·PG 재시작 RW 134/0). deploy-all 확장은 배포 exit0·healthy 확인. **워커 자동 롤백은 미실증**(첫 배포 last-good 부재, POST-DEPLOY attended). (E-000d/E-017, U-014)

**Q. 답변 자가검증이 실제로 효과가 있나?**
- 개발·배포·테스트(34 PASS)·적대 리뷰까지 확인. **단 리뷰어의 실판정 품질·환각 실감소는 미측정** — 다음 대화 감사로 실측 예정. 오늘은 "효과 실측 전"으로 정직히. (E-005/E-006, U-013)

**Q. 렌더 엔진 왜 바꿨나, 게임 엔진은?**
- 이전 엔진은 화면 안 도형을 매 프레임 CPU 재래스터 → 대규모 팬이 구조적으로 60fps 불가. 게임 엔진은 이득 원천(GPU 상주)이 웹 표준으로도 얻어지는데 수십 MB 번들·별도 툴체인·접근성/검증 파이프라인 부정합 등 부담만 커 기각. 결정 기록은 내부 설계 문서(BLUEPRINT/REPORT)에 있음(번호 ADR 없음). (E-012, C-2)

**Q. 메시지 편집 그룹 대화 보안은?**
- 그룹/공유는 단순 수정만 허용, @assistant 호출 메시지 편집 잠금·per-message 권한 격리(IDOR 방지). **코드 보안리뷰로 결함 없음 확인, 단 그 동작 자체의 실화면 검증 기록은 없음** — 재확인 예정. 적대 리뷰 3 MAJOR 봉인. (E-002, U-011)

**Q. 권한 체계를 크게 바꿨는데 회귀는?**
- 원자 단위 분리는 UI 뿐 아니라 백엔드 권한 집행까지 전환한 Critical 변경. **부작용 회귀 1건**(작업화면 '연결 테스트' 버튼 미표시) 발생 → 이틀 뒤 복구(표시 계층만, 보안 불변). 정직하게 공개. (E-015, C-5)

**Q. 릴리즈노트에 다 있나?**
