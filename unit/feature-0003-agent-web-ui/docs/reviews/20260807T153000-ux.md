# [SUBAGENT:ux] — 그룹 대화 첫 사용 안내 툴팁 (gc-first-use-guide)

Trigger: UI/screen/layout · 화면 (§18.8 dispatch 표 3행)
Context bundle: changed_files + diff_excerpt(index.html / chat.css / composer.js) +
task_md_content(TASK-20260807T1500 + feature-0009 FUNCTION 계약 요약) + acceptance_criteria(AC-1~6).

## 1. Findings

### BLOCKING

**B1 — 첫 타건이 안내를 영구 소진, 재진입 경로 없음.**
`composer.js` `_wireGroupFirstUseGuide` 의 `promptInputEl` input 리스너가
`hideGroupFirstUseGuide()` 를 부르고 그 함수가 무조건 `_gcGuideMarkSeen()` 한다.
시나리오: 공유 링크로 갓 참여한 멤버가 안내가 뜬 순간 반사적으로 "안녕하세요" 를 입력 →
첫 글자에서 카드가 사라지고 username 이 localStorage 에 기록 → 5줄 중 한 줄도 못 읽었는데
안내를 다시 여는 경로가 앱에 없어 **영구 복구 불가**. 그 계정은 `@assistant` 규약을 모른 채
멘션 없는 메시지를 보내고 "AI가 답을 안 한다" 로 이탈한다.

**B2 — 발화 가능 상태를 보지 않아 안내가 거짓이 될 수 있음.**
게이트가 "그룹인가 / 이미 봤나" 둘뿐이다. `conversation.ask` 권한이 없거나 대화가
`blocked`(참조 제품 삭제) 인 계정이 그룹 대화를 처음 열면 "@assistant 를 붙이면 AI가
답해요" 라는 **지금 자기에겐 거짓인 안내**로 유일한 1회 기회를 소비한다.

### MAJOR

**M1 — 스크린리더에 통지되지 않음.** `role="note"` 는 라이브 리전이 아니고 포커스도
이동하지 않는다. `display:none → 표시` 전환이 SR 에 아무것도 읽히지 않아 SR 사용자의
온보딩 도달률이 0 이며, 그대로 B1 경로로 소진된다.

**M2 — document 전역 Escape 가 무관한 조작에서 안내를 소진.** 같은 컴포저의 @멘션
자동완성·`+` 드롭업을 Esc 로 닫으면 그 Esc 가 안내까지 영구 소진한다. 사용자 의도는
"메뉴 닫기" 였다.

**M3 — 첨부 안내가 LLM 주입 계약과 어긋남.** "첨부파일은 멤버 모두가 봅니다" 는 열람
계약(REQ-GC-R6 전반부)만 말한다. LLM 주입은 **발신자 본인 첨부 한정**(F1)이므로, B가 올린
파일을 A가 "@assistant 요약해줘" 하면 assistant 가 못 본다 → 사용자는 제품 버그로 인식.

**M4 — `state.user` 미준비 시 fail-closed 로 첫 순간을 놓칠 수 있음.**
`_gcGuideAlreadySeen()` 이 키 부재를 "이미 봤음" 으로 반환한다. 재평가가 보장되지 않으면
AC-1 이 조용히 실패한다.

### MINOR
- m1 같은 relative 컨테이너의 다른 오버레이(드롭업·자동완성)와 스택/가림 미검증.
- m2 `bottom: calc(100% - 4px)` 라 caret 이 `.composer-wrap` 최상단(=배너)을 가리킨다.
- m3 "확인" 이 영구성을 전달하지 않는다(실제 의미는 "다시 안 보기").
- m4 `@이름` 줄이 바로 윗줄(`@assistant` → AI 응답)과 대비되지 않아 실행으로 오해된다.

### NIT
`--primary` 만 폴백 부재 · 멀티탭 `storage` 미구독 · 50계정 LRU 초과 시 재출현 ·
소진 후에도 리스너 상주.

## 4. Disposition (main session 반영 결과)
- **B1 수용** — 닫기와 소진을 분리. "다시 안 보기" 클릭만 영구 소진, 입력/Esc 는
  `_gcGuideDismissedThisLoad` 로 **이 로드에서만** 숨김 → 다음 방문에 다시 뜬다.
  하네스 `[임시닫기]` 4건이 경계 양측을 단정(뮤테이션 M1 이 red 로 검출).
- **B2 수용** — `speakable = can("conversation.ask") && !conv.blocked` 게이트 추가.
  발화 불가 상태에서는 표시도 소진도 없음. 하네스 `[게이트]` 5건(뮤테이션 M2 red).
- **M1 수용** — `aria-live="polite"` 추가. 포커스 이동은 채택하지 않음: 비차단 툴팁에서
  포커스를 뺏으면 "팝업 금지" 요구(사용자 결정)와 상충한다.
- **M2 수용** — Esc 핸들러가 `_gcGuideOtherOverlayOpen()`(멘션 AC·액션/모델/추론/제품
  드롭업 5종)이면 양보하고, 처리하더라도 소진하지 않는다. 하네스 `[Esc 양보]` 5건(뮤테이션 M3 red).
- **M3 수용** — 문구를 `첨부는 전원 공유, AI엔 내 것만`(19자)로 교체. 하네스가 F1 계약
  대비 오도 여부를 단정.
- **M4 부분 수용(설계 유지, 근거 명시)** — 키 부재는 계속 "노출 보류" 다. `renderComposer`
  는 `refreshWorkspace`·`selectConversation`·폴링이 모두 지나는 choke-point 라 세션이
  붙은 뒤 반드시 재평가되며, 하네스 `[지연] 세션 확정 후 정상 노출` 이 그 경로를 단정한다.
  반대 방향(익명 키 소진)은 복구 불가라 fail-safe 방향이 이쪽이다.
- **m2·m3·m4 수용** — 앵커 `calc(100% + 6px)`(카드+caret 전체가 wrap 밖) · 라벨
  `다시 안 보기` + `title` · `@이름 은 알림만, AI 미호출`(17자).
- **m1 수용(스택)** — z-index 40 으로 낮춰 `.mention-ac`(50)·`.chat-drop-overlay`(50)
  아래. 최신 메시지 가림은 남지만 **입력 시작 즉시 걷히고** 백드롭이 없어 조작은 차단되지
  않는다(AC-6). 완전 무가림은 컴포저 위 툴팁이라는 요구와 양립하지 않는다.
- **NIT 미반영(근거)** — `--primary` 는 `base.css:53` 에 항상 정의되며 폴백을 추가했다.
  멀티탭 동기화·LRU 초과는 발생 시 안내가 한 번 더 뜨는 것이 전부(무해 방향)라 복잡도를
  더하지 않는다. 리스너 상주는 요소당 1개 상한이 하네스로 고정돼 누수가 아니다.
