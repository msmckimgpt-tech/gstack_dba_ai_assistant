### Run (2026-09-07) — 칩 자리 — **Environment: Windows-browser (라이브, CDP 실측)**

배포본 `https://localhost` 에 수정 CSS 를 주입해 **실제 렌더 박스를 측정**했다. 소스 검사가
아니라 좌표다.

| 폭 | 계정 이름 | 상태 문구 | 같은 줄 | 잘림 | 클리핑 |
|---|---|---|---|---|---|
| 180 · 252 · 320 | `admin` · `bootstrap_admin` · `a_very_long_account_name_x` | `대기 중` · `업데이트 필요` | ✅ 전부 | 없음 | 없음 |

**수정 전 대조군**(같은 방법): 252px 에서 칩이 `x=8, y=860` — 계정 행(`bottom=856`) **아래
줄**. 사용자가 "계정 옆에 없다"고 한 그대로다. 스크린샷으로도 확인(사이드바 맨 아래 왼쪽
구석의 `● 대기 중`).

⚠ 중간에 칩을 줄어들게(`flex-shrink: 1`) 두었더니 **상태 낱말이 잘렸다**(`truncated: true`,
기본 252px 에서도). 되돌렸다 — 잘린 상태 칩은 상태를 알리는 일을 못 한다.

### Run (2026-09-07) — 자기 실행 승인창 — **Environment: host pytest + 뮤테이션**

- 원인 확정: `_maybeAutoEntry`(로그인 직후 자동 경로)에 `clientBridge` 가드 부재. 클릭
  경로에만 있었다.
- 스킴 발사를 `_fireScheme()` 한 곳으로 모으고 거기서 차단. `location.href` 가 파일 전체에
  **한 자리**임을 테스트가 잠근다.
- 뮤테이션 **4/4 KILL**: 가드 무력화 · 가드를 이동 뒤로 · 자동 진입 가드 제거 · 발사 지점 분산.
- 옮겨진 단정 2건(`window.location.href` 를 표식으로 쓰던)은 성질을 보존한 채 재조준했다.

### ⚠ 확정하지 못한 것

사용자 창에서 칩이 안 보인 원인이 **자리 때문인지 확정하지 못했다.** 그 창이 실행 중이라
WebView2 프로필(쿠키)이 잠겨 그 세션을 열 수 없었고, 재현은 **같은 배포본의 브라우저**에서만
했다. 자리 문제는 실측된 사실이고 그것을 고쳤다 — 배포 후 그 창에서 다시 본다.
