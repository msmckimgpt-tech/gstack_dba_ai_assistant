## 1. Findings

### P2 — 줄바꿈 계열 차이가 `identical` 에 흡수되는데, 이번 변경이 그 위에 더 강한 단정을 얹었다

서버는 `left_text.splitlines()` / `right_text.splitlines()` 로 비교한다. Python `splitlines()` 는
`\r\n`·`\r`·`\n` 을 같은 경계로 접고 종단자를 버린다:

```
'a\r\nb\r\n'.splitlines() → ['a', 'b']
'a\nb'.splitlines()       → ['a', 'b']
```

따라서 **CRLF↔LF 변환·후행 개행 추가/삭제만 있는 두 버전은 `identical=True`** 다. 종전 화면은
"두 버전의 내용이 동일합니다." 한 줄이었지만, 이번 변경은 "아래는 문서 원문(N줄)입니다" 를
덧붙이고 좌우를 직접 대조할 표현(2열 뷰)까지 화면에서 제거했다.

첨부 버전은 (a) 사용자 재업로드, (b) AI 수정 두 경로로 생긴다. AI 가 파일을 다시 써서 후행
개행이 붙거나 사용자가 Windows 에서 편집해 CRLF 로 재업로드하는 것은 흔하다. 목록에는 크기가
다른 두 버전이 남아 있는데 비교 화면은 "동일합니다" 라고 답한다 — CODE_REVIEW.md §1 의
"조용히 틀린 결과" 계열.

**판별 데이터는 이미 응답에 있다**: `_side()` 는 텍스트 경로에서도 `sha256` 을 싣고, 프론트는
바이너리 분기에서 이미 그 필드를 쓴다. 정보 부족이 아니라 미사용이다.

### P2 — 절단 상태에서 세 문구가 서로 모순되고, 이 조합은 이번 변경으로 **기본 경로**가 됐다

종전: identical + 기본 `context=3` → 파일 전체가 gap 1행 → `row_cap`(6000) 초과 불가.
이번 변경: identical 이면 항상 전량 방출 → **6,000줄 넘는 동일 텍스트는 기본 상태에서 절단**.

한 화면에 동시에 뜨는 문구:

| 위치 | 문구 |
|---|---|
| 절단 배너 | `차이가 많아 앞쪽 6000행만 표시했습니다.` |
| 안내 배너 | `두 버전의 내용이 동일합니다 — 아래는 문서 원문(20000줄)입니다.` |
| 요약 배지 | `차이 없음 — 원문 표시` |

"차이가 많아" ↔ "차이 없음" 은 정면 모순이고, "문서 원문(20000줄)" ↔ 실제 6,000행 표도 모순이다.
원본 1MB cap 절단도 같다 — 접두부만 같아도 `identical=True` 라 "동일합니다" 자체가 검증되지 않은
주장이 된다. 하네스 B8 은 배너 **존재**만 단언하고 문구를 보지 않는다.

### P2 — `syncDiffOnlyControls` 가 선언한 원칙을 4개 상태 중 1개에만 적용한다

주석은 "diff 가 있을 때만" 이라고 선언하는데 구현은 `identical` 만 본다:

| 상태 | 2열/단일열·맥락 토글 | 구문 색 토글 |
|---|---|---|
| 정상 diff | 표시 ✅ | 표시 ✅ |
| identical | 숨김 | 표시 |
| `comparable:false`(바이너리) | **표시** ❌ | 숨김 |
| `from===to` | **표시** ❌ | 숨김 |
| 조회 실패 | **표시** ❌ | 숨김 |

비교할 줄이 없는 세 화면에서 "좌우 2열/단일열" 과 "동일한 줄도 모두 보기" 가 살아 있고 눌러도
아무 일도 없다. 이 모듈이 스스로 "거짓 어포던스" 라 부르며 금지한 결함과 같은 결함이며, 그것을
봉인하려고 만든 함수가 재현했다. `syncDiffOnlyControls(null)` 이 `hide=false` 로 떨어지는 것도
사고로 보인다 — 같은 인자를 받는 `syncHlToggle(null)` 은 "숨김" 을 뜻하는데 이쪽은 "표시" 다.

### P3 — 컨트롤 숨김이 컨트롤 바를 흔든다 (상태 자체는 보존됨)

`mode`·`localStorage`·`ctxCb.checked` 는 wrapper 만 `hidden` 이 되므로 값이 유지된다 — 이 축은
문제없다. 남는 문제는 레이아웃이다. `.attach-diff-controls` 는 `flex-wrap`, `.attach-diff-stats`
는 `margin-left:auto` 라 토글 2개가 사라지면 우측 클러스터가 이동하고, 좁은 폭에서는 줄 수 자체가
바뀐다(본문 높이 점프). 또 모달을 처음 열 때 마크업에는 두 토글이 보이는 상태이고
`syncDiffOnlyControls` 는 응답 후에만 호출되므로 identical 기본 쌍에서 항상 깜빡인다.

### P3 — 원문 표에 스크린리더 맥락이 없다

`<table>` 에 accessible name 이 없고 줄번호 `<td>` 도 데이터 셀이다 — 매 행 "열1: 1247, 열2: 본문"
이 낭독된다. diff 표는 좌/우 대조라는 표 성격이 있어 정당하지만 원문 뷰는 성격상 문서다.

### P3 — 문서 사실 정확성

`FUNCTION.md` 의 선행 서술 "내용 동일이면 빈 표 대신 '두 버전의 내용이 동일합니다'" 가 그대로
남아 이번 계약과 충돌한다(AC-AVD-23 은 개정했으나 이 bullet 은 누락). `MODIFY.md` Files 목록이
아직 손대지 않은 문서를 포함한다.

## 2. Risks

- identical 이면 `rows` 가 각 줄을 `left`/`right` 두 벌로 싣는다 — "줄 수는 적고 줄이 긴" 파일
  (minify 된 `.json`/`.js`)에서 payload·렌더 비용이 종전 gap 1행 대비 크게 는다. 측정하지 않았다.
- 롤링 배포 창(web-a/web-b)에서 신 JS + 구 서버 조합이면 "원문(N줄)" 배너 밑에 gap 한 줄만 뜬다.
  A9 가 gap 을 표면화하므로 무음은 아니지만 배너 문구는 거짓이 된다.
- identical 인데 ctx 체크가 켜져 있으면 여전히 `context=full` 이 요청에 실린다(무해).

## 3. Recommendation

1. sha256 불일치를 배너·배지에 반영하고 등급을 warn 으로 (B9/B9b 테스트 동반).
2. 절단 문구를 상태에 맞게 분기하고, identical 배너는 절단 시 "원문" 대신 "앞부분 N줄" 로 약화.
3. `syncDiffOnlyControls` 의 판정면을 `syncHlToggle` 과 동일하게 맞추고 초기 호출 추가.
4. identical 화면에도 메타 요약(작성 주체·크기·시각·sha256)을 주는 것을 검토.
5. 원문 표 `aria-label` + 줄번호 `aria-hidden`.
6. FUNCTION.md 선행 bullet 개정 · MODIFY.md Files 목록 정정.

## 4. Verdict

**CONCERN** — 요청 자체는 서버·프론트 양쪽에서 정본 1곳으로 올바르게 구현됐고 `[hidden]` 트랩
적발은 순수 이득이지만, ① 줄바꿈 차이를 흡수한 `identical` 위에 더 강한 단정을 얹었고,
② 이번 변경으로 기본 경로가 된 절단 상태에서 세 문구가 서로 모순하며, ③ 거짓 어포던스를 막으려
만든 함수가 같은 컨트롤 바에 세 번째 가시성 규칙을 만들었다 — 셋 다 같은 cycle 에서 처리 가능.
