## 1. Findings (correctness)

- **litellm ollama embedding 문법 — CORRECT.** `model: ollama/bge-m3` +
  `api_base: http://ollama-edge:11434` 는 정확한 형식. litellm 의 ollama embedding
  provider 는 `{api_base}/api/embeddings` (native) 로 POST 하고 Ollama 의
  `embedding` 필드를 OpenAI `data[].embedding` shape 으로 변환 — 앱의
  `resp.data[0].embedding` (kb_retrieval.py:493-494) 및 worker (kb_embedding_worker.py)
  와 정합. `api_base` 에 `/v1` 등 trailing path 를 붙이면 오히려 깨짐. `ollama/` vs
  `ollama_chat/` 구분은 chat 전용 이슈라 embedding 에 무관 — `ollama/` 가 맞음.
  `drop_params`/`request_timeout` 은 embedding 호출에 무해.
- **라우팅 — CORRECT (코드 확인).** `is_local_llm_model("titan-embed")` → False
  (`_LOCAL_LLM_VALUES={auto,edge,core,code}`), 따라서 `_get_llm_client(model=
  "titan-embed")` 는 `BEDROCK_GATEWAY_URL`(bedrock-gateway)로 resolve. query path
  + backfill worker 모두 bedrock-gateway 경유 → 이제 llm-shared 로 Ollama 도달.
  local-llm-gateway bypass 실재.
- **네트워크 변경 — CORRECT, non-breaking.** `networks: [dbnet, llm-shared]`,
  llm-shared 는 compose 에 external 선언. dbnet 유지로 앱→gateway master_key 인증
  + claude-* Anthropic-direct 라우팅 무영향 (Anthropic egress 는 default route).
  web/agent/ask/insight 가 이미 `[dbnet, llm-shared, replica-net]` 인 패턴과 동일.
- **재백필 우려 — 실증적으로 무효(BLOCK 아님).** texts.embedding 은 baseline 부터
  vector(1024) (alembic 0001), sample_queries 는 0015 에서 1536→1024 정렬. 두 컬럼
  모두 **실 임베딩 0건** (alembic 0015 docstring: "titan 다운"). Titan-space 잔존
  벡터가 없으므로 bge-m3-space 와 cosine 혼선 발생 corpus 자체가 없음. worker 는
  `WHERE embedding IS NULL` 만 처리 → 향후 전량 bge-m3-space 로 self-consistent.

## 2. Risks

  기록 — 실제 backing 은 bge-m3. provenance 추적 목적 저해 (audit 오인 가능).
- (operational) 임베딩이 이제 local-llm-edge Ollama 가용성에 의존. Ollama down 시
