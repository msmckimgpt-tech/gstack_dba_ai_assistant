## 설계에서 가장 중요한 두 가지

**1. 클러스터 정체성은 `cluster_id` 가 아니라 멤버셋 지문이다.**
`semantic_cluster_id` 는 pass 마다 MDS 배치 순서로 재부여되어 churn 한다. 좌표를 캐시 키로 쓰면
내용이 그대로인데도 매 pass 818개를 재생성한다.

**2. 요약은 클러스터링 시그니처에 유입되지 않는다.**
유입되면 요약 갱신 → 재임베딩 → 재클러스터 → 요약 갱신의 순환이 된다. 수렴 보장이 없고 비용이
발산한다. 증거·분석의 변화는 오직 **요약 캐시 키**(2중 버전)로만 전파된다.

## 리뷰에서 배운 것

codex 가 P1 3건을 잡았고 전부 실질적이었다:

  구현은 `Σ schema × 40` 이었다 — 라이브 스키마 수를 곱하면 폭주다.
- **토큰 예산을 pass 진입 시 1회만** 확인했다. `acquire("llm")` 은 동시성 슬롯이지 누적 소비가
  아닌데 그것으로 충분하다고 착각했다.
- **증거 매칭이 대소문자에 취약**했다. 어긋나면 `evidence_version` 이 영구히 빈 문자열이 되어
  L0 변경이 요약에 전파되는 유일한 경로가 조용히 죽는다.

그리고 P2 중 savepoint 누락은 **바로 앞 cycle(feature-0031)에서 자체 점검으로 잡았던 결함을
그대로 반복한 것**이다. 같은 커넥션을 공유하는 모듈을 새로 만들 때 savepoint 를 기본값으로
삼는다는 계약을 FUNCTION.md 에 명시했다.
