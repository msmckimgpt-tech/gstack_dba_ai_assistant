# Source Code Layout

## 개요
이 디렉토리는 기능의 소스 코드를 포함한다.

## 구조
```
src/
├── README.md           # 이 문서 (소스 코드 레이아웃 설명)
├── (메인 코드 파일)     # 기능의 핵심 구현
├── config/             # 설정 파일 (선택)
│   ├── default.env     # 공통 기본 설정
│   ├── profiles/       # 프로필별 설정 오버라이드
│   │   └── local.env   # 로컬 환경 프로필
│   └── credentials/    # 자격증명 (git-ignored)
│       └── *.example   # 자격증명 템플릿만 커밋
└── (추가 모듈)
```

## 설정 계층
설정 값은 아래 순서로 로드되며, 후순위가 전순위를 오버라이드한다:
1. `config/default.env` — 공통 기본값
2. `config/profiles/<profile>.env` — 프로필별 오버라이드
3. 환경변수 (`.env` 또는 시스템) — 런타임 오버라이드
4. CLI 인자 — 최종 오버라이드

## 설정 변수 주석 규칙
설정 파일의 변수에는 반드시 주석을 작성한다.
- 모든 변수: 역할 설명 (1~2줄)
- 열거형: `허용값:` + 각 옵션 동작 설명
- 숫자형: 단위 명시 (초, 일, GB 등)
- 경로형: 상대경로 기준점 명시
- 템플릿형: 지원 토큰 목록
- 불리언형: 각 값(0/1)의 동작 설명

상세 표준과 예시는 `/repo/docs/CONVENTIONS.md` §8.2를 참조한다.

## 자격증명
- `config/credentials/` 내 실제 자격증명 파일(`.cnf`, `.env`)은 `.gitignore`에 등록한다.
- `*.example` 파일만 저장소에 커밋하여 필요한 키와 형식을 문서화한다.
- 자격증명 파일 권한은 `0600`을 유지한다.

### 왜 소스가 패키지이고 배포본이 생성물인가

러너는 **사용자가 파일 하나를 내려받아 그대로 실행**하는 산출물이라(무설치 계약,
`../docs/ANCHOR.md` §1·§3) 배포되는 실물은 단일 파일이어야 한다. 그렇다고 소스까지 단일
파일로 두면 4,238행 한 파일에 모든 관심사가 모여 **병렬 세션이 반드시 충돌**한다. 게다가
종전에는 그 파일이 배포 경로에도 **바이트 동일 사본**으로 커밋돼 있어, 90일 49개 커밋이
예외 없이 둘 다 고쳤다(49/49). 소스는 쪼개고 배포본은 빌드가 만들어 두 문제를 함께 없앴다
(`AGENTS.md` §13.1 v3.35.1 «1순위» — 생성물을 소스에 커밋하지 않는다).

### 고치는 법

1. `agent/` 안 해당 모듈을 고친다. 새 모듈을 추가했으면 `__init__.py` 의 `_EMIT_ORDER`
   에도 넣는다 — 빠뜨리면 그 코드는 배포본에서 **조용히 사라진다**(빌드와 테스트가 차단).
2. `make bridge-agent` 로 로컬 산출물을 갱신한다(테스트는 `conftest.py` 가 자동 수행).
3. 배포본은 이미지 빌드가 만든다 — `bridge_agent.py` 를 직접 편집하지 않는다.

### 제약 (분할해도 변하지 않는 것)

- **stdlib 전용** — `pip install` 이 필요한 모듈을 import 하지 않는다.
- **모듈 간 순환 금지** — 번들에서는 드러나지 않지만 패키지 형태에서 `ImportError` 가 된다.
- **가변 전역은 접근자로** — `from .x import _GLOBAL` 은 import 시점 값에 묶여 갱신을
  못 본다. `state.py` 참조.
