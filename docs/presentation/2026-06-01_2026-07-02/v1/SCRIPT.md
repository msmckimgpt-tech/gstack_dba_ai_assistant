# 개발 진척 보고 — 발표 스크립트 (2026-06-01 ~ 2026-07-02 · v1)

> 시각 자료는 동봉 `deck.html`(자기완결 슬라이드). 조작: → / Space / 우측 클릭 = 다음, ← / 좌측 클릭 = 이전, `Esc` 또는 좌상단 "목차" = 목차, 주소 끝 `#키`로 특정 장 직행(예 `#feat-graph`).
>
> **정직성 규칙(중요)**: 이 자료는 "개발·머지 완료"와 "라이브 배포·효과 확인"을 구분한다. `확인필요`(⚠) 배지가 붙은 것은 **"완료/개선했습니다"로 단정하지 말고** "도입했고, 효과는 측정/검증 예정입니다"로 말한다. 근거 상세는 `EVIDENCE.md`.

## 0. 발표 개요 (presenter brief)

| 항목 | 값 |
|---|---|
| 대상 청중 | 기획·운영·관리(비전문가) + 개발 |
| 핵심 메시지 | "한 달 만에 **쓸 만한 도구 → 믿고 운영하는 플랫폼**으로 — 신뢰·데이터 범위·정확도·협업·안정성이 함께 올라섰다" |
| 소요 | 풀 12~15분 / 압축 6~7분 |
| 톤 | 절제·신뢰. 성과는 근거 있는 것만 수치로, 나머지는 "예정/목표"로 정직하게 |

**발표 흐름**: 결론(요약) → 배경(왜) → 화면 흐름 순 7가지 변화 → 성과(확인 vs 확인필요) → 리스크·후속 → 마무리.

**압축 발표(6~7분)**: 표지 → 핵심 요약 → 배경 → 개요 → [4. 데이터 · 6. 운영·지식그래프 · 7. 무중단]만 → 기대 효과 → 리스크. 나머지 기능 장은 목차로 건너뛰거나 질의응답 때.

## 1. 구간별 스크립트

### [0] 표지 — `cover`
> "2026년 6월 한 달, **DBA AI Assistant**가 어떻게 발전했는지 보고드립니다. 한 문장으로 — *SQL을 몰라도 자연어로 데이터를 묻고, 시스템은 안전하게 검증된 조회로 답하는* 사내 어시스턴트입니다. 오른쪽 위 배지 다섯 개(신규·이어받음·완료·확인·확인 필요)를 먼저 봐 주세요. 뒤에서 **'확인된 것'과 '아직 확인이 필요한 것'을 일부러 구분**해 말씀드립니다."
> **전환**: "먼저 결론부터."

### [1] 핵심 요약 — `summary`
> "이 기간 개발은 세 방향입니다 — **①제품 신뢰(보안·안정), ②데이터 범위·정확도, ③함께 쓰기·운영 관제.** 총 **16개 작업 묶음**이 본선에 반영됐고, 지원 데이터베이스가 **MySQL 하나에서 MSSQL까지 둘**로 늘었으며, **배포 중 접속 중단이 0회**가 됐습니다."
> *(정직 표현)* "여기 숫자들은 근거가 있는 것만 올렸습니다. '16 묶음'은 코드 이력, '중단 0회'는 실제 부하 시험 결과입니다."
> **전환**: "왜 이 일을 했는지부터."

### [2] 개발 배경 — `background`
> "상황은 — 현업도 데이터를 직접 보고 싶어 하지만 대상은 MySQL 하나, 웹은 한 대뿐이었습니다. 문제는 — **배포할 때마다 화면이 잠깐 끊기고(502)**, 계정 보호나 기록 변조 방지 같은 **운영 신뢰 요소가 부족**했으며, 답의 **정확도를 측정·개선할 수단**이 없었죠. 그래서 목표를 셋으로 잡았습니다 — 안 끊기게, 더 많은 데이터를 더 정확하게, 안전하게·함께."
> **전환**: "이제 사용자가 화면을 만나는 순서대로 보겠습니다."

### [3] 이번 기간 개요 — `agenda`
> "일곱 가지입니다. 접속·인증부터 시작해 작업 화면, 정확도, 데이터 범위, 협업, 운영 관제, 그리고 마지막이 끊김 없는 서비스입니다. 대부분 **신규**이고, 인프라는 **완료·배포**까지 됐습니다."
> **전환**: "하나씩."

### [4] 접속·인증 — `feat-access`
> "먼저 '들어오는 문'입니다. 전에는 접속 시 인증서 경고가 뜨고 로그인이 단일 인증이었는데, 이제 **사내 자체 인증서로 경고를 없애고, 2단계 인증과 로그인 시도 제한**을 넣었습니다."
> *(확인필요 정직 표현)* "이 기능들은 **개발·반영이 확인**됐습니다. 다만 '얼마나 사고를 막았는가' 같은 **실효는 운영에서 확인이 필요**합니다 — 오늘은 '도입했다'까지만 말씀드립니다."

### [5] 작업 화면 — `feat-work`
> "핵심 작업 화면입니다. 답변이나 첨부 SQL을 고쳐 달라고 하면 이제 **깃 diff처럼 바뀐 줄을 색으로** 보여주고, 큰 결과는 화면 안에서 바로 펼치며, 처리 중엔 전송 버튼이 중단 버튼으로 바뀝니다. **무엇이 바뀌었는지 검토**가 쉬워졌습니다."

### [6] 더 정확한 답 — `feat-accuracy`
> "정확도입니다. **좋은 답을 등록 → 관리자 검수 → AI의 참고 예시로 환류**하는 선순환을 만들었고, 회사 고유 용어·코드값 사전과 혼합 검색을 더했습니다. 중요한 건 **자동 학습이 아니라 사람 검수**를 거친다는 점 — 나쁜 답이 정확도를 오염시키지 않게요."
> *(확인필요 정직 표현)* "여기서 조심할 것 — **정확도가 몇 % 올랐다는 수치는 아직 측정 전**입니다. '정확도를 측정하고 올릴 수단을 갖췄다'가 이번 성과이고, 수치는 다음 기간에 목표로 제시합니다."

### [7] 더 많은 데이터 — `feat-datasource`
> "제품이 커진 지점입니다. **MySQL 전용에서 MSSQL까지** 다루게 됐고, 접속 정보는 **암호화 저장**, 접근은 **제품 → 데이터소스 → DB 단위 화이트리스트**로 통제합니다. 바인딩이 없으면 접근 자체가 0 — **기본이 차단**입니다. 연결 상태는 정상·불안정·끊김을 색과 글자로 함께 표시하고, 불안정한 DB 하나가 전체를 막지 않게 격리합니다."

### [8] 함께 쓰기 — `feat-group`
> "데이터 점검은 함께 할 때가 많죠. **공유 링크로 여러 명을 한 대화**에 부르고, 사람끼리는 채팅하듯 의논하다 **`@어시스턴트`를 붙인 글에만 AI가 답**합니다. 핵심 안전장치 — **열람과 발화(조회)를 권한으로 분리**했고, AI 조회는 **언제나 요청한 본인의 권한**으로만 이뤄집니다. 권한이 새지 않습니다."

### [9] 운영·관제 + 지식그래프 — `feat-admin`
> "운영자 화면입니다. **사용량·비용 대시보드, AI 운영 현황 패널, 단계적으로 펼쳐지는 권한 편집기**를 넣었고, 감사 기록은 **해시 체인으로 변조를 막습니다.** 그리고 하이라이트 — 수천 개 테이블 메타데이터를 **지식그래프로 탐색**합니다. 관계(외래키)가 선언 안 된 DB도 **관계를 추론**하되, **추정과 신뢰를 구분해 표시**해서 과장하지 않습니다."
> *(확인필요 정직 표현)* "그래프는 **배포됐고 서버 조회 속도가 약 60배 빨라진 건 서버에서 실측**했습니다. 다만 **화면 렌더 속도(FPS)와 실제 화면 시각 검증은 아직 확인이 필요**합니다."

### [10] 끊김 없는 서비스 — `feat-stability`
> "마지막, 안정성입니다. 웹을 **두 대(A·B)로 나눠 한 대씩 교체**하니 배포 중에도 최소 한 대는 정상 — **502가 0**이 됐습니다. 질문은 '작업 대기열'에 넣어 **재배포에도 살아남고**, 29,000줄짜리 거대한 코드 파일은 **21개 모듈로 정리**했습니다 — 겉보기 동작은 그대로 두고요."
> *(확인필요 정직 표현)* "무중단·모듈화는 **배포·실증까지 확인**됐습니다. 단 **자동 롤백과 일부 보조 기능(백업 자동화)은 배포·검증이 남아** 있습니다."
> **전환**: "종합하면."

### [11] 기대 효과·성과 종합 — `impact`
> "왼쪽은 **근거가 확인된 성과** — 무중단 502 zero, 그래프 서버 조회 60배, DB 재시작 오류 0, 백업 복원 통과, 그리고 다중 데이터·보안·협업·정확도 수단의 개발 완료입니다. 오른쪽은 **아직 단정하지 않는 것** — 정확도·FPS 수치, 일부 라이브 배포, 실 화면 검증입니다. 저희는 이 둘을 **일부러 나눠** 보고합니다. 그게 신뢰의 핵심이라고 봅니다."

### [12] 리스크·후속 — `risk`
> "남은 위험과 다음 할 일입니다. 무중단 보조 기능 라이브 배포, 실 화면 시각검증, 성능·정확도 수치 측정, 자동 롤백 검증입니다. 그리고 **단일 호스트라는 구조적 한계**는 인지하고 있고, 무리한 이중화보다 **데이터 보존(백업/복원) 강화**를 먼저 택했습니다 — 문서화된 의사결정입니다."

### [13] 마무리 — `outro`
> "정리하면, 한 달 만에 **신뢰·데이터 범위·정확도·협업·안정성**이 함께 올라섰습니다. 다음 기간엔 남은 배포와 **수치 측정**으로 오늘의 '예정'을 '확인'으로 바꾸겠습니다. 발표 전 확인필요 8건은 담당자와 점검하겠습니다. 질문 받겠습니다."

## 2. 청중별 팁
- **의사결정자**: 요약 → 배경 → [데이터·무중단·지식그래프] → 기대 효과 → 리스크. 체감+가치 중심, 나머지는 목차 점프.
- **운영 담당**: 접속·인증 · 운영 관제 · 무중단 · 리스크 중심.
- **개발**: 전 장 + `EVIDENCE.md`·`unit/*/docs/REPORT.md` 병행.
- **공통 주의**: `확인 필요` 항목을 "완료"로 말하지 않는다. 계정·비밀번호·접속 정보 등 민감정보는 화면·구두 어디에도 노출하지 않는다.
