# Decisions (feature-local ADR)

## ADR-0031-01 — 접지를 계층 요약보다 먼저 한다
- **결정:** 노드 분석 개선의 첫 슬라이스를 L2/L3 계층 요약이 아니라 L0 증거 수집 + L1 주입으로 잡는다.
- **맥락:** 사용자 요청은 "오케스트레이터가 분석 AI 를 파견·집계"였고, 리서치가 지목한 업계 패턴
  (GraphRAG 계열)도 계층 요약을 핵심 이득으로 제시한다. 그러나 우리 실측상 분석 입력에는 데이터
  실측이 0이고 프롬프트가 명시적으로 이름 규칙 추론을 지시한다 — 1만여 건의 분석문이 추측이다.
- **근거:** 접지 없이 요약을 얹으면 "추측의 요약"이 되어 틀린 내용을 더 권위 있게 만든다. 게다가
  나중에 접지를 넣으면 요약을 전량 재생성해야 하므로 순서를 뒤집는 비용이 크다.
- **결과:** ROADMAP 의 Phase 순서가 T1(접지) → T2(합성)로 고정됐다. L2 는 T1 완료를 depends_on 으로 갖는다.

## ADR-0031-02 — LLM 오케스트레이터를 도입하지 않는다
- **결정:** 분석 fan-out 을 LLM 오케스트레이터로 바꾸지 않고 기존 결정적 큐(`node_analysis_jobs`)를
  유지한다. LLM 은 집계(L2)와 검증(T3)에만 새로 투입한다.
- **근거:** fan-out·예산·중복 제거는 이미 결정적으로 구현돼 있다. 오케스트레이터를 LLM 으로 바꾸면
  토큰 15배(Anthropic 실측)와 비결정성만 얻는다. 2026 프로덕션 사례의 다수가 결정적 백본 +
  특정 스텝만 LLM 이다.
- **폐기하지 않은 것:** 사용자가 원한 "파견 → 집계"의 **집계** 쪽은 채택했다(L2 클러스터 요약).
  구조를 거부한 게 아니라 LLM 이 값어치를 내는 자리를 옮겼다.

## ADR-0031-03 — 원시 샘플값을 수집·저장·주입하지 않는다
- **결정:** 증거는 통계로 한정한다. 컬럼 값 자체는 저장하지 않으며, **문자열 컬럼의 min/max 값도
  저장하지 않는다**. 문자열은 길이 분포 + 패턴 클래스(`digits|hex|uuid|email_like|mixed|empty`)로
  대체하고, 숫자·시각 타입만 min/max 를 남긴다.
- **맥락:** 사용자가 "샘플값 배제"를 확정했다(2026-07-30). 설계 초안에는 `min_text`/`max_text` 가
  있었는데, 구현 시점에 그것이 사실상 원시 샘플 1건이고 이름·이메일·주소 컬럼에서는 곧 PII 임을
  확인해 함께 배제했다.
- **근거:** DBAutoDoc(2025)의 결정적 이득(FK 판정 F1 +23p)은 통계에서 나오지 샘플값에서 나오지
  않는다. 즉 접지라는 목적에 샘플값은 필수가 아니다.
- **강제 수단:** `ck_metadata_column_stats_pattern` CHECK 제약이 열거된 분류값만 허용한다 —
  실수로 원시값을 적재하려 하면 코드 리뷰가 아니라 **DB 가 거부**한다. 테스트는 집계 산출물과
  upsert 바인딩 양쪽에서 원시값 부재를 단정한다.

## ADR-0031-04 — 적응형 부하는 AIMD 가 아니라 관측 기반 단계 승격으로
- **결정:** 수집 깊이를 Stage 0~3 으로 두고, **하루 최대 1단계** + **주간 시간창 상한** +
  **Stage 3 은 운영자 명시 상향**으로 올린다. 자동 증감(AIMD)은 쓰지 않는다.
- **맥락:** 사용자 지시는 "첫 동작은 보수적, 점진적으로 적극적인 탐색으로 전환하는 적응형 부하"였다.
- **근거:** AIMD 는 (a) 우리가 그 자원의 지배적 소비자이고 (b) 신호 지연이 제어 주기보다 짧을 때
  성립한다. 운영 DB 는 게임 서비스가 주 소비자이고 부하 신호는 분 단위로 늦게 온다 — 두 전제가
  모두 깨져 발진(증가 → 지연 관측 → 과감축 → 재증가) 위험이 크다. 단계 승격은 같은 "보수적 시작 →
  점진 확대"를 발진 없이 만든다.
- **관측:** 승격 판단의 근거는 `metadata_table_stats.collected_at`/`stage`(DB) + 수집 로그이고,
  자원 점유는 T0 의 워커 자원 스냅샷(`bin/perf-snapshot.sh` §12)이 이미 노출한다.

## ADR-0031-05 — 수집 대상은 스케줄러가 아니라 분석 흐름이 정한다
- **결정:** 별도 수집 스케줄러를 두지 않고, 노드 분석이 Table 잡을 처리하기 직전에
  `ensure_stats()` 를 호출한다(`_ensure_table_columns` 와 같은 자리).
- **근거:** (a) 분석되는 테이블만 보므로 쓰이지 않을 통계를 미리 모으는 낭비가 없고, (b) 노드
  분석 자체가 이미 페이싱·예산 게이트 아래 있으므로 수집 부하가 그 페이스를 그대로 물려받는다.
  독립 스케줄러는 자기 페이싱·자기 예산·자기 실패 처리를 새로 만들어야 한다.
- **트레이드오프:** 아직 분석되지 않은 테이블에는 증거가 없다. 이는 T3(결정적 플래너)가 커버리지를
  넓히면 함께 해소되는 문제라 지금 별도 장치를 만들지 않는다.

## ADR-0031-06 — 증거를 semantic_cluster 시그니처에 넣지 않는다
- **결정:** 통계 증거는 분석 payload 에만 들어가고, 클러스터링 시그니처(RC4)에는 유입되지 않는다.
- **근거:** 시그니처에 넣으면 통계가 갱신될 때마다 전량 재임베딩·재클러스터가 유발된다
  (blast-radius 가 feature 경계를 넘는다). 증거 변경의 전파는 L2 요약 캐시 키가 담당한다.

## ADR-0031-07 — thin 판정을 길이에서 항목 충족도로 바꾼다
- **결정:** `_analysis_is_thin` 을 summary 길이 단독 판정에서 항목 충족도(summary·relationships·
  usage, Table 은 role)로 바꾸고, 길이 하한 기본값을 120 → 40 으로 내린다.
- **맥락:** 프롬프트 계약은 "한국어 1~2문장"(≈50~100자)인데 판정 임계가 120자였다 — **정상 분석
  대부분이 thin 으로 잡히는** 모순이다.
- **위험:** 지금은 `REFINE_MAX=30`/run 캡이 폭주를 막고 있을 뿐이다. 캡을 올리면 대량 재분석이
  터진다. 즉 이 수정은 "판정 정확도" 문제이자 **미래의 폭주를 미리 제거하는 안전 조치**다.
- **하위호환:** `AGENT_NODE_ANALYSIS_THIN_CHARS` 는 여전히 실제 게이트다(한 문장도 안 되는 응답
  방어). 게이트 없는 knob 을 남기지 않는다는 ADR-0025-06 과 정합.
