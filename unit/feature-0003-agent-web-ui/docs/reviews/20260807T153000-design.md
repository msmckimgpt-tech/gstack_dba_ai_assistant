# [SUBAGENT:design] — 그룹 대화 첫 사용 안내 툴팁 (gc-first-use-guide)

Trigger: UI/layout · 화면·레이아웃 (§18.8 dispatch 표 3행)
Context bundle: changed_files + diff_excerpt(index.html / chat.css) + 기존 레이아웃 사실
(`.composer-wrap` 형제 오버레이 · `.mention-ac` · `.chat-drop-overlay` · CSS 토큰) +
acceptance_criteria(AC-5·AC-6).

## 1. Findings

### BLOCKING
**z-index 40→60 tier 가 `#mentionAutocomplete` 를 가린다.** 툴팁이 `left:20px;
bottom:calc(100% - 4px)` 로 `.mention-ac` 와 같은 자리를 쓰는데 z 60 이라 위에 선다.
안내 2·3번째 줄이 사용자에게 `@` 입력을 시키므로 **안내가 떠 있는 동안 멘션 목록이 열리는
것이 정상 경로**다 → 멤버 목록이 가려진다.

### MAJOR
- **caret 이 `.composer-wrap` 안으로 12px 파고든다.** `bottom: calc(100% - 4px)` +
  `::after { bottom:-7px; border-top:8px }` 인데 wrap 의 top padding 은 8px 뿐.
  `#llmRestrictionBanner`/`#timeoutExtendBanner` 가 떠 있으면 흰 노치가 배너 첫 줄을 덮는다.
- **`.chat-drop-overlay`(z 50) 를 뚫는다.** 파일 드래그 중에도 카드가 오버레이 위에 뜬다.
- **다크 모드 회귀** — `box-shadow: rgba(15,23,42,.15)` 는 어두운 표면에서 보이지 않고
  (백드롭이 없어 그림자가 유일한 분리 신호), `--primary` 12px 텍스트가 다크에서 3.58:1 로
  AA 미달. 폴백들(`#0f172a`/`#64748b`)이 이 저장소의 warm 팔레트(`--text:#26251e`)와 이질적.
- **모션 선호가 인앱 설정을 무시.** 저장소 규약은 `html[data-motion="on"]` 재활성 /
  인앱 off 반영인데 OS 전용 형태만 썼다.

### MINOR
- 닫기 버튼 실측 ≈40×21px — 터치 최소 44px 미달인데 유일한 소진 어포던스.
- `max-width: calc(100vw - 48px)` 는 사이드바를 뺀 실제 pane 폭보다 커서 무효.
- `width:max-content` 는 좁은 뷰포트/큰 폰트에서 줄바꿈 → AC-5("각 줄 한 줄")가 시각적으로
  깨질 수 있고 문자열 길이 단언은 이를 못 본다.
- 조상 `overflow:hidden` 클리핑 위험 미확인.

### NIT
제목과 본문이 모두 12px 이라 위계가 약하다.

## 4. Disposition (main session 반영 결과)
- **BLOCKING 수용** — `z-index: 40`. `.mention-ac`(50)·`.chat-drop-overlay`(50) 아래로
  내려 두 지적을 한 번에 해소. 하네스 `[스택]` 이 **두 파일에서 실제 z 값을 읽어 비교**한다
  (상수 하드코딩 아님, 뮤테이션 M4 red).
- **caret 수용** — `bottom: calc(100% + 6px)`(`.mention-ac` 와 동일 앵커)로 카드와 caret
  전체를 wrap 밖에 세웠다. 하네스가 `calc(100% - Npx)` 형태의 회귀를 금지(뮤테이션 M5 red).
- **드래그 오버레이 수용** — 위 z 조정으로 동시 해소.
- **다크 모드 — 지적을 검증한 결과 반대로 조치(정정).** `css/base.css` 에
  `prefers-color-scheme` 블록이 **0개**이고 `--surface` 는 항상 `#ffffff` 다(라이트 단일
  테마). 여기에 다크 override 를 넣어 강조색을 밝은 파랑으로 올리면 OS 가 다크일 때
  **흰 카드 위 연파랑(≈1.8:1)** 이 되어 오히려 못 읽는다 → **다크 블록을 넣지 않는다.**
  대신 실제로 유효한 축만 고쳤다: 폴백을 저장소 팔레트로 정렬(`--border:#e6e5e0`,
  `--text:#26251e`, `--primary:#2563eb`), 그림자·hover 를 토큰(`--gc-guide-*`)으로 빼
  다크 도입 시 재정의 지점을 남김. 하네스가 "base.css 에 다크 토큰 없음" 이라는 **전제**와
  "안내에 다크 @media 규칙 없음" 을 함께 단정해, 전제가 바뀌면 red 로 드러난다.
- **대비 — 계산해서 고쳤다.** 본문에 쓰려던 `--text-muted`(#807d72)는 흰 배경 **4.12:1** 로
  12px 본문 AA 미달 → 전용 토큰 `--gc-guide-body(#4a4841)` **9.15:1**. 제목 15.38:1,
  닫기 버튼 5.17:1(모두 AA 통과).
- **모션 수용** — `html:not([data-motion="on"])` + `html[data-motion="off"]` 저장소 규약 이식.
- **터치 타깃 수용** — `padding: 8px 10px` + 음수 margin(시각 밀도 유지). 하네스가 산식으로 단정.
- **max-width 수용** — `calc(100% - 40px)`(컨테이너 기준).
- **줄바꿈 — 의도된 degrade(미반영, 근거)**: `nowrap` 은 좁은 폭에서 **클리핑**을 낳는다.
  최장 항목이 24자/≈222px 라 실사용 폭에서 한 줄이며, 극단적으로 좁을 때는 잘림보다
  줄바꿈이 낫다. 렌더 줄 수 단언은 브라우저가 필요하므로 **PB-0008 의 몫**으로 남긴다(정직 표기).
- **클리핑 위험 — 실측으로 해소**: 툴팁은 `.chat-pane`(overflow:hidden) **안쪽** 위로만
  자라며, 동일 패턴의 `.mention-ac` 가 같은 앵커로 이미 정상 동작한다.
- **NIT 수용** — 제목 13px.
