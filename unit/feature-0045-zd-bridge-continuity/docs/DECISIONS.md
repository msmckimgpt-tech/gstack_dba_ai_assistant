# Decisions

## ADR-20260827T073753-01 — 대기와 작업을 다르게 다룬다

- **결정**: 배포 게이트는 진행 중인 도구 호출(`bridge_inflight`)만 기다리고, 블로킹 대기
  (`bridge_waiters`)는 드레인 신호로 즉시 비운다.
- **근거**: 연결된 AI 는 **항상** 대기 중이다. 대기를 기다리면 배포가 매번 상한까지 갔다가
  강행하게 되어, 게이트를 붙인 의미가 사라진다. 반면 대기는 끊겨도 잃을 것이 없다 —
  정상 200 으로 끝내고 다시 부르면 다른 replica 가 받는다.
- **대안**: 둘 다 기다린다(Alt-A, ANCHOR §2) — 기각.

## ADR-20260827T073753-02 — 드레인 신호는 `/livez` 503 + 도구 경로 503 두 겹

- **결정**: 엣지에는 `/livez` 503 으로, MCP 어댑터에는 `X-Bridge-Draining` 헤더로 알린다.
- **근거**: 어댑터는 엣지를 거치지 않고 `web-a` → `web-b` 로 **직결**한다. 엣지 신호만으로는
  그 경로가 드레인된 replica 를 계속 붙잡아 `bridge_inflight` 가 0 이 되지 않는다 —
  무중단을 위해 만든 장치가 정확히 반대로 작동한다.

## ADR-20260827T073753-03 — 점유 회수는 소유자를 지우지 않는다

- **결정**: `ClaimedAt` 만 과거로 밀어 lease 를 만료시키고 `ClaimedBy` 는 보존한다.
- **근거**: `submit_answer` 는 `ClaimedBy` 만 본다. 소유자를 지우면 **살아남은 러너의 제출이
  409 로 거절**되어, 끊기지도 않은 작업을 배포가 버리는 셈이 된다. 보존하면 먼저 끝내는 쪽이
  이기므로 어느 경우에도 손실이 없다.

## ADR-20260827T073753-04 — MCP 표면은 2-replica 상시 (surge 아님)

- **결정**: `ext-tool-mcp-a/b` 를 상시 띄우고 Caddy LB 뒤에서 하나씩 교체한다.
- **근거**: surge 교대는 **큐 소비자**에게 성립하는 패턴이다("받는 쪽을 먼저 세운다").
  MCP 는 HTTP 수신자라 엣지 upstream 을 배포 중 동적으로 바꿔야 하고, 그 reload 경계가
  2-replica 상시보다 얇다. 사용자 결정(2026-08-27).
- **비용**: 상시 컨테이너 1개.

## ADR-20260827T073753-05 — 러너의 "sleep 금지" 는 대기에만 적용된다

- **결정**: 대기 루프에는 sleep 이 없다(유지). 연결 **실패** 경로에만 지수 백오프(1→15s).
- **근거**: 종전 규칙은 파일 전체에서 sleep 을 금지했고, 그 금지가 실패 경로까지 덮어
  서버가 교체되는 몇 초 동안 **초당 수천 번 재시도**하는 busy-loop 를 만들었다. 대기와
  재연결은 다른 일이다. 테스트는 허용되는 sleep 이 **하나뿐**임을 값으로 고정한다.
