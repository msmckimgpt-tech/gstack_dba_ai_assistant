### F3 (Critical·확증된 결함) 매니페스트 예산 선점이 cap 을 깨고 **본문 발췌를 전량 축출**한다

  노출 → 모델이 execute_sql 실패 후 원인 추정) 전부 테스트 0.
- **R4**: `read_attachment` 가 인라인 본문을 재사용할 때(`agent_core.py:695-698`) 그 본문은

## 4. Verdict rationale (판정 근거)

BLOCK 근거는 "테스트가 적다"가 아니라 **테스트가 있는 곳이 실제로는 비어 있다**는 점이다.

- 확증된 기능 결함 1건(F3): probe 로 cap 2.9배 초과 + 본문 전량 축출을 재현했고, 그 구간을 지키는
  것처럼 보이는 테스트가 조건을 비켜가 green 이다. 변경의 **목적(리뷰어 오판 감소)과 반대 방향**으로
  작동한다.
- 선언된 AC 가 코드에서 성립하지 않는 것 2건(F7 client 합집합 계약, F9 그룹 발신자 불변식) —
  둘 다 테스트가 우회 동작을 오히려 정상 계약으로 고정한다.
- AC 5개 중 **AC-4 는 절반(프롬프트 지시)이 0건 + 나머지 절반이 tautology(F2, F5)**, **AC-5 는 0건(F6)**,
  **AC-1 의 "최신 우선"과 AC-2 ①의 운영 경로가 0건(F1, F7)**. 즉 5개 중 실질 커버는 AC-3 일부뿐이며
  그 AC-3 도 datamark(인젝션 방어) 단언이 빠져 있다(F8).
- 기존 계약 1건이 의미 반전된 채 green(F4) — 이 changeset 이 만든 가장 위험한 신호 손실이다.
- 게이트·증적 2건(F10 baseline 주장 무근거, F11 CHECK#13 Windows-browser Run 미스테이지)은
  단독으로도 verify-completion 을 통과하지 못한다.
