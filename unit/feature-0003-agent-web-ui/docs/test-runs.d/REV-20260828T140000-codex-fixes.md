## 이번 cycle 의 변경 성격

바꾼 것은 **서버 로직과 러너**다:

| 파일 | 변경 |
|---|---|
| `shared/bridge_tasks.py` | 확인된 변경만 보고 · 못 지운 것은 취소 승격 |

| `src/bridge_agent.py` | 대기·자리 분리 · 배압 · `_failed` 전 경로 · 제출 재시도 |

**프런트 자산(JS/CSS/HTML)은 한 줄도 바뀌지 않았다.** 화면이 그리는 내용·조작면은 이전
cycle 과 동일하므로, 이번 변경만으로 새로 볼 화면 동작이 없다.

다만 `routers/` 변경이 CHECK#13 의 대상 범위에 들어오므로 **미수행 사유를 명시**한다:

1. 이번 diff 에 **웹 자산 변경 0** — 화면 렌더 경로는 무변경이다.
2. 서버측 변경의 사용자 대면 효과(취소가 실제로 걸렸는가 · 워커 포화 중 취소 인지 ·
   부하 시 폴링 강등)는 **실제 LLM 러너를 붙여야** 관측된다. 그 검증은 사용자가 브라우저에
   로그인해 주기로 한 다음 단계에서 수행한다(TASK.md 잔여).
3. 브라우저 브리지 자체는 **정상 동작**한다(이전 Run 에서 근본원인 수정 완료 —
   `REV-20260828T093000-live-interrupt-measure.md`). 이번 미수행은 브리지 문제가 아니다.
