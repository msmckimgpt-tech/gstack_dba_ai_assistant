위협 모델: `work`/`reason` 은 외부 AI 가 `POST /api/ai/tools/<name>` 으로 보내는 값이며, 그 AI 는
DB 내용·첨부에 심긴 프롬프트 인젝션으로 조종될 수 있다. 워크트리 실물 기준 실측.

### 1. Blocking issues

- **B1 (high) 파생 경로가 공격자 제어 도구 표기를 화면에 되돌려 놓는다 — 판정기 우회 완결.**
  - Evidence: `_resolve_step_display({"tool":"search_tables","args":{"keyword":"describe_table
    {'schema_name': 'coupon', 'table_name': 'dbo.T_COUPON'}"},"work":"search_tables 실행"})`
    → 제목 `` `describe_table {...}` 관련 테이블을 찾는다 `` (`work_source="derived"`), 그리고
    그 제목에 판정기를 다시 태우면 True 다. 제보 문자열이 **그대로** 복귀한다.
  - Location: `src/routers/_conv_store.py:4245` · `src/routers/ai_tools.py:4283`
  - Reason: 정화가 `work` 한 축만 막고 대체값 생성기가 `args` 의 같은 페이로드를 무검증으로
    제목에 주입한다 — 공격자는 같은 요청에서 필드만 옮기면 된다. 적재 경로는 파생값을
    재검사하는데 표시 경로 2곳만 빠졌다.
  - Action: 표시층의 마지막 산출을 고정점으로 만들어라 — 파생 직후 재정화 + 일반 문구 강등.
- **B2 (high) 파생 제목에 길이 상한이 없어 저장 문구의 255자 캡을 우회한다.**
  - Evidence: `args={"keyword": "A"*100000}` → 제목 **100,014자**(저장 경로는 255자).
  - Location: `src/routers/_conv_store.py:4245`
  - Reason: 이 패널은 폴링마다 통째로 재렌더되므로 대형 제목 한 건이 매 tick 비용을 곱한다.
  - Action: 파생 결과에도 `_normalize_step_text(w, 255)` 를 적용하라.
- **B3 (medium) 「진행/완료 제목 동일」 완료 기준이 실제로 성립하지 않는다.**
  - Evidence: `read_task_attachment` — live `첨부 파일 "a.sql" 의 내용을 읽는다` vs
    done `첨부 파일의 내용을 읽는다`. 적대 인자에서는 live 가 강등하고 done 이 유출을 낸다.
  - Location: `src/routers/_conv_store.py:6456` ↔ `src/routers/ai_tools.py:1644`
  - Reason: 가드가 `describe_table` 픽스처 1건만 태워 구조적으로 잡을 수 없다.
  - Action: 파생 정본을 하나로 합치고 가드를 census × {정상, 적대} 로 모수화하라.

### 3. Challenge to current spec

「(c) 로 정상 문구를 걸러도 손실이 없다」는 전제가 두 지점에서 깨진다 — 대체값이 원문에 없던
내부 스키마·파일명을 **새로 노출**하고(순수 확대), 원문이 인자에 없던 사실을 담고 있었다면
복구 불가하게 소멸한다. 불변식의 이름도 틀렸다: 요구는 「도구 구문처럼 보이지 않을 것」이
아니라 「내부 식별자·기계 표기가 화면에 없을 것」이고, 그래야 정화기 자신의 대체값도 그
불변식의 적용 대상이 된다. 프런트의 무방비를 하네스 `[5]` 로 못박은 것도 재검토가 필요하다 —
서버 단일 실패점이 확정된다.
