# ANCHOR: feature-0043 external-llm-bridge

## §1. 외부 관점 요약

처음 코드를 여는 사람은 이렇게 묻는다. **"AI assistant 인데 서버가 LLM 을 안 부른다고? 그럼 답은 누가 하지?"**

답: 각 사용자의 **개인 머신 AI 런타임**이 한다. 이 서비스는 사내 DB 를 아는 assistant 였고 추론 비용·쿼터가
전부 우리 것이었다. 계정 2개(`claude-corp` · `root`)로 버텨 왔지만 2026-08-07 에 claude-corp 7일 쿼터가
100% 소진돼 서비스가 멈춘 적이 있다. 계정을 늘리는 대신 **추론 주체를 뒤집는다** — 우리는 도구·컨텍스트·
데이터만 주고, 추론은 각자의 Claude 구독이 돌린다. feature-0041 이 그 표면을 이미 만들어 뒀고,
본 feature 는 그것을 **주 경로로 승격**하면서 서버 LLM 을 fail-closed 로 잠근다.

두 번째 의문: **"웹 대화창은 왜 남기지? MCP 로만 쓰면 되잖아."** 사용자 결정(2026-08-26)이다 —
익숙한 진입점을 없애지 않고 경로만 바꾼다. 웹 질문은 서버 LLM 으로 가지 않고 **대기 작업**이 되고,
그 사용자의 개인 머신 AI 가 MCP 로 가져가 답하고, 답이 같은 대화창에 돌아온다.

세 번째 의문: **"서버가 사용자 머신 LLM 을 직접 부르면 되지 않나(MCP sampling)?"** 안 된다.
sampling 은 프로토콜 `2026-07-28` 에서 **폐기**됐고(SEP-2577 — *"New implementations SHOULD NOT
adopt it"*), Claude Code 는 미지원이다(anthropics/claude-code#1785, 2025-06-08 이래 open).
그래서 push 가 아니라 **도구 기반 pull** 로 뒤집는다 — 표준 tools 만 쓰므로 클라이언트 호환성 문제가 없다.

## §2. 대안 분기

- **Alt-A: MCP sampling(`sampling/createMessage`) 으로 서버가 클라이언트 LLM 을 push 호출.** 페르소나:
  "웹 UX 를 한 글자도 안 바꾸고 비용만 옮기고 싶은" 팀. 안 고른 이유: 스펙에서 폐기된 기능이고
  (12개월 후 제거 가능), Claude Code 가 구현하지 않았다. 채택하면 **오늘 당장 동작하지 않고**
  내일 제거될 기능 위에 제품 주경로를 얹게 된다.

- **Alt-B: BYOK — 사용자별 API 키를 서비스가 보관하고 서비스가 호출.** 페르소나: 즉답 UX 를 지키려는 팀.
  안 고른 이유: ADR-0026 과 feature-0041 ANCHOR §2 Alt-B 가 이미 폐기한 결정(자격증명 보관 책임 부활 +
  prompt cache 파편화로 총비용 상승). 게다가 구독이 아니라 **종량 API 키**가 필요해 "비용 이전"이 아니라
  "비용 신설"이 된다.

- **Alt-C: 계정 증설 — claude 계정을 N개로 늘려 쿼터를 키운다.** 페르소나: 변경 최소를 원하는 운영팀.
  안 고른 이유: 회전·소진 운영 부담이 N배가 되고 근본 구조는 그대로다. 2계정으로도 이미 겪은 부담이다.

- **Alt-D: 웹 대화창 폐지, MCP 전용.** 페르소나: 표면을 줄이려는 팀. 안 고른 이유: 사용자 결정으로
  기각(2026-08-26) — 익숙한 진입점을 유지한 채 경로만 바꾼다. 다만 기술적으로는 가장 단순했다.

### §2.1 pull 브리지의 알려진 한계 (수용된 트레이드오프)

feature-0041 ANCHOR §2 Alt-D 가 역방향 호출을 기각하며 지적한 **"사용자 로컬 런타임은 상시 도달
가능하지 않다"** 는 본 설계에서도 해소되지 않는다. 해소한 것은 그 옆의 문제(자격증명 보관)뿐이다.
개인 머신 AI 가 꺼져 있으면 답변은 오지 않는다. 이를 숨기지 않고 **대기 상태로 정직하게 표시**하는 것이
본 feature 의 UI 계약이다 — "곧 답이 온다"고 가장하지 않는다.

## §3. 가정된 사용 시나리오

DBA 팀 김 과장이 아침에 자기 PC 에서 Claude Code 를 켜고 브리지 러너를 상주시킨다(한 번 설정하면 끝).
낮에 브라우저에서 평소처럼 assistant 대화창에 "어제 KR 라이브 신규 가입자 추이" 를 묻는다. 화면에는
즉시 "내 AI 가 처리 중" 이 뜨고, 자기 PC 의 Claude 가 MCP 로 질문을 집어가 `describe_table` ·
`execute_sql` 로 조사한 뒤 답을 올린다. 답은 같은 대화창에 렌더되고 기록은 서비스에 남아 나중에
팀이 열람한다. 토큰은 김 과장의 구독에서 나가고, 회사 계정 쿼터는 한 톨도 쓰이지 않는다.

점심에 PC 를 끄고 나가면 그동안의 질문은 "대기 중" 으로 쌓여 있다가, 돌아와 러너를 켜면 처리된다.
급하면 자기 Claude Code 에서 직접 `list_open_requests` 를 불러 그 자리에서 답하게 할 수도 있다.
