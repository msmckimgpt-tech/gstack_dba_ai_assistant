## 발표자 전용 Q&A 대비 (청중 비노출)

> 청중 슬라이드에는 내부 식별자·근거 코드가 없다. 상세 근거는 EVIDENCE.md.

**Q. "배포 완료"라면서 라이브 배포는 안 했다는 게 무슨 뜻인가?**
- 이 자료의 "배포/검증 완료"는 전부 **검증 환경(로컬→QA)** 기준이다. 기능·보안을 그 환경에 올려 검증까지 마쳤다는 뜻. **프로덕션 라이브 배포(라이브 DB 접근·실사용자)는 이번 기간 미진행** — 보안 결정 2건 대기(구글 드라이브 접근 / 라이브 DB 접근 범위). 현재 연결은 로컬→QA. (U-020)

**Q. 왜 라이브 배포를 안 했나, 준비가 안 됐나?**
- 준비가 아니라 **결정**의 문제다. ① 사내 계정 구글 로그인으로 드라이브에 접근할지, ② 복제본 구성이 제한된 상태에서 라이브 DB에 직접 접근할지 — 이 두 보안 결정이 내려지면 즉시 전환한다.

**Q. DB 복제본은?**
- 부하분산용 IDC·웹DB 복제본을 계획했으나 **환경 제약으로 미구성**. 대신 **참조에 필요한 메타데이터만 내부에 구축**했고, 그 산물이 관계도 지도(23,465 객체)다. (U-021)

**Q. 구글 드라이브는 쓸 수 있나?**
- 아직 아니다. MCP 연동 **기능 토대(스캐폴딩)만** 만들었고 **실제 서비스에는 통합되지 않았다**. 어시스턴트 답변 경로에 미편입. 서비스 편입·사내 계정 접근 허용은 결정 대기(U-022). "연결 완료"가 아니라 "토대 구축"으로 말할 것.

**Q. 공유 대화·관계도 지도를 왜 '신규'라고 하나, 예전부터 있지 않았나?**
- 개발은 이번 범위 안에서 이뤄졌고(공유 07-04·관계도 06-30, 사용자 지정 baseline 5/19~6/17 이후), 무엇보다 **상부보고에서 이번에 처음 공개**하는 기능이다(이전 보고 미언급, 사용자 확인). 그래서 청중 관점 '신규'로 표기했다.

**Q. 보안 6종은 실제로 적용됐나?**
- 6종 모두 **개발·검증 환경 검증 완료**(SECURITY 정본 §12~16 등). 로그인 제한·2FA·인젝션 방지·공유 만료·사용량 한도·감사 변조방지(해시 체인). **프로덕션 적용은 라이브 배포 시점**에 함께. (E-021, U-020)

**Q. "23,465개"·"18개"·"6종"·"60fps"·"0회"는 믿을 수 있나?**
- 18개=고유 기능 영역 토큰(검증 가능·활동강도 아님). 6종=SECURITY 정본+06-19 배치(검증됨). 23,465=검증 환경 서버측 파이프라인+밴드 렌더. 60fps=검증 환경 실 Windows **약 409객체**(실 규모 아님, U-016). 0회=검증 환경 부하 시험(단일 호스트, 프로덕션 SLA 아님). 229 작업·521 PR=개발 이력 집계.

**Q. 답변 자가검증이 실제로 효과가 있나?**

**Q. 렌더 엔진 왜 바꿨나, 게임 엔진은?**
- 이전 엔진은 매 프레임 CPU 재래스터 → 대규모 팬 60fps 구조적 불가. 게임 엔진은 이득 원천(GPU 상주)이 웹 표준으로도 얻어지는데 부담만 커 기각. (E-012, C-2)
