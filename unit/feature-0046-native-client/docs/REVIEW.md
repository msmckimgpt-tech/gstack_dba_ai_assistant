## REV-20260903T234500-ai-claude-fingerprint [CODEX:core.py 지문 비교] — ACCEPTED
- Timestamp: 2026-09-03T23:45:00+09:00
- 도구: `codex exec -s read-only` (codex-cli 0.152.1). ⚠ **첫 호출은 10분 무응답이었다** —
  여러 줄 코드 블록을 `$(cat file)` 로 실어 보낸 것이 원인이었고, 원인을 먼저 진단하라는
  사용자 지시에 따라 최소 프롬프트로 가르니 **4초**에 응답했다. 프롬프트를 3줄로 줄여 재요청.

**지적 3건과 처리**

1. `split()` 이 위치 무관하게 모든 공백을 지운다 — **의도**다. 사용자가 웹에서 값을 복사해
   붙이는 경로가 있고, 표기 변형을 흡수해도 **다른 값이 통과하지는 않는다**. 불채택.
2. `:`·`-` 를 개수·위치 제한 없이 지운다 — 같은 이유로 불채택.
3. **정규화 후 `^[0-9a-f]{64}$` 를 검증하지 않는다 — 채택.** 이것이 실질적이다.
   기대값이 `":"` 이면 truthy 라 `if plan.ca_sha256` 가드를 통과하고, 정규화 후 `""` 가 된다.
   계산값도 `""` 라면 **둘이 같다고 판정된다.** 지금 계산 경로(`hashlib`)는 항상 64자를
   내므로 도달 불가능하지만, **무결성 검사가 「우연히 도달 불가」에 기대는 것은 옳지 않다.**
   → `fingerprints_match()` 신설, 두 호출부 모두 경유. 테스트 10건 추가.

**뮤테이션 13종 중 11 KILL · 2 생존 — 생존 2건은 등가 뮤턴트다(구멍이 아니다).**

- `F8 형식 검증을 한쪽만(a 만)`: `_HEX256.match(a)` 를 통과하고 `a == b` 가 성립하면 `b` 도
  반드시 유효하다. `b` 검사는 **결과를 바꿀 수 없다**. 대칭성을 위해 코드에는 남긴다.
- `F6 return a.startswith(b)`: 형식 검증이 양쪽을 **정확히 64자**로 강제하므로, 같은 길이
  문자열에서 `startswith` 는 `==` 와 동치다. → 즉 **codex 지적을 반영한 형식 검증이 이 뮤턴트를
  등가로 만들었다.** 반영 전이라면 잘린 지문이 통과했을 것이고, 그때는 진짜 구멍이었다.

등가 뮤턴트를 죽이려고 테스트를 더 쓰지 않는다 — 죽일 수 없는 것을 죽이려 들면 구현을
그대로 베낀 테스트가 되고, 그것은 회귀를 잡지 못한다.
