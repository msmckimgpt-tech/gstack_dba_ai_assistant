## 0-A. 핵심 프레이밍 (정직성 — 사용자 확인 2026-09-02)

### (1) 배포 상태 — 이 보고의 "완료"가 뜻하는 것

- **실사용자 대상 라이브(운영) 환경 배포는 아직 이루어지지 않았다.** (사용자 명시, 2026-09-02)
- 이 범위의 모든 작업은 **개발·검증 환경에 배포되어 실측**됐다. 제품 릴리즈노트 본문의
  "배포된 서비스에서 확인했습니다"는 **그 개발·검증 환경 배포본**을 가리킨다 — 라이브 운영
  환경이 아니다.
- 따라서 본 보고에서 **"완료" = 개발 완료 + 검증 환경 실측**이며,
  **라이브 운영에서의 효과·안정성은 전부 미측정**이다. 덱·스크립트 전체가 이 한정을 따른다.

> **직전 보고(2026-08-25 v1)와의 차이 — 정정 기록.**
> 직전 원장 §0-A 는 당시 사용자 확인에 따라 "서비스는 이번 기간 이전부터 실사용 중"이라
> 적었다. 2026-09-02 사용자 확인으로 **라이브(운영) 환경 배포는 미실시**임이 명확해졌으므로,
> 본 보고는 그 기준을 따른다. 두 기술의 정합 해석 = 지금까지의 사용은 **개발·검증 환경 범위**다.

### E-005 · 87분 대기의 원인 규명과 회수 상한 재설계
- **kind**: release-note(2026-09-01) · unit-doc(feature-0043)
- **ref**: 한 대화에서 질문 1건에 87분 대기. 그중 **1시간 넘게는 아무도 그 질문을 볼 수 없던 구간**
  — 개인 머신 프로그램이 재기동되면 자기가 이미 집어 간 질문이 30분간 자기 자신에게도 안 보였다.
  조치: 켜질 때·꺼질 때 보유 질문 즉시 반납 → **30초 안팎 재회수**. 화면도 '가져갔다'와
  '진행하고 있다'를 분리 표시.
- **status**: 확인 (개발 완료 · 검증 환경 실측)
- **note**: **측정 조건 분리** — "1시간+ → 30초"는 *미회수 질문의 재회수 가능 시점*이지
  *답변 소요 시간*이 아니다. 답변 자체의 소요는 개인 AI 성능에 좌우되며 본 보고 범위에서 미측정.

## 2. 확인 필요 (근거 부족·불일치·단정 위험 — "발전 과제"로 발표)

### U-001 · 라이브(운영) 환경 배포와 그 효과
- **왜 확인필요**: 배포 미확인 — 실사용자 대상 라이브 배포가 **아직 이루어지지 않았다**(사용자 확인 2026-09-02).
- **가진 것 / 없는 것**: 있음 = 개발 완료 + 검증 환경 배포·실측 기록 다수 · QA 파이프라인 설계 rev.3.
  없음 = 라이브 배포 실적 · 라이브 부하에서의 안정성 · 실사용자 규모에서의 체감.
- **확인 방법(제안)**: D-2 순서대로 ① DB 복제본 구성 ② QA 환경 구축·승격 검증 ③ 라이브 분리 배포.
  각 단계의 게이트 통과 기록을 다음 보고의 근거로 삼는다.

### U-002 · 라이브/운영 DB 접근 범위
- **왜 확인필요**: 사람 결정 대기 — 직전 보고부터 이월. D-2 로 **순서**(QA → 라이브)는 확정됐으나
  접근 범위 자체는 미결.
- **가진 것 / 없는 것**: 있음 = 조회 전용 가드·부하 게이트·감사 원장. 없음 = 어느 운영 DB 를 어느 범위까지
  열지에 대한 결정.
- **확인 방법(제안)**: 보안·운영 담당과 대상 DB·계정 권한·감사 요건을 표로 확정.

### U-003 · 밖의 AI 도구 연결의 인증 이후 구간 종단 확인
- **왜 확인필요**: 사람의 브라우저 인가 1회가 필요해 자동 검증으로 닫히지 않는 구간 1건이 남아 있다.
- **가진 것 / 없는 것**: 있음 = 배포 후 점검 10회 전건 통과 · 익명 차단 실측. 없음 = 인가 이후 종단 왕복 1건.
- **확인 방법(제안)**: 담당자 1인이 실제 브라우저로 인가 1회 수행 후 종단 왕복 기록.

### U-004 · 답변 품질·응답 속도의 실제 개선폭
- **왜 확인필요**: 수치 미측정. 정직성 규칙·자체 점검·지식 도달(1층→5층)·성능 1차 개선은 **개발·배선까지**
  확인됐고, 그것이 답변 품질/속도를 얼마나 바꿨는지는 재지 않았다.
- **가진 것 / 없는 것**: 있음 = 전환 이전 구조의 병목 지도(E2E 평균 141초 분해) · 전달 여부 전후 대조.
  없음 = 개선 후 E2E 재측정 · 품질 평가 기준·표본.
- **확인 방법(제안)**: 대표 질문 세트를 고정해 전/후 동일 조건으로 소요·정확도 측정.
  **주의**: 전환 이후에는 답변 소요가 개인 AI 성능에 좌우되므로 측정 설계에 그 축을 넣어야 한다.

### U-005 · 사용자 컴퓨터에서만 확인되는 항목
- **왜 확인필요**: 검증 환경에서 닫히지 않는 구간이다. 릴리즈노트가 항목마다 그 사실을 명시하고 있다.
- **대상**: 중단 후 이어 묻기 왕복 · 실패 사유가 실제 화면에 뜨는 것 · 예전 프로그램의 자가 종료 ·
  두 프로그램 실제 경합 · 파이썬 대신 설치 · 긴 조사 완주 · 잠금 해제 왕복 · 연결 3경로 완주 ·
  새 프로그램 내려받기→실행 왕복.
- **확인 방법(제안)**: 담당자 2~3인이 각자 환경(Windows / WSL / macOS)에서 체크리스트 1회 왕복.

### U-006 · 관계도 확장분의 라이브 시각검증과 대규모 체감
- **왜 확인필요**: DB 객체 확장(트리거·자동 실행 작업·뷰 등)은 **코드·단위검증까지만** 완료이고
  라이브 시각검증·배포가 미수행이다. 카테고리 정리의 효과(과세분화 감소·배치 개선)도 미관측.
- **확인 방법(제안)**: 배포 후 실제 브라우저로 객체 유형별 표시·필터·상세 확인 + 전후 스크린샷 대조.

### U-007 · 회의 결정 3건의 문서 정본화

## 7. v2 어조 개정 기록 (2026-09-02)

### 7.1 지적

사용자 검토 — **"«지금 결정해 주시면 다음 기간에 바로 착수합니다» 와 같은 어조는 진척 보고
발표에 구성되기에 적절하지 않다. 청중 입장에서는 마치 선택을 강요하는 것과 같이 느껴진다."**

### 7.2 진단

발전 과제(`#risk`)·마무리(`#outro`)·범위(`#scope`)·라이브 경로(`#feat-qa`) 네 슬라이드에서
미결 항목을 **«요청»의 문법**으로 서술하고 있었다. 진척 보고의 화행(speech act)은 **보고**이지
**요청**이 아니므로, 같은 사실을 **현황·선행 조건 기술**로 바꾼다. **내용은 그대로 두고 어법만 교체**했다.

### 7.5 유지한 것 (과교정 방지)

- **미결·리스크를 숨기지 않는다** — 8개 과제 표, 확인 단계 5행 표, «라이브 배포 미실시» 고지,
  «일부러 열어 둔 위험»은 **전부 그대로**다. 어조를 부드럽게 한다는 이유로 정직성을 낮추지 않았다.
- **선행 조건의 구체성도 그대로**다 — 장비 2대·리드타임·그래픽 장비 불요·협의 대상까지 명시한다.
  듣는 쪽이 판단하는 데 필요한 정보를 빼면 그건 어조 개선이 아니라 정보 누락이다.
