**Q3 (high) — 자격 게이트가 SQL 문자열 assertion 으로만 검증돼 조건 무력화를 못 잡고, `root_key` 축(같은 scope 문자열을 품음)은 한 번도 단언되지 않는다**
- **Evidence**: `test_eligibility_requires_majority_success` 는 `assert "done > 0" in sql and "done * 2 >= enqueued" in sql` 뿐이고, FakeCursor 는 SQL 을 평가하지 않고 `"root_label='Schema' AND status='done'"` 부분문자열 매칭만으로 `(1,)` 을 돌려준다(`:53-56`, `:135-138`). `test_eligibility_matches_scope_case_variants` 는 `params[0]`, `params[1]` 만 단언하고 `params[2]`(= root_key = schema_key)는 검사하지 않는다. `test_running_auto_run_is_busy_not_appended:216` 의 `assert not _sql_of(cur, "SET enqueued = enqueued + %s")` 는 이 함수가 어떤 변형에서도 만들지 않는 문자열이라 사실상 동어반복이다.
- **Location**: `unit/feature-0002-agent-core/tests/test_node_analysis_change_reanalysis.py:174-191`
- **Reason**: (a) 과반 조건을 `AND (done * 2 >= enqueued OR TRUE)` 로 바꾸는 무력화 변형은 두 부분문자열을 그대로 남기므로 전 테스트를 통과한다 — B3 흡수는 회귀 방어가 없다. (b) `root_key=%s` 는 대소문자 방어 없는 단일 등가 매칭인데, 자동 경로의 `schema_key` 는 `f"{get_active_datasource()}:{_rel_store_schema}"` 이고 `set_active_datasource` 가 key 를 **강제 소문자화**한다(`shared/config.py:508`). 반면 수동 run 의 root_key 는 라우터가 프론트에서 받은 그래프 노드 key 를 `.strip()` 만 하고 저장한다(`unit/feature-0003-agent-web-ui/src/routers/admin_metadata.py:1940`). scope 축에는 `IN (원형, 소문자)` 방어를 넣고 정작 그 scope 를 문자열로 품은 root_key 축에는 넣지 않아, 두 파생이 한 글자라도 어긋나면 기능이 **100% 침묵 사망**한다. 그리고 그때 남는 신호는 정상 상태("아직 전체 분석 안 한 DB")와 구분되지 않는 `ineligible` 하나뿐이라, 운영자가 오작동을 인지할 방법이 없다.
- **Action**: (a) `root_key` 도 scope 와 동일한 대소문자 정합을 적용하거나 schema_key 파생을 한 함수로 단일화하고, `params[2]` 를 단언하는 테스트를 추가한다. (b) 과반 조건은 문자열이 아니라 행 판정으로 검증 — FakeCursor 를 `(done, enqueued)` 후보 행에 대해 조건을 실제 평가하는 소형 evaluator 로 바꾸거나 PG 통합 테스트 1건을 둔다. (c) `ineligible` 을 "이력 없음"과 "이력 있으나 과반 미달"로 분리 계측해 침묵 사망을 관측 가능하게 만든다.

### 3. Challenge to current spec

**backend 리뷰 흡수 자체는 실질적이다.** B1(감지원을 `table_fp` → 전용 구조 스냅샷으로 재설계), B2(append 제거 → busy no-op), B6(`or "common"` 폴백), B7(`enqueued` INSERT 확정값 + 행 단위 try/except + 시드 0 시 run DELETE)은 코드에서 실제로 확인된다. `test_worker_parallelism.py` 수정도 **정당하다** — `test_performance_group_registered` 가 `keys == PERF_KEYS` 로 집합 등가를 요구하므로 스펙 추가 시 갱신이 강제되는 구조이고, `test_exposed_knob_defaults_track_config` 에 두 knob 을 넣은 것은 검증을 **약화가 아니라 강화**한다(실패 무마 아님). 다만 `snap` fixture 의 `delenv` 목록에 신규 2 knob 이 빠져 있어 배포 env 가 설정된 환경에서는 격리가 불완전하다(nit).

**남는 설계 이슈 1 — 자격 기준이 "전체 분석"이 아니라 "과반 성공한 아무 run"이다.** `done*2 >= enqueued` 는 B3 의 1/500 케이스는 막지만, 수동 경로가 `only_missing=True` + `SCHEMA_CAP`(기본 200) 절단이라 2000 테이블 DB 에서 200개만 분석한 run 도 `enqueued=200, done=200` 으로 자격을 만든다. 즉 10% 만 분석된 DB 가 "'DB 전체 AI 능동 분석'이 이루어진 DB"로 인정된다. 원 리뷰 권고인 커버리지 기준(`get_scope_analysis_status().done_keys` 가 그 스키마 Table 노드의 일정 비율 이상)이 더 정직하다. 아울러 자격은 여전히 **취소 불가**다 — 스키마별 opt-out 이 없어 "이 DB 는 자동 분석 끄기"를 사용자가 선택할 수 없다.

**남는 설계 이슈 2 — 오작동의 관측 신호가 오작동과 정상을 구분하지 못한다.** 라이브에서 이 기능이 (a) 침묵 사망(Q3 의 root_key 불일치)하면 신호는 `ineligible` 뿐인데 이는 "아직 전체 분석 안 함"과 동일 값이고, (b) 오탐 폭주(Q2 의 스냅샷 wipe)하면 wipe 사이클 자체는 무음이고 다음 사이클의 `auto_reanalysis_candidates` 급증만 남는데 이는 진짜 대량 DDL 과 구별되지 않는다. 두 경우 모두 운영자가 "정상인가 고장인가"를 판정할 수 없다. 최소 개선: `ineligible` 사유 분리 계측, 스냅샷 축 drop/wipe 전용 카운터(`..._axis_dropped`), 그리고 자동 run 의 누적 노드 수·비용을 admin usage 에서 `root_label='SchemaAuto'` 로 분리 조회 가능하게 하는 것.

**POST-DEPLOY 계획은 오탐 축을 빠뜨리지 않았다** — TEST.md TCR.11 첫 항목이 "구조를 전혀 바꾸지 않은 상태로 최소 2 사이클 → candidates=0 · SchemaAuto run 미생성"을 **최우선**으로 두고 shadow 1 사이클 옵션까지 명시한다. 이 부분은 리뷰 challenge 를 정확히 흡수했다. 다만 계획에 두 가지를 추가해야 한다: (1) 2 사이클이 아니라 **루틴 introspect cadence(`rel_maintenance_due`)를 최소 1회 넘기는 구간**까지 관측해야 축 첫 활성화 오탐이 드러난다, (2) 권한/목록 공백 시나리오 — 대상 스키마에서 계정 권한을 좁히거나 빈 스키마 상태를 1 사이클 통과시킨 뒤 다음 사이클 candidates 가 0 인지 확인(Q2 의 직접 검증). 문서 nit: TASK.md TCR.2 는 "⑤ run 생성/**append**"라는 구설계 문면이 남아 있고 §비용경계 3 은 D4 를 "아래 D3"로 잘못 참조한다.

**shadow 를 기본으로 한 사이클 돌리는 편이 여전히 더 안전하다.** 코드에 `shadow` 3-state 가 들어왔지만 `AGENT_NODE_ANALYSIS_AUTO_ON_CHANGE_MODE` 는 `runtime_settings` 미등록이라 shadow 전환·해제에 재배포가 필요하고, `_auto_enabled()` 는 `AGENT_NODE_ANALYSIS_AUTO_ON_CHANGE`(shadow → True)만 보므로 `enqueue_change_analysis` 자체는 shadow 를 모른다(현재는 insight 호출부만 게이트). 기본 ON 으로 나가려면 최소한 shadow 도 콘솔에서 토글 가능해야 하고, 그렇지 않다면 첫 배포는 shadow 로 나가는 것이 이 규모(스키마 전량 × datasource 수)의 무승인 지출에 맞는 기본값이다.
