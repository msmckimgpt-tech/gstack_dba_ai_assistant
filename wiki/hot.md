## Key Recent Facts
- **위임된 콘솔 작업의 결과는 `bridge_pending` 봉투 + 폴링으로 온다 — SSE 가 아니다** (09-09). 게이트가 닫힌 배포에서 '자동 작성' 3진입점(프로필 내 프롬프트 · 관리 콘솔 역할/제품)은 개인 AI 로 위임되고 서버는 `{"bridge_pending":true, poll_url, task_id}` JSON 을 준다. 화면이 그것을 모르면 **200 을 받고도 조용히 버린다**(라이브 09-08: 작업 적재·러너 제출까지 정상, 화면만 무반응). 판정 단일 지점은 `static/console-job-poll.js`(**의존 0** — `admin/llm-state.js` 는 `adminState` 를 import 해서 관리 콘솔 밖에서 못 쓴다, 그것이 원래 결함의 뿌리다). ⚠ 폴링 주소는 **프로필 경로**(`GET /api/profile/ai-jobs/{task_id}`, 로그인만·`AccountId` 스코프) — 개인 프롬프트 자동작성은 `console.access` 를 요구하지 않으므로 admin 주소를 주면 그 사용자는 결과를 영영 못 받는다. ⚠ **「제출됐다」 ≠ 「AI 가 해냈다」** — 러너는 실패를 답변 본문에 적어 제출하므로(대화 축에서는 옳다) 서버가 고정 꼬리표(`RUNNER_DEGRADED_NOTICE`)로 `degraded` 를 표시하고, 폼 축은 그때 본문을 덮지 않는다.
- **서비스의 주 사용 표면은 일반 웹브라우저가 아니라 DQA 앱이다** (09-08, 사용자 직접 지시 · ADR-20260908T024500). 정본은 `docs/PROJECT.md` 의 `primary_ui_surface: dqa-client` + AGENTS §15.4.1·§16.6 + **PB-0009**(`playbooks/PB-0009-dqa-client-verification.md`, 신규)다. ⚠ **PB-0008 은 폐기가 아니라 «보조 호환 경로»로 재범주화**됐다 — UI 변경의 완료 게이트는 실제 앱 화면·로컬 브리지·해당 사용자 동작이고, 별도 브라우저 기동을 매번 요구하지 않는다. ⚠ 브라우저·Node·CLI PASS 를 **앱 전체 PASS 로 합산하지 않는다**. 기존 Windows-browser Run 이력은 삭제하지 않고 실제 대상에 따라 해석한다.
- **외부 AI 가 쓸 수 있는 조회 도구가 7종에서 12종이 됐고 「영구 제외」라는 말이 폐기됐다** (09-08, 정본 `unit/feature-0003-agent-web-ui/docs/TOOL_SURFACE_AUDIT.md`). core 정적 15 + 조건부 6 중 외부 dispatcher 가 **7개만** 제공하던 것에 `search_routines`·`describe_routine`·`search_db_objects`·`describe_db_object`·`explain_query` **5종을 연결**했다(사용자가 본 증상은 `search_routines` HTTP 404). 나머지 9종은 **대체 경로와 제한 사유를 명시**한다 — `get_sample_rows`→`execute_sql` 의 제한된 SELECT · `check_table_coverage`→`read_task_attachment`+`describe_schema` · `graph_navigate`→제품 범위 `get_task_context(focus=…)` · 첨부 계열은 웹 task 전용 경로(읽기 `read_task_attachment` · 저장 `attachment-edit`+`submit_answer`). ⚠ 목록은 `get_tool_catalog` 와 claim/`get_task_context` 의 `tool_catalog` 가 **런타임에 알려 준다**(인자 규격·SQL 활성 상태 포함) — 새 core 도구는 자동 공개되지 않는다(명시 allowlist). MCP 는 `run_read_tool` 이 서버 catalog 를 확인한 뒤 전체 인자를 전달한다.
- **공유 링크는 «열람 = 브라우저 / 참여·fork = DQA 앱» 으로 갈린다** (09-08, 사용자 결정 「앱 전용 + 받기 안내」·「집행은 프런트 유도까지」). 브라우저 화면엔 `[링크 복사]` 와 `[DQA 앱에서 참여 · fork]` 뿐이고 직접 실행 버튼은 **앱 창 안에서만** 뜬다(웹 로그인 링크는 **제거** — 웹에서 로그인해도 누를 버튼이 없어 그 자체가 막다른 길). 판정 신호는 브리지 좌표 하나(`window.__dqaClientBridge` ← `share-client-context.js` 가 정본 `app/client-bridge.js` 를 import 해 얹는 **어댑터**). 딥링크는 **서버가 정본으로 조립**(`dqa_identity.app_open_url` → `dqa-connect://open?path=/share/<token>&base=…`)하고 **토큰을 싣지 않는다** — 앱 창은 브라우저 세션으로 인증되므로 베어러를 더 실으면 노출만 는다(연결용 `scheme_url` 과 **다른 축**이라 함수를 나눴다). ⚠ **표시이지 집행이 아니다** — 서버 join/fork 게이트는 무변경이고, 우회로 얻는 것은 권한이 아니라 «어느 화면에서 눌렀는가» 뿐이다. ⚠ 경로 검증(`safe_app_path`)은 **조립·수용 양쪽**에 사본으로 있고 테스트가 같은 표로 대조한다 — base 만 검사하면 `path=//evil/x` 가 **protocol-relative** 로 남의 origin 을 앱 창에 띄운다. 부적격이면 **키만 버려 루트로 열화**(구버전 degrade 와 같은 형태). ⚠ **클라이언트 재배포 전까지 목적지 이동은 성립하지 않는다.**
- **연결하는 길은 «DQA 앱» 하나다** (09-07, 사용자 결정 「그냥 전면 제거」) — 「연결 준비」 버튼·터미널 1단계(OS 탭·명령·복사)·AI 지시문 두 갈래·토큰 경고가 **두 화면(대화 모달 · `/ai/connect`)에서 함께** 사라졌다(한쪽만 지우면 링크를 새 탭으로 연 사용자가 옛 화면을 본다). ⚠ **접은 것이 아니라 지웠다** — 「터미널은 접힌 보조 경로」로 적힌 서술은 전부 낡았다. 토큰은 **여전히 발급되고 그리지 않을 뿐**이며(스킴 URL 로 곧장 전달) 그래서 「닫으면 지운다」가 「애초에 넣지 않는다」로 **강해졌다**. 실행 URL 은 **창을 열 때** 미리 받는다(`_offerLaunch` — 클릭 시점에 발급하면 그 앞에 `await` 가 생겨 사용자 활성화가 끊기고 크롬이 스킴 이동을 조용히 거른다 · 자격은 서버가 아는 연결 이력 `last_os`). ⚠ 서버는 아직 `handoff`·`launch` 를 만들어 보낸다(되돌릴 자리). ⚠ **대가**: 앱을 못 받았고 서버가 배포본도 못 내놓으면 **연결할 길이 없다** — 사용자가 알고 고른 결정이다.
- **로컬 LLM 은 전면 폐기됐다 — 활성 `model_name` 이 0개다** (09-07). `local-llm-edge`/`local-llm-gateway` 컨테이너 · 모델 16GB · `embed-ollama` 서비스 · `titan-embed` alias · `edge-fallback` 정의 · `check-llm-network` 게이트가 전부 사라졌다. 폐기 근거는 실측이다 — 7일 로그 77,789줄 중 추론 `POST` **0건**(전량 healthcheck) · RSS 31.5MiB(모델 미로드). ⚠ **라이브에서만 열려 있던 fail-open 3경로**가 같이 닫혔다: `.env` 의 `LOCAL_LLM_API_BASE` 를 읽던 `_LOCAL_LLM_ENABLED` 가 **라이브에서만** 로컬 alias 를 카탈로그에 넣었고 **테스트 환경은 env 미설정이라 정반대를 단정하며 통과**했다. KB 검색은 죽지 않았다 — `kb_retrieval` 2-tier 로 `pg_trgm` 강등(기존 임베딩 154,365행·bge-m3 볼륨 **보존**). `bedrock-gateway` 철거는 **범위 밖**(feature-0020 무중단 배포 machinery 에 배선 — ADR-20260907T175000).
- **KB 검색은 이제 「문자 후보 + 외부 AI 판단」이다** (09-07, ADR-20260907T185500). 서버가 `pg_trgm` 으로 후보를 찾아 `claim_request.kb_context`·`get_task_context(focus=…)` 로 전달하고 **의미 적합성 판단·질문 재구성은 외부 AI 가 한다** — 새 임베딩 API 는 도입하지 않는다. 샘플은 제품+common 의 **승인·active** 행만, **벡터 NULL 도 검색된다.** MySQL 인사이트는 엔진 포함 endpoint hash + 제품 허용 DB 로 제한하고 **MSSQL 레거시는 catalog 출처 불명이라 원문 검색에서 제외**(구조 도구 안내). ⚠ **의미검색과 동등하지 않고 무매칭은 부재의 증거가 아니다** — 그 고지가 계약의 일부다.
- **모델 목록의 1차 출처는 CLI 자체 카탈로그다** (09-07) — `codex debug models`(실측 0.23초 · 토큰 0 · 로그인 무관). 종전엔 능력 질의가 22.7초에 `models: []` 를 주고 열거·확인이 전부 타임아웃인데 **협상이 기동 1회뿐**이라 목록이 영영 오지 않았고 화면은 「확인하는 중입니다」였다. `_probe` 순서는 **카탈로그 → 캐시 → 확인 → 열거 → 원장**이고, 확인된 목록을 얻을 때까지 배경 재시도한다(60→900초 · 표시 중 3600초). ⚠ 카탈로그 상한 **8MB** — 실측 출력이 413,777바이트라 종전 probe 상한 256KB 로는 **한 번도 성공한 적이 없었다**. 전부 실패하면 원장을 표시하되(`baseline_as_caps`) **건강 축은 건드리지 않는다.**
- **터미널 없이 연결하는 Windows 네이티브 클라이언트가 있다** — feature-0046(신규, 2026-09-03). `bridge_setup.ps1` 이 하던 일을 **같은 계약·같은 중단 지점**으로 수행하고 껍데기만 GUI — **3단**(기본 = 내장 WebView2 창 → 브라우저 앱 모드 → tkinter 폴백, 2026-09-04). ⚠ **미서명**(SmartScreen 2클릭 감수, 사용자 결정) · **Windows 우선**(macOS 는 경고가 아니라 차단이라 범위 밖) · 배포 형식은 설치 마법사 + **인터프리터** 동봉(러너는 동봉하지 않고 서버에서 받아 sha256 대조 — 동봉하면 배포가 갈린다).
- **「창 닫기 = 트레이로 · 종료 = 아이콘 우클릭 [종료]」는 세 껍데기(내장 WebView2 창 · 브라우저 앱 모드 · tkinter) 공통 계약이다** (2026-09-04). ⚠ 판정은 **닫는 순간** 묻는다 — `Shell.can_hide` 는 bool 이 아니라 `Callable` 이고 정본은 `gui._tray_alive` **하나**다(아이콘은 뜬 뒤에도 죽는다 → 기동 시점 bool 을 들고 있으면 창도 아이콘도 없는 프로세스가 남는다). `Bridge.resident` 는 **읽기 전용 property**(대입 자리 제거 = 구조 가드). 첫 닫기에 `gui.HIDDEN_NOTICE` **1회** — 단 **닫힘을 이벤트로 받는 두 껍데기(내장·tkinter)에만**. 브라우저 껍데기는 `WM_CLOSE` 가 오지 않고, 무신호를 「닫힘」으로 추정하면 **창이 열려 있는데** 안내가 뜬다(패널 ping 은 `initClientPanel` 안에서만 시작 · 배경 탭 스로틀 — codex 2라운드 적발). **없는 근거로 말하지 않는다.** 실측 `tests/windows/verify_embedded_close.py`(hide/quit).
- **클라이언트는 알림 영역(트레이)에 상주한다 — 세 껍데기 공통** (2026-09-04 재구성 · 그 시점엔 웹 셸·tkinter 둘이었고 직후 내장 창이 들어와 내장 WebView2 → 브라우저 앱 모드 → tkinter 3단이 됐다). [X] 로 닫아도 연결 유지, 우클릭 메뉴로 열기·연결 끊기·종료. ⚠ **상주 중에는 유휴가 종료 사유가 아니다**(웹 셸의 수명 신호 = 패널 생존인데, 패널을 닫아 두고 쓰는 것이 상주다). 웹 셸 트레이에 「다시 연결」은 **의도적으로 없다** — 연결 입구는 패널 하나다. ⚠ **트레이 생성 실패 시 그 동작을 켜지 않는다**(닫기=종료 폴백) — 「닫아도 유지」는 아이콘이 **지금 살아 있을 때만** 하는 말이고, 판정은 `tray is not None` 이 아니라 `Tray.alive`(backend 생존)다. `pystray` 불채택(Pillow 동반) — `ctypes`+`Shell_NotifyIconW` 직접.
- **주 표면의 연결 패널은 `app/client-bridge.js` 가 그린다** — `ai-connect.{html,js}` 는 **별도 페이지**다(둘 다 살아 있다). 앱 창은 서비스 루트를 열므로 화면 작업은 「앱 창이 여는 URL 과 그 화면을 그리는 코드」를 먼저 확정한다. ⚠ 그 모듈은 **아무것도 import 하지 않는다**가 성질이다(`connect-modal.js` 가 이 파일을 import 하므로 역방향은 순환) — 필요한 헬퍼는 **지역 정의**하고, 두 `_status` 가 같은 요소를 쓴다는 것을 테스트가 잠근다.
- **GUI 앱이 콘솔 앱 자식을 띄우면 Windows 가 «빈 콘솔 창»을 새로 할당한다** — 사용자가 본 깜빡임의 정체. 정본은 `core.hidden_child_kwargs()` **한 곳**이고 자식을 띄우는 **모든** 함수가 그것을 쓴다. ⚠ 종전에도 가드는 있었다(`spawn_runner` 한 곳) — 없었던 게 아니라 **모수가 좁았다**.
- **로그인은 「위임」이 아니라 「대행 실행」이다** — 벤더 공식 명령을 subprocess 로 띄우고 종료코드만 본다. 토큰 미접촉. 2026년에 3사가 구독 OAuth 제3자 사용을 차단했다.
- **개인 머신 클라이언트의 명칭 축은 넷이다 — 패키징 `APP_NAME`(`DQA Connect`) · 화면에 뜨는 `DISPLAY_NAME`(`DQA`) · 스킴 `dqa-connect` · 역-DNS `com.masangsoft.dqa-connect`** (2026-09-03 개명 + 2026-09-04 `DISPLAY_NAME` 분리, 정본 `shared/dqa_identity.py`). ⚠ 창·트레이·대화상자·바로 가기에 «Connect» 가 남으면 서비스와 별개의 무언가로 읽혀 **보이는 이름만** 바꿨다 — 설치 폴더·`AppId` 까지 바꾸면 업그레이드가 아니라 **두 벌 설치**가 된다. ⚠ 스킴을 `dqa` 로 줄이지 않는다 — URL 에 세션 토큰이 실리고 스킴은 **마지막 등록자 승** 머신 전역 네임스페이스다. MCP 키는 로컬이라 짧게(`dqa`). **하드 컷오버** — 옛 스킴 미등록, setup 재실행이 옛 홈·옛 핸들러를 지운다.
- **연결 상태는 3상태다** — 「모른다」를 「정상」으로 말하지 않는다. ⚠ 다만 **게이트 축의 fail-open 은 의도된 것**(`ai_blocked()` — 조회 실패 시 연결됨으로 간주)이고 표시 축과 별개다. 두 축을 섞어 「fail-open 은 폐기됐다」로 읽으면 오정정한다.
- **브리지 러너의 정본은 `src/agent/` 모듈군(20)이고, 배포되는 단일 파일은 «빌드 산출물»이다.** 소스만 고치면 **배포는 성공하고 러너 다운로드만 404** — 배포 스크립트가 하드 게이트를 건다.
- **KB 근거는 도구 호출이 아니라 «자동 주입»으로 도달한다** — `claim_request` 응답의 `kb_context`/`kb_notes`. ⚠ 배치가 러너 `compose_prompt` 에 있어 **구버전 러너에는 안 실린다**.
