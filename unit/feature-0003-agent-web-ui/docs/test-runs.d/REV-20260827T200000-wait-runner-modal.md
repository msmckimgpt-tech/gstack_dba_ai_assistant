Environment: **Windows-browser 미수행** (relay 불가 — `REV-20260827T000500-bridge-poll-ui.md`)

## 왜 이번엔 특히 실사용이어야 하나

이 변경군의 핵심 주장은 셋이고, 셋 다 **정적 검사로는 참·거짓을 못 가린다**:

1. "질문 전송 즉시 AI 가 인지한다" — 서버가 보류하다 그 순간 돌려주는지는 **시간**의 문제다.
2. "런타임 무관" — claude·codex·gemini·ollama 각각에서 실제로 도는지.
3. "모달이 대화 화면을 떠나지 않게 한다" — 링크 가로채기가 실제 브라우저에서 먹는지.

지금까지 이 feature 의 결함을 실제로 잡아낸 것도 리뷰나 테스트가 아니라 실사용이었다:
`list_open_requests` 500(전 축 단절) · 사설 CA 벽 · "외부 AI 연결" 문구 불통.

## 자동으로 잠근 것 (주장이 아니라 함정 방지)

| 대상 | 검사 |
|---|---|
| 대기 루프 커밋 | 없으면 스냅샷 고정으로 **새 행이 영원히 안 보인다** |
| 대기 상한 | 클라이언트가 못 정한다(정하는 순간 환경 차이) |
| 타임아웃 | 200+`timed_out` — 오류로 주면 호출측이 재시도를 주저한다 |
| 끊김 | `is_disconnected()` — 끊긴 클라이언트를 위해 DB 를 두드리지 않는다 |
| 러너 | sleep 0 · 외부 의존 0 · **정본↔배포본 해시 일치** · 4런타임 · argv 전달 · 실패해도 제출 |
| 모달 | 문서 위임 · **새 탭 의도 존중** · 열고 닫을 때 토큰 DOM 제거 · 단독 페이지 생존 |

`getElementById` 기반 DOM 계약은 **JS 에서 추출**해 검사한다 — 고정 목록은 id 를 지웠을 때
조용히 통과한다(실제로 그런 vacuous pass 를 한 번 겪었다).

## 해소 조건

1. `/ai/connect` 또는 안내 말풍선 → **모달**이 뜨고 연결 정보가 만들어지는가

3. 웹에서 질문 전송 → AI 가 **즉시** 인지하는가(대기 반환 시각)
4. 러너를 띄운 뒤 AI 세션을 닫아도 질문이 처리되는가
