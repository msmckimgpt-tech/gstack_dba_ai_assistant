### Run (2026-09-07) — 패널 자동 연결 — **Environment: host node 실행 하네스**

`client-bridge.js` 를 **가짜 DOM 위에서 실제 import 해 구동**하고, 런타임 목록을 주입해
`connect` 호출이 나가는지·어느 `id` 로 나가는지 관측했다(소스 검사 아님).

| 주입 | 기대 | 결과 |
|---|---|---|
| 플랫폼 하나 | 자동 연결 | ✅ |
| 서로 다른 플랫폼 둘 | 자동 연결(갈림 아님) | ✅ |
| **같은 플랫폼이 두 자리** | 묻는다 | ✅ 연결 없음 |
| 순서 뒤집기 | 같은 선택(고정 순서) | ✅ |
| 답 못한 것 + 하나 | 자동 연결 | ✅ |

- 자동·수동이 **같은 경로**(`doConnect`)를 쓰는지도 잠갔다 — 봉투(`launch.protocol`) 전달 포함.
- `declined` 분기는 **지웠다**(브리지가 묻지 않으므로 도달하지 않는다). 남겨 두면 다음 사람은
  그것을 보고 확인 창이 아직 있다고 읽는다. 주석은 걷어 내고 검사한다.

### Run (2026-09-07) — 라이브 — **Environment: Windows-browser (배포 후로 이연)**

- 정적 자산은 이미지에 baked 되어 배포 후에만 반영된다. 그리고 이 경로는 **클라이언트 안에서만**
  나타난다(패널은 브리지 좌표가 있을 때만 켜진다) — 설치본 재빌드까지 있어야 완주한다.
- 계획: 배포 → 재빌드·재설치 → 앱 창에서 자동 연결·확인창 미발생·트레이 알림 확인.
