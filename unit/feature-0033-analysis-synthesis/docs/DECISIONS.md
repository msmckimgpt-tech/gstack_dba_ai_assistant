# Decisions (feature-local ADR)

## ADR-0033-01 — 클러스터 정체성은 cluster_id 가 아니라 멤버셋 지문
- **결정:** `cluster_summaries` PK 를 `(scope_key, schema_name, member_set_hash)` 로 둔다.
- **근거:** `semantic_cluster_id` 는 pass 마다 MDS 배치 순서로 재부여되어 churn 한다. 좌표를
  키로 쓰면 클러스터 내용이 그대로인데도 매 pass 818개가 캐시 미스 → 전량 재생성된다.
- **결과:** 재배치·재정렬에도 캐시가 살아남는다. `cluster_id` 는 조회 편의로만 저장한다.

## ADR-0033-02 — 라벨 생성기를 확장하지 않고 별 경로를 만든다
- **결정:** `_llm_content_labels` 를 확장하지 않고 `_llm_cluster_summaries` 를 신설한다.
- **근거:** 라벨은 32자·kv 저장·40개 배치 계약이고, 요약은 2~4문장·테이블 저장·6개 배치에
  2중 버전과 커버리지 카운트를 동반한다. 한 함수에 두 계약을 섞으면 둘 다 나빠진다.

## ADR-0033-03 — 캐시 키는 3중(멤버셋 + L1 + L0)
- **결정:** 멤버셋 지문 · 분석문 지문 · 증거 지문이 **모두** 일치할 때만 캐시 적중.
- **근거:** 요약의 입력은 멤버 목록만이 아니라 그들의 분석문과 통계 증거다. 셋 중 하나만 바뀌어도
  요약은 낡은 것이다. 반대로 이 키가 없으면 "분석을 다 다시 했는데 요약은 옛날 것"이 된다.

## ADR-0033-04 — 요약은 클러스터링 시그니처에 유입되지 않는다 (불변식)
- **결정:** 요약 텍스트를 `build_table_signature_text` 에 넣지 않는다.
- **근거:** 유입되면 요약 갱신 → 시그니처 변경 → 재임베딩 → 재클러스터 → 멤버셋 변경 → 요약
  갱신의 **순환**이 된다. 수렴 보장이 없고 비용이 발산한다.
- **강제:** 테스트가 시그니처 빌더 소스에 요약 관련 식별자가 없음을 단정한다(주석 규약이 아니라
  실행되는 검사로).

## ADR-0033-05 — 정렬은 성능이 아니라 정합성 장치
- **결정:** 버전 지문은 정렬 후 해시하고, payload 의 멤버·분석문도 정렬해 넣는다.
- **근거:** 정렬이 없으면 같은 클러스터가 pass 마다 다른 지문을 받아 캐시가 **매번** 미스 난다.
  즉 정렬 누락은 느려지는 문제가 아니라 캐시가 작동하지 않는 문제다.

## ADR-0033-06 — 전량 사전 생성하지 않고 pass 당 40개씩
- **결정:** `_SUMMARY_MAX_PER_PASS = 40`. 큰 클러스터 우선, 동률은 해시 순.
- **근거:** 818콜을 한 pass 에 몰면 백그라운드 토큰 예산(feature-0032)을 즉시 소진해 노드 분석·
  분류 제안이 함께 굶는다. 며칠에 걸쳐 채우는 편이 전체적으로 낫다.
- **정합:** LazyGraphRAG 교훈(사전 전량 생성이 필수가 아니다)과 같은 방향이며, ITEM-08(L3)은
  아예 요청 시 합성으로 간다.

## ADR-0033-07 — 빈약한 응답은 저장하지 않는다
- **결정:** 20자 미만 요약은 버리고 다음 pass 에 재시도한다.
- **근거:** 저장하면 캐시가 적중해 **영원히 그 상태로 굳는다**. 캐시는 좋은 답을 오래 쓰는
  장치이지 나쁜 답을 오래 쓰는 장치가 아니다.

## ADR-0033-08 — 요약 실패는 클러스터링을 막지 않는다
- **결정:** 요약 생성 전체를 try 로 감싸고 실패 시 경고만 남긴다.
- **근거:** 요약은 부가 산출물이다. 클러스터링·라벨 역기록은 그래프 뷰의 기본 동작이므로
  부가 기능의 실패가 그것을 볼모로 잡으면 안 된다.
