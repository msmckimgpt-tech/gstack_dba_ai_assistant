# ANCHOR: feature-0031-analysis-grounding 노드 분석 접지(evidence grounding)

## §1. 외부 관점 요약

"그래프 뷰의 AI 능동 분석은 이미 1만 건을 분석했는데, 왜 또 DB 를 읽어서 통계를 모으나?"
→ 지금까지의 분석 입력에는 **데이터 실측이 하나도 없다**. 이름·설명·이웃 관계만 주고,
프롬프트가 명시적으로 "이름 규칙(CT_*/sp_*/*_log)에서 가장 그럴듯한 의미를 추론하고 단정하라"고
지시한다. 결과적으로 1만 건의 분석문은 **추측이 정본 노릇**을 하고 있고, 평균 94자다.
통계 증거(카디널리티·null 비율·길이 분포·키 후보)를 붙이면 같은 LLM 콜 수로 분석의 사실성이
올라간다 — 이것이 상위 계층 요약(L2/L3)보다 **먼저** 와야 하는 이유다. 접지 없는 요약은
추측의 요약이라 틀린 내용을 더 권위 있게 만든다.

"왜 실제 데이터 샘플은 안 넣나? 그게 제일 정확할 텐데."
→ 원시 값은 곧 PII 표면이다(계정·결제·개인정보 컬럼). 업계 실측(DBAutoDoc 2025)상 결정적 이득
(FK 판정 F1 +23p)은 **통계**에서 나오지 샘플값에서 나오지 않는다. 그래서 통계만 쓴다. 문자열
컬럼의 min/max 도 사실상 원시 샘플 1건이라 함께 배제하고, 길이 분포 + 패턴 클래스로 대체한다.

## §2. 대안 분기

- **Alt-A: 계층 요약(L2/L3)을 먼저.** 페르소나 — GraphRAG 논문을 읽고 "커뮤니티 요약이 핵심"이라
  판단한 팀. 안 고른 이유: 우리 병목은 요약 부재가 아니라 **입력 접지 부재**다. 접지 없이 요약을
  얹으면 추측을 압축해 더 그럴듯하게 만들 뿐이고, 나중에 접지를 넣으면 요약 전량을 재생성해야 한다.
- **Alt-B: LLM 오케스트레이터가 분석 AI 를 파견·집계.** 페르소나 — Anthropic multi-agent 리서치
  결과를 본 팀. 안 고른 이유: fan-out 자체는 이미 `node_analysis_jobs` 큐로 결정적으로 구현돼
  있다. 오케스트레이터를 LLM 으로 바꾸면 토큰 15배·비결정성만 얻고 얻는 게 없다(2026 프로덕션의
  70%가 결정적 orchestrator + LLM worker 형태다). LLM 이 실제로 필요한 자리는 계획이 아니라
  집계(L2)와 검증이다.
- **Alt-C: 운영 DB 를 건드리지 않고 대화 로그·실행 SQL 만으로 접지.** 페르소나 — 운영 DB 부하를
  극도로 경계하는 DBA. 안 고른 이유: 커버리지가 실제 조회된 테이블에 한정돼 편향이 그대로다.
  다만 이 신호는 ITEM-11(결정적 플래너)의 우선순위 입력으로 채택한다 — 버리지 않았다.

## §3. 가정된 사용 시나리오

신규 입사한 데이터 분석가가 그래프 뷰에서 `CT_ItemDrop` 노드를 열고 AI 분석을 읽는다.
지금은 "아이템 드롭 정의 테이블로 추정된다" 수준의 한 줄이 나오고, 이게 이름에서 나온 추측인지
데이터를 본 결과인지 구분할 수 없다. 접지 후에는 "약 12만 행, `item_id` 는 고유하지 않고
`stage_id`+`item_id` 조합이 유일(키 후보), `drop_rate` 는 0~1 범위, `expire_at` 은 87%가 NULL"
같은 실측이 근거로 붙는다. 그 분석가는 **테이블을 직접 열어보지 않고도** 조인 키와 필터 조건을
결정할 수 있고, 무엇보다 "이건 AI 가 이름 보고 지어낸 문장"과 "이건 데이터를 본 문장"을 구분할 수
있다. 6개월 뒤의 우리 자신에게도 같은 구분이 필요하다.
