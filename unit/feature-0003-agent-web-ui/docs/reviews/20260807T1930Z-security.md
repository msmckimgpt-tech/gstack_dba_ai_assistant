## 검증했고 깨끗한 축 (안 본 것과 구별)

- **게이트 순서 동형**: `_require_account` → `_load_attachment_row` → `_account_can_access_attachment`(404)
  → `_account_is_pending`(403) — `download_attachment` · `/diff` 와 문자 그대로 같은 순서.
- **스코프 비대칭 없음**: `/diff` 가 `scope_row` 를 넘기는 이유는 *체인의 다른 행*을 반환하기 때문.
  `/source` 는 게이트를 통과한 그 행만 쓰므로 필터링 대상 자체가 없다. soft-delete 는
  `_account_can_access_attachment` 가 `DeletedAt` 으로 거부(PG 미러도 같은 키를 싣는다).
- **oracle 없음** · **XSS 없음**(본문은 textContent 전용, 메타표는 escapeHtml) · **신규 권한 표면 0**
  (API 토큰 도달범위가 `/download` 와 동일) · **휴지통 미배선**.

## Findings (P2)

1. **§21 공유창 window 미적용** — clip 이 걸린 곳은 fork·일괄 다운로드 둘뿐. 목록·다운로드·비교·원문
   4경로는 미적용. bounded 멤버가 floor 이전 첨부 본문을 원클릭 열람. **이 diff 가 뚫은 경계는 아니고**
   같은 행의 ⬇ 로 이미 가능했다(일괄 다운로드 주석이 그 갭을 명시 인정) → P1 아님. 봉인하거나
   SECURITY.md §21.5 에 명시 수용으로 기록할 것.
2. **`Cache-Control`·`nosniff` 누락** — `download_attachment` 는 `private, no-store` + `nosniff`.
   같은 bytes 를 JSON 으로 감쌌을 뿐인데 저장 정책만 사라졌다. 미들웨어·Caddy 도 넣지 않는다(확인).
   공용 단말 디스크 캐시 잔존 → 로그아웃 후 재노출.
3. **자원 증폭 + rate limit 부재** — `get_object_bytes` 는 객체 전체를 메모리로 읽는다(ranged 헬퍼 없음).
   per-file cap 25MB ÷ 뷰 cap 1MB = **최대 25× 증폭**. 트리거가 목록 행 전체로 넓어졌고 모달은 열 때마다
   재요청(클라 캐시 없음). 저장소에 이미 `_search_rate_limit_check` 가 6곳에 쓰이는데 여기는 미사용.
4. **`stats.lines` 가 절단된 앞부분에서 계산되는데 전체처럼 표시** — 실측: 200,000줄/2.2MB 파일이
   화면에 `"95326줄 · 2.2MB"`(앞부분 줄 수 + 전체 크기). 배너는 "앞부분만 표시" 라고만 하고 숫자가
   틀렸다는 말은 하지 않는다. 모듈 자기 규칙("clipped 면 '원문' 이라 쓰지 않는다")과도 충돌.

## Findings (P3)

- **P3-1 `splitlines()` 왜곡** — `\r\n`·`\r`·form feed·U+2028/U+0085 가 줄 경계로 접힌다. FUNCTION.md
  AC-ASV-2 "byte 동일" 주장이 일반적으로 거짓이고, form feed 는 없던 줄바꿈을 만들어 줄번호를 민다.
- **P3-2 빈 `ObjectKey` 가드 누락 + 과광폭 `except Exception`** — 데이터 결손이 503(저장소 장애)으로
  오분류된다. `download_attachment` 는 404 가드를 갖는다.
- **P3-3 게이트 회귀 테스트 부재** — 공유 `_patch_auth` 가 `_account_can_access_attachment` 를 통째로
  치환해 soft-delete 거부·멤버십 판정이 **한 번도 실행되지 않는다**.
- **P3-4 감사 없음** — `download`·`/diff` 도 없고 감사는 파괴적 쓰기·대량 반출만 남기는 정책이라
  통제 후퇴는 아니다(기록만).
- **P3-5 실패 로그에 object key(대화 id + 원본 파일명)** — `/diff` 와 동형, 로그 한정.
- **P3-6 `role="button"` 컨테이너 안에 실제 button 3개** — 파괴적 컨트롤(🗑) 시맨틱이 가려질 수 있다.
- **P3-7 SECURITY.md 미갱신**.

## Verdict

**CONCERN** — 인가·oracle·XSS·D21 은 `/download`·`/diff` 와 동형으로 정확하고 새로 뚫린 경계는
없으나, 본문 응답의 저장 정책 누락·read 증폭 + rate limit 부재·절단 프리픽스 줄 수 오표기는 같은
cycle 에서 닫아야 하고, §21 window 미적용은 봉인 또는 명시적 수용 기록이 필요하다.
