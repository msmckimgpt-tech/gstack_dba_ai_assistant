## Findings (P2)

1. **`min-width: 22px` 는 바닥이지 고정이 아니다** — 실제 폭이 `max(값, 내용폭)` 이라, 같은 열에서
   한 행은 실버튼·다른 행은 빈 슬롯인 **바로 그 상황**에서 실버튼이 22px 를 넘는 순간 열이 다시
   갈린다. 브라우저 "최소 글꼴 크기" 설정으로 11px 이 승격되면 원증상이 그대로 복귀한다.
   또 하네스 D5b 가 `flex: 0 0 auto` 를 리터럴 단언해 **잘못된 계약을 테스트가 잠갔다**.
2. **AC-AVA-6("목록 3종 전부")의 픽셀 근거가 0** — test-runs fragment 의 좌표는 버전 이력뿐인데
   `verdict: PASS` 이고 AC 는 무조건 단언. 22px 은 한 버튼 크기(11px/4px)에서 얻은 값인데 다른
   크기(12px/5px)에 일반화됐다(§2.5). 형제 목록은 결함 존재도 해소도 실측되지 않았다.
3. **하네스 [E] 는 소스 정규식이라 오배치를 통과시킨다** — 슬롯을 엉뚱한 컨테이너에 붙이거나
   `⬇` **앞**에 넣어 열 순서를 깨도 통과한다(§2.1 "항상 통과하는 검사"). 이 파일의 헤더가 스스로
   금지한 방식이며, `_renderTrashAttachmentList` 는 순수 함수라 실행 테스트가 **가능**하다.
