프로덕션 라이브 배포는 두 가지 보안 결정을 기다리며 이번 기간 유보했습니다(구글 드라이브 접근 / 라이브 DB 접근 범위).

계획했던 DB 복제본 부하분산은 환경 제약으로 미구성, 대신 참조 메타데이터를 내부에 구축했습니다(관계도 지도). 자세한 내용은 범위·환경 슬라이드에서 정리했습니다.

개발 배경 · 왜 이 일을 했나

"실서비스로 올리려면 — 기본 보안부터, 함께·믿고·크게 쓰기까지"

상황 (직전 기간까지 · 5/19~6/17)

  • 개별 대화 화면을 다듬음 — 첨부·조회결과 표시·감사 드로어·권한 트리·데이터소스 관리.
  • 혼자·한 대화는 잘 썼지만, 실서비스 운영에 필요한 기본 보안은 아직 없었습니다.
  • 협업·자율 지식·관계도·무중단도 미구축 상태였습니다.

목표 (이번에 풀 것)

  • 기본 보안 6종 — 로그인 제한·2단계 인증·인젝션 방지·공유 만료·사용량 한도·감사 변조방지.
  • 대화 편집·검증, 안전한 공유, 수천 테이블 지도 탐색, 끊김 없는 배포.
  • 부하 분산용 DB 복제본(IDC·웹DB) 구성.

이번 기간의 접근 — 기능·보안을 검증 환경(로컬→QA)에서 개발·검증하는 데 집중했습니다.

프로덕션 라이브 배포와 복제본 구성은 보안 결정·환경 제약이 얽혀 있어, 그 부분은 정직하게 '유보'로 구분해 보고합니다(범위·환경 슬라이드).

1. 안전하게 접속·이용한다 (기본 보안 6종) 신규·완료

실서비스로 올리기 위한 기본 보안을 한 번에 갖췄습니다

1배경·문제
  • 지금까지는 기능 위주였고, 실제 운영에 올릴 기본 보안이 부족.
  • 로그인 무제한 시도 · 비밀번호만으로 로그인.
  • 공유 링크 무기한 · 사용량 무제한 · 감사 기록 위·변조 여지.
2무엇을 갖췄나 (6종)
로그인 시도 제한(잠금·차단) 2단계 인증(인증 앱 코드) AI 프롬프트 인젝션 방지 공유 링크 만료 처리 LLM 사용량 한도 감사 기록 변조방지(해시 체인)
3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 운영의 전제 조건 — 실제로 올리려면 이 여섯은 선택이 아닌 필수.
  • 감사 기록은 해시 체인으로 이어 붙여 몰래 고치면 즉시 드러남.
  • 인젝션 방지는 데이터에 숨긴 지시를 명령으로 오인하지 않게 계층 분리.
5기대 효과 개발·검증 완료
  • 계정 탈취·정보 유출·기록 위조·사용량 남용의 기본 위험 저감.
  • 6종 모두 개발·검증 환경 검증 완료.
  • 프로덕션 적용은 라이브 배포 시점에 함께(범위 슬라이드).
2. 대화를 편집하고 조율한다 신규

보낸 말을 고치고, 요청을 바꿔 다시 답변받되 이전 답변도 남깁니다

1배경·문제
  • 보낸 말을 고칠 수 없어 오타 하나에도 새로 작성.
  • "요청을 바꿔 다시 받되 이전 답변과 비교"가 불가.
  • 모든 질문이 똑같은 생각의 양으로 처리.
2화면 흐름
내 말풍선 hover›수정›단순 수정 · 요청 바꿔 재답변›< 1 / 2 > 버전 비교

더불어 생각 깊이 4단계 · 실시간 진행 표시 · 지연 시 조용한 자동 재연결.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 대화 안에서 가지를 치는 방식(ChatGPT식) — 사이드바 오염 없음.
  • 가지 없는 대화는 기존과 완전히 동일(회귀 0).
  • 그룹·공유는 답변 근거 보호 위해 단순 수정만 허용.
5기대 효과 개발·검증 완료
  • 오타 즉석 수정 + 요청 변경은 분기 재답변·버전 비교.
  • 1:1·그룹 모두 검증 환경 실화면 검증 통과 · 보안 결함 3건 봉인.
  • 그룹 편집 보안 세부는 실화면 재확인 예정.
3. 답변을 스스로 검증한다 (신뢰·정직) 신규

AI가 자기 답변을 스스로 비판하고, 첨부와의 일치를 확증합니다

1배경·문제
  • AI가 답변을 곧바로 전달 — 근거 부합을 되짚는 단계 없음.
  • 첨부↔실데이터 비교 시 일부만 본 결과를 전부로 단정.
  • 실재 항목을 "누락"이라 오진하는 환각이 사용자에게 보고됨.
2동작 흐름
답변 초안›별도 리뷰어 · 5축 적대 점검›문제 시 수정›전달

5축 = 근거 정합 · SQL 정확성 · 권한/정보누출 · 완전성 · 정직성. 첨부는 코드가 대소문자까지 대조. 운영자는 '감사 > AI 추론'에서 조회.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 검증은 품질 계층일 뿐 관문이 아니게 — 문제 있어도 답은 나옴.
  • 첨부 대조는 코드가 결정론적으로 판정(대소문자에 안 흔들림).
  • 근거 못 대면 '미확인'이라고 정직하게 말하도록 계약.
5기대 효과 효과(재발 감소) 측정 예정
  • 근거 미부합·과단정 사전 차단, 첨부 대조 환각 감소.
  • 개발·검증 완료(테스트·적대 리뷰 통과).
  • "라이브 검출력·환각 감소"는 다음 기간 실측.
4. 안전하게 나눠 본다 (공유 범위 지정) 신규·첫 공개

대화의 "보여줄 구간"만 나누고, 나머지는 완전히 가립니다

1배경·문제
  • 공유하면 처음부터 끝까지 전부 노출.
  • 앞부분 민감 데이터·다른 계정 정보도 가릴 수 없음.
  • 참여자가 "앞 대화 보여줘"로 AI를 속여 캐낼 위험.
2화면 흐름
말풍선 ☰ 메뉴›여기부터/여기까지 공유›공유·초대·복제›가린 구간은 어디서도 안 보임

공유 링크에는 만료 기한(보안 6종)이 함께 적용됩니다.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 보안 최우선 — 가린 구간을 화면만 아니라 AI가 읽는 데이터에서도 제거.
  • 없는 것은 아무리 캐물어도 안 나옴(물리 배제).
  • 오류 시 무조건 차단 · 재공유로 범위 넓히기도 차단.
5기대 효과 실화면 검증 예정
  • 민감 구간 유출 없이 부분 공유.
  • 기능·보안 개발 완료(적대 리뷰로 초기 누출 1건 봉인).
  • 실제 화면 시각검증은 배포 후 확인 예정.
5. 스스로 똑똑해지는 지식 (용어·코드값·제품 분류) 이어받음

대화에서 배운 뜻을, 검토를 거쳐 지식으로 쌓습니다

1배경·문제
  • 회사 고유 용어·코드값(예: 상태 1=결제완료)·제품 분류를 사람이 일일이 등록·매핑.
  • 용어 사전 수단은 있었지만 후보가 여기저기 흩어져 관리가 번거로움.
2선순환 흐름
대화·분석›AI 후보 제안›채택 인박스›관리자 검토·승인↻더 정확한 답

구글 드라이브: 현재 기능 토대만 구축 — 서비스에는 아직 미포함(편입·접근은 결정 대기).

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 자율성 + 오염 방지 — 전수 기록·되돌리기·사람 검토를 붙여 안전하게 개방.
  • 제품 분류도 AI는 제안까지만, 최종 승인은 사람이.
  • 외부 지식원 구글 드라이브 연결의 기능 토대를 마련(서비스 편입은 결정 후).
5기대 효과 드라이브: 토대만·서비스 미포함
  • 손이 덜 가면서 지식이 쌓여 답 정확도에 기여.
  • 용어 사전 검증 통과 · 코드값·채택 인박스는 배포 후 확인 예정.
  • 구글 드라이브는 기능 토대만 구축, 서비스 미포함(편입·접근은 결정 후).
6. 데이터베이스를 '지도'로 탐색한다 (관계도 뷰) 신규·첫 공개·대폭 확장

수천 개 테이블을 지도로 — 이제 대규모도 매끄럽게 움직입니다

1배경·문제
  • 운영 DB는 테이블 수천 개인데 화면은 평면 목록.
  • 관계·역할이 보이는 대화형 지도는 갖췄으나…
  • 노드가 많아지자 화면 이동(팬)이 계속 버벅여 반복 신고.
2탐색 흐름 (영역별)
제품 카테고리›스키마 묶음›컨텐츠 군집›테이블·함수›검색·관계 추적

이 지도는 복제본 대신 '참조에 필요한 메타데이터'를 내부에 구축한 결과이기도 합니다(범위 슬라이드).

3변경 전 → 후 (렌더 엔진 전면 교체)
실제 화면 대신 개념 도식 · 실선=신뢰 관계, 점선=추정 관계
4왜 이 방향
  • 앱 최적화로는 한계 → 화면을 GPU에 상주시키는 웹 표준 방식으로 교체.
  • 무거운 게임엔진 기각(이득 원천=GPU 상주는 웹으로도 획득).
  • 보이는 화면은 그대로 유지 + 비상 시 옛 엔진 복귀 장치.
5기대 효과 검증(중간 규모) 실 규모 확인 예정
  • 낯선 DB도 구조·흐름을 눈으로 파악, 화면 이동이 매끄러워짐.
  • 실 화면 60fps 검증(약 400개 규모) · 컨텐츠 23,465개 적재.
  • 정작 문제였던 수천 규모 실 체감은 다음 기간 확인.
7. AI를 관제하고 콘솔을 정돈한다 이어받음

AI가 무엇을·얼마에·얼마나 빠르게 하는지 한눈에, 콘솔은 성격대로 정돈

1배경·문제
  • AI가 여러 경로에서 일하는데 상태·비용·지연을 볼 화면 없음.
  • 관리 콘솔은 관측 데이터와 설정 값이 뒤섞이고 탭 과밀.
  • 권한은 평면 구조라 최소권한 부여 어려움.
2화면 흐름
관리 콘솔 · 감사›AI 운영 현황›상태·KPI·활동›활동 클릭 → 상세·대화 링크

콘솔 정보구조 재편(관측/설정 분리·서브탭) + 권한 카테고리 계층·원자 단위 부여.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 지연을 '전체 시간' 대신 '단계 사이 간격'으로 재정의(진짜 신호).
  • 콘솔은 관측/설정 성격대로 분리 + 유사 탭 서브탭 묶음.
  • 권한은 화면 구조와 정합하는 계층 + 액션 단위 최소권한.
5기대 효과 콘솔·권한 검증 패널 지표 축적 예정
  • 문제를 빨리 발견·진단, 콘솔·권한 부여가 명료.
  • 콘솔 정보구조·권한 계층은 검증 환경 실화면 검증 통과.
  • 패널 실화면·재정의 지연 지표는 배포 후 실트래픽으로 확인.
8. 끊김 없이 배포하고 스스로 회복한다 (기반) 완료·신규

재배포·재시작해도 안 끊기게, 그리고 AI는 안전한 전용 공간에서

1배경·문제
  • 지난 기간 웹 화면만 무중단.
  • 뒤의 처리기(워커)·AI 게이트웨이 재배포는 순간 끊길 수 있음.
  • AI가 여러 데이터를 모아 분석할 격리 공간이 없었음.
2동작 구조
웹 2대 롤링+워커 정상확인 후 교체+게이트웨이 무중단 교체+엣지=중단 0

거대 코드 파일은 21개 모듈로 정리(겉보기 동작 그대로) + AI가 코드를 스스로 찾는 지도.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향
  • 검증된 웹 무중단 방식을 재사용·확장.
  • 게이트웨이는 배포 순간에만 임시 복제(평상시 비용 0).
  • AI 작업공간은 별도 DB로 물리 격리·대화별 분리(기본 꺼짐).
5기대 효과 검증 환경 실증 자동 롤백·전체 e2e 후속
  • 재배포·재시작 중 중단 0 실증(검증 환경 부하 시험).
  • 코드 정리 완료 + AI 코드 자동 지도 · 작업공간 활성화 완료.
  • 실패 시 자동 롤백·작업공간 전체 흐름은 후속.

무엇을 어디까지 했고, 무엇을 왜 '유보'했는가

  • 아래 두 가지는 준비 부족이 아니라 결정·환경 제약 때문에 유보했습니다.

수행 개발·검증 범위

기능·보안을 검증 환경(로컬→QA)에서 개발·검증. 현재 데이터소스 연결은 로컬→QA까지. 이 자료의 "검증 통과"는 모두 이 환경 기준입니다.

유보 프로덕션 라이브 배포

  • 보안 결정 2건이 남아 라이브 배포 미진행.
  • ① 구글 드라이브 — 기능 토대만(서비스 미포함), 접근·편입 여부.
  • ② 라이브 DB 접근 범위 — 복제본 제약으로 직접 접근 여부.

대체 DB 복제본 부하분산

계획했던 IDC·웹DB 복제본은 환경 제약으로 미구성. 대신 참조에 필요한 메타데이터만 내부에 구축했고, 그 산물이 관계도 지도입니다.

다음 단계 — 위 두 보안 결정(드라이브 접근 / 라이브 DB 접근 범위)이 내려지면, 검증 환경에서 완료·검증한 기능·보안을 프로덕션 라이브로 전환합니다.

이 자료의 성과는 그 전환의 준비가 끝났음을 의미하며, "라이브 운영 실적"과는 구분해 읽어 주십시오.
