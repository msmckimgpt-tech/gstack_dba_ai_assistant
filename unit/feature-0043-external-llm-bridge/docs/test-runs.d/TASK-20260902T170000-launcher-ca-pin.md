## 6. 하네스가 스스로 틀린 자리 — 남겨 둔다

이 cycle 에서 **검증 도구 자신이 세 번 거짓 신호를 냈다.** 셋 다 「초록이니까 됐다」로 읽혔을
모양이었다.

| # | 무엇 | 어떻게 드러났나 |
|---|---|---|
| 1 | 뮤턴트가 **의도한 자리에 적용되지 않음**(같은 문자열 2곳) | 적용 여부를 diff 로 확인 |
| 2 | 추출이 어긋나 다운로더 첫 줄이 깨짐 → **모든 「거부」가 SyntaxError 탓** | **기준선**(정상 CA 는 받아야 한다)을 먼저 세움 |
| 3 | root 라 `chmod 500` 이 무효 → 실패 주입 자체가 성립 안 함 | 같은 조작을 테스트 밖에서 직접 재현 |
| 4 | 그 `chmod 500` 이 **과도한 조건**이었다 — `bridge.log` 까지 막아 러너가 뜰 수 없게 해 놓고 「러너가 떠야 한다」고 검사 | **CI(비-root)** 가 red 로 잡았다 |

3 과 4 는 같은 한 줄에서 나왔고 **정반대 방향으로** 틀렸다. 로컬(root)에서는 조작이 무효라
vacuous 통과했고, CI(비-root)에서는 조작이 **너무 잘 들어** 제품이 지킬 수 없는 조건을 만들었다.
그리고 그 사이 내가 넣은 `skipif(root)` 가 **로컬에서 이 모순을 통째로 가렸다** — skip 은
「이 환경에선 검사 안 함」이지 「계약이 지켜짐」이 아닌데, 초록은 그 둘을 구별해 보여 주지 않는다.

지금 L10 은 **정적 계약만** 잠근다(`|| true` 존재 + 받지 못한 다운로더를 실행하지 않음). 동작
축은 L3 이 맡는다 — 잘린 응답으로 갱신을 실패시키고 **런처가 rc=0 으로 끝나는지** 본다.
실패 주입이 «갱신 단계에만» 걸리는 자리가 거기이기 때문이다.

공통 처방은 둘이다 — **①거부·실패를 주장하는 검사는 그 옆에 「정상은 통과한다」를 반드시
둔다.** 그것이 없으면 하네스 고장과 계약 준수를 구별할 수 없다. **②실패를 주입할 때는 그
주입이 «검사하려는 것만» 막는지 확인한다.** 더 많이 막으면 제품이 지킬 수 없는 조건이 되고,
그때의 red 는 제품이 아니라 하네스를 가리킨다.
