# feature-0046-native-client — Windows 네이티브 클라이언트

## 1. 한 줄

사용자가 **터미널을 열지 않고** 자기 AI 를 이 서비스에 연결한다. `bridge_setup.ps1`(669행)이
하던 일을 **같은 계약으로** 하되 껍데기를 GUI 로 바꾼 것.

## 2. 왜

`docs/improvements/onboarding-accessibility/RESEARCH.md` §9.1 — 연결을 우리가 만든 배포물로
구현하고 런타임·설치 UX·설정 UI·업데이트 채널을 전부 자체 구현해 **넷 모두가 마찰**이 됐다.

## 3. 핵심 제약

- **로그인은 「위임」이 아니라 「대행 실행」** — 벤더 공식 명령을 subprocess 로 띄우고 종료코드만
  본다. 토큰 미접촉. 2026년에 3사가 구독 OAuth 제3자 사용을 차단했고 Google 은 유료 구독자
  계정을 정지했다.
- **배포 형식 = 설치 마법사 + 런타임 동봉** (사용자 결정 2026-09-03, 정본 §P0-J) — 포터블 단일
  exe(`--onefile`)를 버리고 Inno Setup per-user 설치기 + `--onedir` + 공식 임베더블 CPython 을
  앱 폴더 옆에 두는 형식으로 옮겼다. ⚠ **동봉하는 것은 인터프리터지 러너가 아니다** — 러너는
  여전히 서버에서 받아 체크섬 대조한다(동봉하면 서버 배포와 클라이언트 배포가 갈려 「고쳤는데
  그대로」가 재발한다). 동결 exe 의 `sys.executable` 은 파이썬이 아니라 앱 실행 파일 자신이라
  종전 배포본은 러너를 실행하지 못했다(실측 exit=2 → 화면엔 「연결 확인에 실패했습니다(코드 2)」).
- **AI 는 Windows 와 WSL 양쪽에서 찾는다** (정본 §「AI 는 Windows 와 WSL 양쪽에서 찾는다」 ·
  §「러너는 WSL 안의 AI 도 찾는다」) — 첫 자리에서 멈추면 쓸 수 있는 것이 있는데도 「없다」가
  된다(사용자 제보: 「기존에 쓰던 LLM 접근 수단(WSL)에 진입할 수 없다」).
  종전엔 WSL 런타임을 러너의 `--cmd 'my-ai -p {prompt}'` 계약으로 넘겼고, 그 경로는 능력을
  신고하지 않아 웹의 「답할 AI 있음」이 ❌ 로 남았다. **2026-09-04 에 그 우회를 고치지 않고
  없앴다** — 러너가 WSL 안을 직접 조회한다(탐지 순서: 지정 경로 → PATH → 표준 설치 위치 →
  WSL 안 · POSIX 절대경로는 `wsl.exe -e` 로 확장). ⚠ 이 확장은 **런타임 종류를 바꾸지 않아**
  협상이 그대로 돈다 — 그것이 `--cmd` 우회와 다른 점이다. 같은 CLI 가 양쪽에 있을 때 어느
  쪽인지는 연결 프로그램이 `BRIDGE_AI_PATH_<NAME>` 로 정한다(각 후보에게 실제로 물어보고
  답한 것을 골랐기 때문이다). 실측에서 「답할 AI 있음」 ✅.
- **인증 상태는 가용성의 증거가 아니다** (정본 §P0-L) — `auth status` 만 보고 「연결할 준비가
  되었습니다」라 하던 판정이 실측에서 틀렸다(로그인돼 있는데 답을 받지 못하는 런타임이 있었다).
  `verify_answers()` 가 실제로 한 번 물어보고 화면·선택은 `usable`(설치됨 + 답함)만 본다.
  ⚠ 이 호출은 사용자의 AI 사용량을 쓴다. 질문 인자는 런타임마다 다르다(`codex` 는 `exec` 하위명령).
- **웹의 인계를 딥링크로 받는다** (정본 §P0-M/§P0-O/§P0-P) —
  `dqa-connect://start?token=…&base=…&ca_sha256=…&agent_sha256=…`. 종전엔 토큰만 실렸다(그
  딥링크는 셸 설치본용이고 그 경로는 설치 때 서버 주소와 CA 를 디스크에 심는다) — 네이티브
  클라이언트에는 그 사전 상태가 없어 **「연결 정보가 없습니다」만 떴다**. 조립은 정본
  `shared/dqa_identity.scheme_url()` 한 곳이고, 서버 주소는 처음 연결한 곳으로 **TOFU 고정**해
  다른 주소가 오면 두 주소를 나란히 보여 주고 묻는다(물을 수 없으면 「아니오」로 읽는다).
- **웹은 클라이언트를 주 경로로 보인다** (정본 §P0-Q/§P0-R) — 터미널 1·2·3단계는 접는다.
  ⚠ **없애지 않는다** — 연결 프로그램을 설치하지 않은 사용자에게는 그것이 유일한 길이고,
  실행 실패 안내가 「1단계 명령」으로 되돌려 보내므로 접힌 블록을 자동으로 펼친다. `/ai/connect`
  에는 [내 AI 실행] 버튼을 **실재시켰다** — 문구만 바꾸고 버튼을 안 넣어 사용자가 없는 것을
  찾게 만든 결함을 실제로 냈다(2026-09-03).
- **Windows 우선 · 미서명** (사용자 결정 2026-09-03). 코드 서명은 조직 결정 대기이고,
  SmartScreen 경고는 설치 마법사 전환으로 **설치 1회**로 줄었다(단일 exe 를 매번 실행하던
  종전보다 나아진 점이다).

## 4-2. 상주는 두 껍데기 공통 (2026-09-04 재구성)

화면은 서비스에 하나(§P0-S)이고 **이 재구성 시점의** 껍데기는 둘이었다 — **웹 셸(주)** 과 **tkinter(폴백)**. 내장 WebView2 창이 그 직후에 들어와 지금은 셋이다(§4-4).
처음엔 트레이가 폴백에만 붙어 주 경로 사용자는 패널을 닫는 순간 연결을 잃었다. 사용자에게
이 프로그램은 하나이므로 상주 규약도 하나여야 한다 — 어느 껍데기로 떴는지는 우리 사정이다.

- 두 경로 모두 **창을 닫아도 알림 영역에 남고**, 끝내는 것은 아이콘 [종료] 뿐이다.
- **상주 중에는 유휴가 종료 사유가 아니다.** 웹 셸의 수명 신호는 「패널이 말을 걸어오는가」
  인데 패널을 닫아 두고 쓰는 것이 상주의 의미다. 아이콘이 없거나 **뜬 뒤 죽으면** 종전
  계약(유휴 90초 / 닫기=종료)으로 되돌아간다 — 상주할 표면이 없는데 살아 있으면 끌 수 없다.
- **웹 셸 트레이에 「다시 연결」은 없다(의도).** 이 경로의 연결 입구는 패널이다. 트레이가
  자체 재연결을 가지면 같은 동작의 입구가 둘로 갈린다. 트레이는 패널을 열어 주고 끊기만 한다.
- **패널의 「닫아도 유지됩니다」는 껍데기가 세운 사실만 근거로 삼는다** — `br.resident`
  → `status.resident` → 패널이 두 문구를 갈라 말한다. 프런트가 추정하면 트레이 없는
  머신에서 거짓이 되고 사용자는 창을 닫고 연결을 잃는다(§P0-R).

⚠ **PB-0008 이월분은 해소됐다**(2026-09-04, feature-0003 `TASK-20260904T200000`) — 배포
`5ab60093` 의 앱 창 안에서 패널이 켜지고(`panelHidden:false`, 오류 0) 이 컴퓨터의 AI 3개
(`claude` · `claude (WSL)` · `codex (WSL)`)를 찾아 각각 응답을 확인했으며 연결 버튼이
활성화됐다. 이 cycle 당시의 사정은 이랬다 — 패널이 Windows 브리지의 `client_port/nonce`
로만 나타나고 유효 토큰이 없으며 라이브 반영은 공유 web 컨테이너를 건드려야 해 §13.2.9 가
금지했으므로, DOM 렌더 + 대조군으로 문구 분기만 실측하고 **이월**했다.

## 4-3. 안내가 **닿는 자리**에 있어야 한다 (2026-09-04)

§4-2 의 「패널이 두 문구를 갈라 말한다」를 넣은 곳은 `ai-connect.{html,js}` 였다. 그런데
앱 창이 여는 것은 **서비스 루트**이고 그 화면의 연결 패널을 그리는 것은
`app/client-bridge.js` 다 — 즉 **주 경로 사용자는 그 안내를 보지 못했다.** 「내 작업을 주
경로와 정합하게」라는 요구가 한 층 아래에서 그대로 반복됐다. 파일 이름이 그럴듯하다는 것
(`ai-connect`)은 그 화면이라는 뜻이 아니다.

해소: `index.html` 연결 패널에 자리를 만들고 `initClientPanel()` 이 `status.resident` 로
채운다. `status` 는 `discover`(수십 초) **앞에** 묻는다 — 「이 창을 닫아도 되는가」는 그 전에
알아야 하는 안내다. 별도 페이지의 안내는 **지우지 않는다**(그 경로 사용자가 남는다).

### 그 패널은 애초에 돌지 않았다 — `ReferenceError`

주 표면을 실제로 **구동**하자 첫 호출에서 던졌다: `_status is not defined`.
`client-bridge.js` 가 `_status` 를 8곳에서 부르는데 정의는 `connect-modal.js` 의
**export 되지 않은 지역 함수**이고 import 도 없다. ESM 모듈 스코프는 파일마다 닫혀 있으니
자유변수다. 예외는 `openConnectModal()` 까지 올라가 **연결 창 자체가 안 열린다**.

- **소스를 읽어서는 안 보인다** — 이름이 «있어» 보인다(정의가 저장소 안에 있다).
- **증상이 병렬 세션이 방금 고친 결함과 같다**(「패널이 끝내 안 켜진다」). 그 처방(플래그를
  결과로)은 필요했지만 충분하지 않았다 — 같은 증상에 원인이 둘이었다.
- 처방은 **지역 정의**다. import 로 풀면 순환이고, 이 모듈의 «의존 0» 성질이 깨진다.

⚠ **검증 하네스가 세 번 스스로를 배신했고 세 번 다 대조군·NOOP 검사가 잡았다** — 뮤테이션
변경 감지가 한글 로케일 때문에 고장(전건 «NOOP» 오보) · 단정이 부분 문자열이라
`connectModalStatusX` 통과 · 행위 층에만 둔 단정이 **CI 에 없는 하네스**라 pytest 를 통과.
「전건 KILL」은 표본이 옳을 때만 뜻이 있다.

## 4-4. 닫기는 트레이로, 종료는 우클릭 [종료] (2026-09-04)

> DQA 클라이언트 윈도우를 닫을 때, 기본적으로 트레이 아이콘으로 남겨두도록 … 실제 프로세스를
> 종료하려면 트레이 아이콘 우클릭을 통해 …

**세 껍데기(내장 WebView2 창 · 브라우저 앱 모드 · tkinter) 공통 계약**으로 못 박았다. 골격은
직전 PR #1576 이 이미 들여왔고, 이 cycle 이 닫은 것은 **그 골격이 무너지는 세 자리**다.

| 행동 | 아이콘 살아 있음 | 아이콘 없음/죽음 |
|---|---|---|
| 창 [X] | 숨는다 (프로세스·연결 유지) | 종료 |
| 아이콘 우클릭 → [종료] | **프로세스 종료** | — |

- **판정을 «닫는 순간» 묻는다.** `Shell.can_hide` 는 bool 이 아니라 `Callable`. 아이콘은 뜬
  뒤에도 사라지므로(탐색기 재시작 후 재등록 실패) 기동 시점 값은 곧 거짓말이 된다 — 그때
  계속 숨기면 **창도 아이콘도 없는 프로세스**가 남는다. 판정 정본은 `gui._tray_alive` 하나이고
  tkinter `_tray_live` 도 그것을 부른다(종전엔 tkinter 만 생존, 나머지는 존재 판정).
- **「닫아도 유지됩니다」도 같은 판정을 본다.** `Bridge.resident` 를 **읽기 전용 property**
  로 바꿔 `resident = tray is not None` 대입 자리 자체를 없앴다(§16.7 G10 구조 가드).
- **첫 닫기에 1회 안내**(`gui.HIDDEN_NOTICE`) — 「어디로 갔는가 + 어떻게 진짜로 끝내는가」를
  같은 자리에서. ⚠ **닫힘을 이벤트로 받는 두 껍데기(내장·tkinter)에만** 단다. 브라우저
  껍데기의 창은 우리 것이 아니라 `WM_CLOSE` 가 오지 않는다 — 한때 무신호(`idle_seconds`)를
  「닫혔다」로 추정해 냈으나 codex 2라운드가 되받았고 **옳았다**: 패널의 20초 ping 은
  `initClientPanel` 안에서만 시작하므로 연결 모달을 열지 않은 사용자는 ping 을 아예 보내지
  않고, 배경 브라우저는 타이머를 스로틀한다 → **창이 열려 있는데** 「알림 영역에 있습니다」를
  말한다. **없는 근거로 말하지 않는다**(그 결정을 테스트 2건으로 잠갔다). 그 껍데기 사용자는
  패널 문구로 닫기 **전에** 안내를 받는다.
- **실패를 삼키되 조용하지 않게** — `Shell.last_error` 신설. 실 Windows 하네스 초판 FAIL 이
  제품 결함인지 하네스 결함인지 가른 것이 이 필드다.

**실측** `tests/windows/verify_embedded_close.py` — `hide` 3연속 PASS · `quit` PASS ·
tkinter `verify_gui.py` 6단계 PASS. 단위 399 · 뮤테이션 16/16 KILL · codex 2라운드 P1 0.

⚠ **하네스가 먼저 틀렸다(기록 가치)**: ① 제목으로 창을 특정 — 트레이도 **같은 제목**의 창을
만들고, 같은 제목의 WinForms 창이 2개인 실행도 있어 같은 코드가 PASS/FAIL 을 오갔다. 소유자
(`BrowserView.instances[uid].Handle`)에게 물어 해소. ② 데몬 워커가 주 스레드 종료에 잘려
**마지막 단정이 결과 파일에 아예 없었다** — 「미측정」이 「측정해서 통과」와 구별되지 않는 형태.

⚠ **남은 것**: 패널의 상주 문구는 아직 **초기화 1회 스냅샷**이다(`client-bridge.js`). 브리지는
매번 새로 판정하지만 화면 문장은 낡을 수 있다. 고치는 자리는 20초 ping 틱(1~2줄)이나
`static/**` 변경은 시각검증 hard gate 를 켜고, 그 패널을 띄우면 `discover` 가 **사용자의 AI
사용량을 쓴다** — PB-0008 을 치를 cycle 에 묶는다.

## 4-5. 앱 창을 프로그램이 직접 그린다 · 아이콘만으로 뜬다 · 이름은 «DQA» (2026-09-04)

**내장 WebView2** (정본 §「앱 창을 이 프로그램이 직접 그린다」) — 그 전까지 앱 창은 「기본
브라우저를 앱 모드로 띄운 **별도 프로세스**」였다. 화면이 서비스 하나라는 원칙(§P0-S)은
지켜졌지만 사용자에게는 프로그램이 둘로 보였다(작업 표시줄 아이콘 둘). 이제 WebView2(Edge
Chromium)를 이 프로세스가 호스팅한다 — **동봉하는 것은 화면이 아니라 창틀**이고, 그 구분이
§P0-S 를 깨지 않는 근거다.

| 껍데기 | 언제 | 다음으로 내려가는 조건 |
|---|---|---|
| **내장 창** | 기본 | WebView2 런타임 부재 · 창 생성 실패 |
| 브라우저 앱 모드 | 내장이 안 될 때 | 크로미움 계열 부재 |
| tkinter | 웹 화면을 띄울 수 없을 때 | — |

⚠ **주 스레드는 창의 것이다** — `webview.start()` 는 돌아오지 않는 GUI 루프라 브리지·트레이·
「창 열어 달라」 폴링이 전부 워커 스레드에 있고 확인창은 `MessageBoxW` 로 받는다.
⚠ **로그인 세션이 브라우저와 갈린다** — 고정 저장소라 한 번 로그인하면 유지되지만 브라우저에
이미 로그인해 두었어도 **앱에서 한 번 더** 해야 한다. 그것이 내장의 대가다.

**아이콘만 눌러도 앱이 뜬다** (사용자 제보, 정본 §「아이콘만 눌러도 앱이 뜬다」) — 이 프로그램은
**웹의 부속물**이었다. 딥링크로 켜질 때만 성립했고 시작 메뉴·바탕화면·설치 직후 [지금 실행]·
자동 시작은 전부 「연결 정보가 없습니다」로 끝났다. 어느 서버를 여는지는 강한 근거 순으로 본다 —
`server.json` 의 `base`(**연결에 성공한** 서버) → 같은 파일의 `last`(사용자가 **받아들인**
딥링크 주소) → 설치 폴더 `service.json`(이 설치본이 어느 배포의 것인가). ⚠ `last` 를 `base` 와
**같은 키에 쓰지 않는다** — 고정은 「연결에 성공한 뒤에만」이라는 규율을 갖고 있고 그것이 TOFU
경고의 근거다. 두 번째 실행은 대화상자가 아니라 **창을 다시 연다**.

**보이는 이름은 «DQA» 하나다** — `APP_NAME`(설치 폴더·제거 항목 등 패키징 층)과
`DISPLAY_NAME`(창·트레이·대화상자·바로 가기)을 갈랐다. 사용자에게 이 프로그램은 「연결
도우미」가 아니라 **DQA 자체**이고, 화면에 «Connect» 가 남으면 서비스와 별개의 무언가로 읽힌다.
⚠ 설치 폴더·`AppId` 까지 바꾸면 업그레이드가 아니라 **두 벌 설치**가 되므로 보이는 이름만
바꾼다. ⚠ 웹 문구는 **어디서 보느냐로 갈린다** — 브라우저로 방문한 사람에게는 「받아서 설치할
것이 있다」가 사실이므로 그 안내는 남고, 앱 창 안의 문구에서만 별도 프로그램이라는 표현을 없앤다.

**업그레이드가 옛 이름의 잔재를 남기지 않는다** (실측) — 이름을 바꾼 뒤 덮어 설치했더니 시작
메뉴에 바로 가기가 **두 벌** 남았다. Inno 는 자기가 더 이상 만들지 않는 바로 가기를 알아서
치우지 않는다(제거 프로그램이 돌 때만 지운다) — 그래서 이 결함은 **덮어 설치한 머신에서만**
나타나고 깨끗한 환경에 새로 설치해 보는 검증으로는 절대 보이지 않는다. `[InstallDelete]` 로 옛
그룹 폴더·바탕화면 아이콘·자동시작 항목을 먼저 지우고, `UsePreviousGroup=no` 가 있어야 **폴더
이름까지** 도달한다(Inno 가 레지스트리에 적어 둔 지난 그룹 이름을 재사용하므로, 기본 그룹 이름만
바꾸면 옛 폴더 **안에** 새 바로 가기를 두게 된다 — 이름을 바꾼 의미가 절반만 도달한다).

**설치본 종단간 확인** (2026-09-04 20:45) — `main` `a8f58f46` 기준 재빌드 → 덮어 설치
(`/VERYSILENT` exit 0) → **실행**: 창 + 트레이 아이콘 · `tasklist` 1건 → 창 [X] 뒤에도 1건 →
트레이 [종료] 뒤 0건. 종료는 트레이 창에 `WM_COMMAND` 를 보내 재현했다 — 합성 마우스 입력으로
팝업을 여닫는 방식은 이 저장소가 이미 실패를 기록한 방법이다. 이어진 최종 설치본 라이브 완주에서
옛 그룹 폴더 없음 · 창 제목 `DQA`(연결 프로그램 자신의 창) · 브리지가 같은 프로세스 · 딥링크
없이 아이콘만으로 서비스가 열림을 확인했다.

**아직 못 본 것**: 코드 서명 · 서버에서 exe 를 받는 배포 채널(리눅스 파이프라인이 `.exe` 를
만들지 못한다) · gemini 로그인 대행(이 머신에 미설치라 측정 불가 — 커버리지를 과장하지 않는다).
