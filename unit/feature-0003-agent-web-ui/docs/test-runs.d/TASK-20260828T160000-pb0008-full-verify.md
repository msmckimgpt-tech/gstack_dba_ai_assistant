Environment: **Windows-browser** (relay @ `172.26.144.1:9223`, Chrome/151) + **실 브리지 러너**
(`bridge_agent.py --ai claude`, bootstrap_admin 계정) + 라이브 DB 대조

## 왜 이번엔 전 구간이 가능했나

직전 검증들은 두 벽에 막혔다 — 브리지 미성립(`win_host` 오판), 그리고 **브라우저 계정과 러너
계정 불일치**(브라우저 `bootstrap_admin` ↔ 러너 `admin`). 사용자가 "부트스트랩 계정으로
검증·인증까지 자율 진행" 을 승인해, 그 계정으로 **연결 발급 → 러너 기동 → 질문 → 답변** 을
한 축에서 돌릴 수 있게 됐다.

절차: `/api/auth/login` → `/api/ai/connect/token`(TTL 12h) → 그 토큰으로 러너 기동 →
브라우저에서 질문 → 러너가 claim → 조사 → submit → 화면 확인.

> ⚠ **브라우저 명령 간 세션이 유지되지 않는다**(win-browser 는 명령마다 컨텍스트를 새로 연다).
> 로그인·조작·검증을 **한 시나리오(`run --scenario`)** 안에 넣어야 한다. relay 도 몇 호출마다
> 끊겨 매 시나리오 앞에 `launch` 를 붙였다.

## 운영 메모 (다음 사람을 위해)

- **공유 계정 토큰을 일괄 revoke 하지 말 것.** 검증 중 `bootstrap_admin` 의 access token 을
  일괄 폐기했는데, 같은 계정으로 검증하던 **병렬 세션의 러너**까지 끊을 수 있다. 자기 세션이
  발급한 토큰만 골라 폐기하는 편이 안전하다.
- 검증에 쓴 토큰은 파일로 남기지 않았고(0600 임시 파일 → 삭제), 러너도 종료했다.
