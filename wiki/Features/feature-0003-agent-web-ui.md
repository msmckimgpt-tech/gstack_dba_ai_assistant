## 2. 상세

### 2.1 책임 경계

- **입력**: HTTP request (`/api/*`), `WebAccounts` 인증, RBAC 권한 검사
- **출력**: JSON 응답 / 정적 자산 / audit row / share link / 첨부 signed URL
- **side-effect**: MySQL mutation (admin 11 / user 5 endpoint) + `WebAuditEvents` row + MinIO PUT / signed URL

### 2.2 주요 endpoint 그룹

| 그룹 | 책임 | audit hook |
|---|---|---|
| `/api/ask` (POST) | LLM agent loop entry — `lazy_create` hint 지원, force_new 분기 | `_audit_user_action("conversation.ask")` |

### 2.3 핵심 RBAC + audit (ADR-0019)

- 4 신규 권한: `audit.read.own` · `audit.read.any` · `audit.export` · `audit.purge`
- `_audit_admin_mutation` = Same-tx fail-safe (INSERT 실패 → rollback + 500)
- `_audit_user_action` = fail-open (long-running 격리, stderr log)

- **첨부 전달 단위가 파일에서 폴더(디렉토리 트리)로 넓어졌다** (2026-09-08, `attach-folder-tree`, 사용자 요청) — 스키마는 **additive**(`WebConversationAttachments.RelativePath VARCHAR(1024) NULL` · `ALTER … ALGORITHM=INPLACE, LOCK=NONE` · PG `core_attachments.relative_path` · alembic `20260908_0059`) 이고 ⚠ **fast path 와 slow path 양쪽에 배선**했다 — 운영 재기동은 slow path 를 안 타므로 fast 누락 시 컬럼이 영영 안 생긴다. 신규 `shared/attachment_path.py` 가 경로 정규화·체인 키·트리 렌더의 **단일 정본**(traversal `..`·절대경로·드라이브 접두·제어문자 제거 · 깊이 32 · 길이 1024 · **파일명이 권위** = 경로 마지막 세그먼트를 업로드된 파일명으로 고정). 체인 조회 스코프가 `(conv, account, RelativePath 또는 OriginalFilename)` 로 넓어져 **경로 있는 행과 없는 행이 섞이지 않는다.** 프론트는 `+` 메뉴 「폴더 첨부」(`webkitdirectory`) + 드롭 디렉토리 **재귀 순회**(`readEntries` 를 빈 배열까지 반복 — 큰 폴더의 뒷부분 유실 방지) + 300개 상한(초과 시 **자르지 않고 멈춘다**) + 폴더 배지·배치 요약. assistant 프롬프트에는 **폴더 첨부가 있을 때만** `## DIRECTORY STRUCTURE OF ATTACHED FOLDERS` 를 1회 렌더한다(없으면 종전 출력과 동치). §18.8 full panel 적발(P1 3 · P2 10 · P3 5) 반영: 트리 구획을 마크다운 펜스 → **datamark sentinel** 로 교체 + 세그먼트·라벨 정제 · 컬럼 부재 시 **경로 없이 재조회**하는 degrade(첨부 섹션 소실 차단) · 서버가 대화당 첨부 **개수 상한**(`_attachment_count_cap()` 기본 1000)을 집행(300 상한이 클라이언트에만 있어 API 직접 호출로 우회되던 것)
- **실행 단계 패널에서 도구 호출 구문 노출을 폐쇄했다** (2026-09-08, `step-tool-syntax-leak`, **Major §12.3** — 표시 계층 + 비신뢰 입력 · 스키마·RBAC·엔드포인트·마이그레이션 0 · 사용자 제보) — 제목이 `describe_table {'schema_name': …}` 같은 도구 호출 구문 그대로였고 라이브 원장 `work_source='external-ai'` **30행 중 19행(63%)** 이 그 형태였다(출처 = 연결된 개인 AI 가 도구 엔드포인트에 넘긴 서술). ⚠ **적대 검증 1라운드가 4명 전원 BLOCK** 을 냈고 뿌리는 **초판 판정기**였다 — 원장 **9,759행 전건 재생**에서 「인용 없는 snake_case 로 시작」 규칙이 걸러낸 412행 중 실제 도구 구문은 **18행뿐**, 394행(96%)이 정상 제목이었다(손익비 1:22). 이 도메인은 **테이블 이름이 곧 사용자의 어휘**라 그 형태를 금지 서명으로 쓸 수 없다. 재설계: 서명을 (a) 인자 매핑 리터럴 + (b) **서버 도구 census 의 이름** 둘로 좁히고 NFKC + 제로폭·bidi 제거로 전각 우회를 닫았으며, 표시 문구를 만드는 **단일 이음매** `_step_display_narration` 을 두어 완료·진행 두 경로가 그것만 부르게 했다(파생값 재정화 · 길이 상한 · 출처 정직화 · None-safe 를 한 자리에서). **사유 축은 분리** — 대체가 없는 축에 같은 규칙을 쓰면 정상 설명이 순수 손실된다(라이브 8건 실측). ⚠ **저장된 원문은 건드리지 않는다**(판정은 표시층 전용 — 감사·재현 가치가 있고 판정이 틀렸을 때 되돌릴 근거가 남는다). 게이트 자체의 결함도 고쳤다 — `_fn_body` 가 주석을 제거하지 않아 존재 단언이 주석에 걸렸고, 「make test 에 node 가 없다」는 **사실이 아닌 전제**로 만든 CI-gap 탈출구가 L6·L7·L8 을 동시에 무력화하고 있었다. 재생 후 버려진 제목 19건(전부 도구 표기) · 버려진 사유 **0** · 잔존 유출 **0**
