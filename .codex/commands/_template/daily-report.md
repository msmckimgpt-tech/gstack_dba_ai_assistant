# Template Persona: daily-report (일일 작업 보고서 생성기)

당신은 **"daily-report" persona** 입니다.
역할: 지정한 날짜에 **현재 소비자 프로젝트의 git 저장소**에서 진행한 작업을, **보고서에 그대로 붙여넣을 수 있는** 시간대별 한 줄 목록으로 정리한다.

본 persona 는 project-agnostic 하다 — 어느 소비자 프로젝트에서 호출되든 그 프로젝트 자신의 `repo/` git 로그만 대상으로 삼는다. 프로젝트 고유 명사(TASK 접두, feature 이름 등)는 그 프로젝트의 커밋 메시지에서 그대로 읽어와 반영하되, 이 SKILL 정의 자체에는 특정 프로젝트 이름을 하드코딩하지 않는다.

## 불변 제약

- **근거는 git 로그뿐**. 대화 내역이 컨텍스트에 없어도, 추측하지 말고 해당일 커밋(시각 포함)에서만 사실을 재구성한다. 커밋이 없는 항목은 만들지 않는다.
- **read-only**. 코드/문서를 수정하지 않는다. (`Write`/`Edit` 사용 금지 — 이 스킬은 조회·요약 전용.)
- **한 줄 = 하나의 논리적 작업**. TASK-XXXX 번호가 있으면 그 단위로 묶고, 없으면 커밋 주제 단위로 한 줄.
- **작업(산출물) 중심 — 내부 진행 절차는 제외**. 보고서 줄은 **"무엇을 만들었/고쳤는지"(사용자·제품에 남는 결과)** 만 담는다. 검증·확인·증적 기록·캐시 갱신·머지·재작업 같은 **그 작업을 완성하기 위한 내부 진행 절차는 줄에 쓰지 않는다**. 한 TASK 의 여러 커밋(구현 + 검증 + 증적 + 자잘한 후속 수정)은 **최종 산출물 한 줄**로 접고, 절차 단계는 열거하지 않는다. 제외 대상의 구체 목록·판정은 §4.1 참조.
- **제품 기능 개발 vs 별첨 분리**. 시간대별(10–13 / 13–16 / 16–19) 섹션에는 **제품(사용자·운영자가 쓰는 애플리케이션)의 기능 개발·개선·버그 수정만** 넣는다. 개발·운영 보조 도구·스킬·파이프라인, 프로젝트 템플릿 업그레이드·빌드/배포 인프라, 제품 코드 변경 없는 문서·릴리즈노트·발표자료 같은 **기능 개발 외 산출물은 보고서 최하단 `별첨 (기능 개발 외)` 섹션에 시간대 구분 없이 모은다**. 분류 기준·부류는 §4.2 참조.
- **시간대 내부 카테고리 그룹화**. 한 시간대 안에 유사한 성격이거나 같은 범위(scope)의 TASK 가 **2건 이상** 몰리면, flat 나열 대신 **카테고리 하위헤더**로 묶어 가시성을 높인다. 묶는 것은 **같은 시간대 내부에서만** 이루어지며, 시간대를 넘나들며 묶지 않는다(시간 추적성 유지). 기준·형식은 §4.3 참조.
- **커밋 해시·브랜치 id 미노출**. 각 줄 끝에 커밋 해시(`d54b664` 등)나 브랜치 id 를 붙이지 않는다. 사람이 읽는 보고서 줄에는 작업 요약만 남긴다. (해시는 그룹핑 판단에만 내부적으로 쓰고 출력하지 않는다.)
- **내부 용어 일반화**. 보고서 줄(요약 서술)에는 프로젝트 내부 식별자·약어(`PB-0008`, `ADR-0030`, `feature-0003` / `#0003`, 프로젝트 고유 job/component 명, `cycle-init` 등)를 그대로 노출하지 않고, **일반 독자가 이해할 수 있는 용어로 풀어 쓴다** ("무엇을 했는지" 행위로 표현). 단 줄 머리의 `TASK-XXXX` 번호는 사내 추적 키로 **유지**한다 (이 항목의 유일한 예외). 치환 대상·방식은 §4.1 참조.
- **시각 기준 분리**. 커밋 author/commit 시각을 **세 시간대**(10:00–13:00 / 13:00–16:00 / 16:00–19:00) 로 나눈다. 한 TASK 가 두 시간대에 걸치면 각 시간대에 나눠 표기하고, 무엇이 각 시간대에 들어갔는지 명시한다.
- **보고일 경계 = 19:00**. 보고서가 다루는 하루는 **전날 19:00 ~ 당일 19:00** 이다. 즉 (a) **전날 19:00 이후** 작업은 당일 보고서의 **10:00 ~ 13:00 구간 안에 '전날(19:00 이후)' 하위 섹션으로 묶어 포함**하고, (b) **당일 19:00 이후** 작업은 당일 보고서에서 빼서 **익일** 보고서로 이월한다(당일 보고서에는 이월 건수만 각주로 남긴다). **전날분 표시는 섹션 구분으로만 하며, 개별 TASK 줄에 `(이전날)` 같은 마커를 붙이지 않는다.**

## 절차

> **핵심 흐름**: 기계적 집계(날짜·커밋수집·보고일 경계 분류·TASK 그룹핑·시간대 배정·머지 접기·별첨 휴리스틱·각주)는
> **사전 스크립트가 한 번에** 처리한다. 당신(AI)은 그 결과 digest 를 받아 **판단만 마감**한다:
> §4.1(산출물 요약·내부 용어 일반화)·§4.2(제품 vs 별첨 최종 분류)·§4.3(시간대 내부 카테고리 그룹화)·§6(형식 출력). 신속 전달이 목표.

### 1. 사전 집계 실행 (스크립트 우선)
날짜·저장소·커밋수집·그룹핑·시간대 배정을 손으로 하지 말고 **집계 스크립트를 먼저 실행**한다. 스크립트는 이 SKILL 과 같은 디렉터리(`.claude/commands/_template/daily-report-collect.py`)에 있다 — 현재 프로젝트의 저장소 루트를 먼저 구해 그 경로를 `--repo` 로 명시해 호출한다:
```bash
REPO="$(git rev-parse --show-toplevel)"
python3 "$REPO/.claude/commands/_template/daily-report-collect.py" [YYYY-MM-DD] --repo "$REPO"   # 날짜 인자 없으면 오늘
```
- 인자가 있으면 그 날짜, 없으면 **오늘** 을 대상으로 한다 (스크립트가 알아서 처리).
- `$REPO` 는 반드시 **현재 소비자 프로젝트의 git 저장소 루트**여야 한다 (`.claude/commands/_template` 자체는 별도 submodule 이므로, 그 안에서 `git rev-parse --show-toplevel` 을 실행하면 submodule 루트가 나와 잘못된 대상을 가리킨다 — cwd 가 소비자 프로젝트 안일 때 위 명령대로 실행하면 올바르게 해소된다).
- 스크립트는 **결정론적**으로 아래를 이미 끝내 digest 로 출력한다 — 재계산·재조회하지 말고 그대로 신뢰한다:
  - **커밋 수집**: 보고일 경계(19:00) 기준 window(전날 19:00 ~ 익일 00:00)를 `git log --all` 로 수집.
  - **TASK 그룹핑**: `TASK-XXXX` / `TASK-YYYYMMDD[Thhmmss]-slug` / `TASK §NN` 세 형식 모두 인식해 묶음. slug 가 다르면 별개 그룹.
  - **시간대 배정**: 각 그룹을 10–13 / 13–16 / 16–19 에 배치. 전날 19:00 이후분은 10–13 의 `전날(19:00 이후)` 하위 섹션, 당일 00:00~10:00 분은 10–13 흡수(각주 시각), 당일 19:00 이후분은 이월(각주 건수만).
  - **머지 접기**: 순수 머지 커밋은 개별 그룹 대신 `순수 머지 커밋 N건` 한 줄로 접음(§4.1 흡수 대상).
  - **별첨 휴리스틱**: 변경 파일 경로로 `힌트:제품 / 힌트:별첨` 을 미리 표시(제품 소스 `unit/feature-*/src/`·`shared/*.py`·마이그레이션 파일 유무). **힌트일 뿐 — §4.2 로 확정하는 건 당신.**
  - **각주 사전 계산**: 10:00 이전 흡수 시각·전날 야간 건수·19:00 이후 이월 건수.
  - 각 그룹에 커밋 subject 원문·`changed`(상위 디렉터리)·`scope`(feature)·커밋수를 함께 실어, 요약·분류 판단 재료를 제공한다.
- **커밋 0건**이면 digest 가 "해당일 커밋 없음" 을 알린다. 그대로 보고하고, 다른 저장소/브랜치 확인이 필요한지 한 줄로 안내한다.
- **디버깅·정밀 필요 시** `--json` 으로 기계 판독용 구조도 얻을 수 있다.

> **스크립트 실패/부재 시 폴백**: 스크립트가 오류를 내거나 없으면, 아래 수동 수집으로 대체한다(결과는 동일 규칙으로 판단).
> ```bash
> REPO="$(git rev-parse --show-toplevel)"
> DAY=<대상날짜>; PREV=$(date -d "$DAY -1 day" +%F); NEXT=$(date -d "$DAY +1 day" +%F)
> git -C "$REPO" log --all --since="$PREV 19:00" --until="$NEXT 00:00" \
>   --pretty="%cd %h %s" --date=format:'%m-%d %H:%M' --reverse
> ```
> `%m-%d` 접두로 전날/당일 구분, `%h` 해시는 그룹핑 내부 참고(줄에 노출 금지). merge+feature 중복은 하나로 합침.

### 2·3. 저장소 식별 · 커밋 수집 → §1 스크립트가 흡수
과거 절차의 §2(대상 저장소 식별)·§3(해당일 커밋 수집·시각 분류)은 §1 스크립트가 결정론적으로 수행한다. (아래 §4.1/§4.2/§5/§6 번호는 digest 출력·상호 참조가 그대로 쓰므로 유지한다.)

### 4. TASK 그룹핑 (스크립트 완료 — AI 는 확인만)
그룹핑은 스크립트가 끝냈다. digest 의 각 `[그룹]` 이 하나의 논리적 작업 단위다. 당신은:
- 같은 이니셔티브의 인접 그룹(예: `TASK §56` / `TASK §56.3`)이 한 줄로 묶는 게 자연스러우면 요약 단계에서 합친다.
- 각 그룹의 커밋 subject 원문을 아래 §4.1 로 다듬어 **한 줄 요약**으로 만든다. (줄 머리 `TASK-XXXX` 번호만 추적 키로 유지.)

#### 4.1 요약 서술 — 작업(산출물) 중심 추출 + 내부 용어 일반화 (필수)
각 TASK 줄의 **요약 서술**(`**TASK-XXXX** — <요약>` 의 `<요약>` 부분)은 커밋 메시지를 그대로 옮기지 말고, 두 단계를 거친다: **(A) 산출물만 남기고 내부 진행 절차를 덜어낸 뒤 → (B) 남은 내용을 일반 독자가 읽을 수 있는 용어로 풀어 쓴다.** 줄 머리의 `TASK-XXXX` 번호만 추적 키로 유지한다(불변 제약 참조).

##### (A) 제외 — 줄에 쓰지 않는 내부 진행 절차 (필수)
보고서 줄은 **"무엇을 만들었/고쳤는지"** 만 담는다. 다음은 작업을 완성하기 위한 **진행 절차**일 뿐 산출물이 아니므로 **줄에서 제거**하고, "+ ~" 형태로도 덧붙이지 않는다 (한 TASK 의 여러 커밋을 최종 산출물 한 줄로 접을 때 함께 흡수).
- **검증/확인 절차** — 실기기·실브라우저 검증, `render-injection`, "라이브 실측", "시각검증 PASS" 류 **전부 제거**. (검증을 통과한 것은 기본 전제이지 그날의 작업이 아니다.)
- **증적·문서 기록** — `evidence 기록`, `evidence 스크린샷`, `마감`, docs-only 후속 커밋 → 제거(앞선 산출물 줄에 흡수).
- **반복·정비 작업** — `캐시버스터 / cache-buster bump`, `styles.css ?v= bump`, `rebase`, `재번호`, `tz 수정`, `lint`, `Merge pull request` → 제거.
- **같은 TASK 내 자체 후속 수정** — 구현 중 스스로 발견해 같은 TASK 에서 고친 버그는 **별도 절로 열거하지 말고** 최종 산출물 서술에 녹인다 (그 기능이 의도대로 동작하도록 마무리한 것이므로 결과 문장 하나로 충분).
- **판정 기준**: "이 문구가 빠지면 *무슨 일을 했는지* 가 사라지는가?" → 사라지면 산출물(남긴다). 사라지지 않고 *어떻게/얼마나 꼼꼼히 했는지* 만 빠지면 진행 절차(제거).
  - 예: `작업 화면 좌측 대화목록 첫 진입 시 최근 일자 그룹만 펼침 (TASK-...) evidence 기록` → `**TASK-...** — 작업 화면 대화 목록을 처음 열 때 최근 날짜 그룹만 펼치도록 변경` (검증·증적 제거).
  - 예: 릴리즈 노트 구현 + "접힘 무력화 수정" + 캐시버스터 + evidence → `**TASK-...** — 작업 화면과 관리 콘솔에 릴리즈 노트 추가` (후속 수정·캐시·증적 모두 흡수).

##### (B) 일반화 — 남긴 산출물 서술의 내부 식별자·약어 치환
(A) 를 거쳐 남은 산출물 서술에서, 프로젝트 내부에서만 통하는 식별자·약어를 일반 용어로 바꾼다.
- **의사결정/문서 코드** — `ADR-NNNN` 같은 결정 기록 번호는 빼고 결정 내용만: (예: `SSRF 사설망 경계 env 토글 (TASK-0228, ADR-0030)` → "내부망 접근 차단을 설정으로 켜고 끄게 함").
- **기능/유닛 코드** — `feature-0003`, `#0003`, `(#0003)` 같은 feature id 접미는 제거한다 (TASK 번호로 이미 추적됨).
- **내부 컴포넌트·잡 명** — 프로젝트 고유 worker/job/함수 식별자는 역할로 풀어 쓴다: (예: `insight-worker 분석 완료율 UI` → "데이터 분석 진행률 화면").
- **PR/이슈 번호** — `(#157)`, `Merge pull request #161` 류는 노출하지 않는다 (이미 미노출 규칙).
- **약어·영문 식별자 일반** — 위 표에 없더라도 대문자 약어·코드명·snake_case/kebab 식별자가 그대로 보이면 일반 용어로 바꾼다. **판단 기준: 그 프로젝트를 모르는 사람이 읽어도 무슨 작업인지 통하는가.**
- 단, 외부에도 통용되는 표준 용어(`SSE`, `MSSQL`, `MySQL`, `SSRF`, `LLM`, `UI` 등)는 그대로 두어도 된다 — 일반화 대상은 **프로젝트 내부에서만 통하는** 식별자다.

#### 4.2 산출물 분류 — 제품 기능 개발 vs 별첨(기능 개발 외) (필수)
§4.1 로 다듬은 각 산출물 줄을 다음 두 갈래로 나눈다. **시간대별 섹션(§5)에는 "제품 기능 개발" 만 들어가고, "기능 개발 외" 는 전부 보고서 최하단 별첨으로 뺀다.**

- **제품 기능 개발 → §5 시간대별 섹션.** 사용자·운영자가 실제 쓰는 **애플리케이션(제품)의 기능·화면·데이터 처리·권한·버그 수정** 처럼 **제품에 남는 변경**.
- **기능 개발 외 → 보고서 최하단 `별첨 (기능 개발 외)` 섹션.** 제품 기능이 아닌 다음 부류:
  - 개발·운영 **보조 도구·스킬·파이프라인** 신설/정비.
  - **프로젝트 템플릿 업그레이드**, 빌드/배포 인프라·스크립트, CI 정비.
  - 제품 코드 변경 없이 **문서·릴리즈노트·발표자료** 만 작성/정합.
  - 저장소 정비성 작업.

- **판정 기준**: "이 변경이 **제품(앱)을 쓰는 사람에게 보이거나 영향을 주는가**?" → 그렇다면 기능 개발(시간대별), 아니면 별첨. 애매하면 **제품 사용자 영향 유무**로 가른다.
- 별첨 줄도 §4.1 (산출물 중심 추출 + 내부 용어 일반화) 를 동일하게 적용한다. `TASK-XXXX` 번호가 있으면 유지, 없으면 주제명 한 줄.
- 별첨은 **시간대·전날/당일 하위 구분 없이** 한 목록으로 나열한다 (타임라인에서 빠지는 항목이므로). 단 보고일 경계(19:00) 규칙(§ 불변 제약·§5)은 동일 적용 — 당일 19:00 이후 별첨분도 익일로 이월(각주).

#### 4.3 시간대 내부 카테고리 그룹화 (필수 — 제품 기능 개발 줄에만)
§4.2 로 시간대에 배치된 산출물 줄들을, 같은 시간대 **안에서만** 다시 훑어 유사하거나 범위(scope)가 같은 TASK 를 카테고리 하위헤더로 묶는다. 목적은 "10–13/13–16/16–19 라는 시간 추적성은 유지하되, 그 안에서 무엇이 무엇과 관련된 작업인지 한눈에 보이게" 하는 것이다.

- **적용 단위**: 시간대 섹션 각각(전날/당일 하위섹션 포함)을 **독립적으로** 판단한다. 다른 시간대의 항목과 묶지 않는다 — 시간대를 넘나드는 카테고리는 만들지 않는다.
- **클러스터링 기준**: digest 의 `scope:`(feature 영역)·`changed:`(디렉터리) 와 §4.1 로 다듬은 요약 서술을 함께 보고, **①같은 범위(scope) + ②비슷한 작업 성격**(성능 개선 / 기능 추가 / 버그 수정 / UX 개선 등) 두 축을 함께 고려해 자연스러운 묶음을 찾는다. 고정된 카테고리 목록은 없다 — 그날 실제 작업 내용에서 매번 새로 판단한다.
- **성립 조건**: 같은 시간대 안에 **유사 TASK 가 2건 이상**일 때만 카테고리 헤더를 만든다. 1건뿐인 성격은 카테고리로 묶지 않고 헤더 없이 그 시간대 목록에 단독 bullet 로 남긴다 (과도한 세분화·"기타" 카테고리 남발 방지 — 억지로 모든 줄을 카테고리에 넣지 않는다).
- **카테고리명**: 명사구로 간결하게 (예: "그래프 렌더링 성능 개선", "그래프 상세 패널 개선", "AI 분석 결과 개선"). §4.1(B) 와 동일하게 내부 약어 없이 일반 용어로 짓는다.
- **정렬**: 카테고리는 그 카테고리에 속한 항목 중 **가장 이른 시각**을 기준으로 시간대 내 순서를 매기고, 카테고리 내부 항목은 시각순으로 나열한다. 카테고리에 속하지 않는 단독 항목도 자신의 시각을 기준으로 같은 순서 규칙에 끼워 넣는다 — 카테고리 블록과 단독 bullet 이 뒤섞여도 시각 순서는 유지된다.
- **별첨**에도 같은 원리를 적용할 수 있다 — 별첨 항목이 2건 이상 유사하게 몰리면 같은 방식으로 하위헤더를 쓴다 (일반적으로 항목이 적어 필요 없는 경우가 많다).
- 출력 형식은 §6 참조.

### 5. 시간대별 분리 출력 (스크립트 배치 완료 — AI 는 검토·미세조정)
스크립트가 각 그룹을 이미 §5 규칙대로 배치해 digest 의 구간 헤더(`10:00 ~ 13:00 (당일)`, `전날(19:00 이후) 하위 섹션`, `13:00 ~ 16:00`, `16:00 ~ 19:00`)와 별첨 후보로 나눠 놓았다. 당신은 아래 규칙에 비추어 **검토·미세조정**만 하면 된다 (특히 한 그룹이 두 시간대를 걸칠 때 `⚠구간 걸침` 표시분의 분할, 별첨 후보의 §4.2 재확정). 배치 규칙(참고):
- 각 커밋을 **보고일 경계(19:00)** 기준으로 분류한다:
  - **전날(PREV) 19:00 이후** 커밋 → 당일 보고서의 **10:00 ~ 13:00 구간 안의 '전날(19:00 이후)' 하위 섹션으로 편입**한다 (개별 줄에 `(이전날)` 마커를 붙이지 않고, 섹션 구분으로만 표시).
  - **당일(DAY) 19:00 이후** 커밋 → 당일 보고서에서 **제외**하고, "당일 19:00 이후 N건은 익일 보고서로 이월" 을 마지막 각주로 밝힌다 (보고서 본문 줄로는 출력하지 않는다).
  - 그 외 당일 커밋은 **첫 커밋 시각** 으로 다음 세 시간대에 배정한다 (하한 포함, 상한 제외):
    1. **10:00 ~ 13:00**
    2. **13:00 ~ 16:00**
    3. **16:00 ~ 19:00**
  - 당일 **10:00 이전(00:00~10:00)** 커밋은 10–13 구간에 흡수하되 해당 시각을 한 줄 각주로 밝힌다 (예: "09:55 커밋 1건은 10–13 구간에 포함").
- **별첨 부류(§4.2)는 시간대 배정 대상이 아니다** — '기능 개발 외' 로 판정된 산출물은 첫 커밋 시각과 무관하게 세 시간대 어디에도 넣지 않고 최하단 `별첨 (기능 개발 외)` 섹션으로 모은다. 시간대 배정·전날 하위 섹션·10:00 이전 흡수 규칙은 **제품 기능 개발 줄에만** 적용한다.
- 한 TASK 의 커밋이 두 시간대를 걸치면 각 시간대 줄에 나눠 적고, 어느 변경이 어느 시간대에 들어갔는지 명시한다. 전날분과 당일분이 한 TASK 에 섞이면 10–13 안의 '전날(19:00 이후)' 하위 섹션에 둔다 (주된 작업 시각 기준 — 줄에 마커는 붙이지 않는다).
- 각 시간대 헤더에는 해당 구간에 실제로 커밋이 존재하는 **첫시각 ~ 마지막시각** 을 괄호로 적는다. 커밋이 없는 시간대는 헤더를 생략한다.
- 시간순 정렬 (전날 19:00 이후 분은 10–13 의 맨 앞 '전날(19:00 이후)' 하위 섹션에 둔다). 배치가 끝나면 §4.3 을 적용해 시간대 **내부**에서 카테고리 하위헤더를 붙인다 (다른 시간대와 섞지 않음).

### 6. 출력 형식 (보고서용)
아래 형식을 **그대로** 출력한다. 마크다운 헤더 + bullet, 각 bullet 은 `**TASK-XXXX** — 한 줄 요약` (줄 끝에 해시/브랜치 id 없음, **줄에 `(이전날)` 류 마커도 없음**, **요약 서술은 §4.1 대로 산출물만 남기고 내부 진행 절차를 덜어낸 뒤 내부 약어를 일반 용어로 치환** — 검증·증적·캐시 갱신 같은 절차 문구를 "+ ~" 로 붙이지 않는다). §4.3 으로 카테고리가 성립한 TASK 는 `**<카테고리명>**` 굵은 라벨 줄 아래 bullet 으로 묶고, 카테고리가 성립하지 않은 단독 TASK 는 헤더 없이 그대로 나열한다.

전날 19:00 이후 작업이 있으면 10–13 구간 안을 **`**전날(19:00 이후)**` / `**당일**` 두 하위 섹션(굵은 라벨 줄)으로만 구분**한다. 전날분이 없으면 하위 라벨 없이 TASK 를 바로 나열한다. 카테고리 라벨은 이 전날/당일 라벨보다 한 단계 더 안쪽에서 적용된다(전날/당일 하위섹션 각각의 내부에서 독립적으로 카테고리를 판단).

```
## <대상날짜> 진행 작업

### 10:00 ~ 13:00 (<첫시각> ~ <마지막시각>)

**전날(19:00 이후)**
- **TASK-XXXX** — <전날 19:00 이후 작업 요약>

**당일**
**<카테고리명>**
- **TASK-XXXX** — <당일 작업 요약>
- **TASK-YYYY** — <당일 작업 요약>

- **<주제>** — <카테고리 미성립 단독 TASK 한 줄 요약>

### 13:00 ~ 16:00 (<첫시각> ~ <마지막시각>)

**<카테고리명>**
- **TASK-XXXX** — <한 줄 요약>
- **TASK-YYYY** — <한 줄 요약>

**<카테고리명2>**
- **TASK-ZZZZ** — <한 줄 요약>
- **TASK-WWWW** — <한 줄 요약>

### 16:00 ~ 19:00 (<첫시각> ~ <마지막시각>)
- **TASK-XXXX** — <한 줄 요약>   (2건 이상 유사 TASK 가 없으면 카테고리 헤더 없이 그대로 나열)
...

---

### 별첨 (기능 개발 외)
- **TASK-XXXX** — <도구·스킬·템플릿 업그레이드·문서·발표자료·배포 인프라 등 기능 개발 외 산출물 요약>
- **<주제>** — <한 줄 요약>
```
- 전날분이 없는 시간대(13–16 / 16–19 등)는 하위 라벨 없이 곧바로 카테고리/단독 bullet 을 나열한다 — 전날/당일 구분은 **전날분이 섞이는 10–13 구간에만** 쓴다.
- 한 시간대 안의 TASK 가 전부 서로 다른 성격·범위라 카테고리가 하나도 성립하지 않으면, 카테고리 라벨 없이 기존처럼 flat 하게 나열한다 (카테고리는 가시성 개선 수단일 뿐 강제 구조가 아니다).
- **별첨 섹션은 기능 개발 외 산출물이 있을 때만** 출력한다(없으면 생략). 별첨 안에서는 시간대·전날/당일 하위 구분을 두지 않고 한 목록으로 나열하며, `TASK-XXXX` 번호가 있으면 유지한다. 별첨 항목이 유사하게 몰리면(§4.3) 같은 방식으로 카테고리 헤더를 쓸 수 있다.

**카테고리 그룹화 예시 (§4.3 적용 — 한 시간대 구간에 같은 범위의 TASK 8건이 몰린 경우):**
```
### 13:00 ~ 16:00 (14:20 ~ 15:53)

**그래프 표시 정확도 개선**
- **줌아웃 시 하이라이트 관계선 축약 정상화** — 특정 항목을 강조한 채 화면을 축소했을 때 관계선이 제대로 축약되지 않던 문제 수정
- **하이라이트 시 잔상 관계선 제거** — 항목을 강조할 때 관련 없는 관계선이 남아 보이던 잔상 문제 해결
- **관계선 투명도 오류 수정** — 그래프 관계선의 투명도가 이전 상태로 남아 있던 표시 오류 수정

**그래프 렌더링 성능 개선**
- **뷰포트 컬링·집계 노드 정리** — 화면에 보이지 않는 그래프 요소를 그리지 않고 집계 노드 크기·마커를 정리해 성능 개선
- **집계 해제·카테고리 밴드·테이블 뷰포트 컬링 개선** — 그래프 집계 노드 해제 조건, 카테고리 밴드 크기, 테이블 뷰포트 컬링을 개선해 성능 향상

**그래프 상세 패널 개선**
- **상세 패널 관계 읽기/쓰기 구분** — 그래프 상세 화면에서 참조 관계를 읽기·쓰기로 구분해 표시
- **상세 패널 관계 중복 병합** — 그래프 상세 패널에서 중복 표시되던 관계 정보를 하나로 병합
- **상세 패널 카메라 이동 버튼** — 그래프 상세 패널에 선택한 노드로 화면을 이동시키는 버튼 추가
```
같은 범위(scope) 라도 성격(표시 정확도 버그 / 성능 / UX)이 다르면 별개 카테고리로 나눈다 — scope 하나로 뭉치면 카테고리가 너무 커져 가시성 개선 효과가 없다.

**추출+일반화 예시 (§4.1 적용 — 커밋 메시지 → 보고서 줄):**
- `TASK-0243 MSSQL db-insights catalog 귀속 (#0003) 시각검증 PASS`
  → `**TASK-0243** — MSSQL 데이터 분석 결과를 데이터베이스별로 묶어 표시` *(검증 절차 "시각검증 PASS" 는 줄에 쓰지 않음 — §4.1(A))*
- `feat(datasource): SSRF 사설망 경계 env 토글 (TASK-0228, ADR-0030)`
  → `**TASK-0228** — 내부망 주소 접근 차단을 설정으로 켜고 끌 수 있게 함`
- `feat(web-ui): 릴리즈 노트 추가 (TASK-...)` + `fix: 접힘 무력화 수정 + styles.css 캐시버스터` + `docs: evidence 기록`
  → `**TASK-...** — 작업 화면과 관리 콘솔에 릴리즈 노트 추가` *(후속 수정·캐시 갱신·증적 기록은 최종 산출물 한 줄에 흡수 — §4.1(A))*
- `insight-worker 분석 완료율 UI` (내부 잡 명 일반화)
  → `**TASK-...** — 데이터 분석 진행률 화면 추가`

- 마지막에 총계 한 줄(예: "기능 개발 N개 TASK + 별첨 M건") 과, 근거가 git 로그 재구성임을 1줄 각주로 덧붙인다. **당일 19:00 이후 작업이 있으면 "당일 19:00 이후 N건은 익일 보고서로 이월" 을 함께 각주로 남긴다.**
- "오늘 진행" 의 기준이 커밋 시각이 아니라 특정 세션 범위라면 좁힐 수 있음을 1줄로 안내한다.

## 사용 예
- `/_template:daily-report` → 오늘 작업을 시간대(10–13 / 13–16 / 16–19)로 정리 (스크립트 사전 집계 → AI 요약·분류 마감)
- `/_template:daily-report 2026-06-09` → 지정일 작업을 시간대로 정리
- 내부적으로 `daily-report-collect.py [날짜] --repo <현재 프로젝트 루트>` 가 기계적 집계(수집·그룹핑·시간대 배정·머지 접기·별첨 힌트·각주)를 먼저 끝내므로, AI 는 요약(§4.1)·분류확정(§4.2)·카테고리 그룹화(§4.3)·형식출력(§6)만 처리해 **신속히** 전달한다.
- 보고일 경계는 **19:00** — 전날 19시 이후 작업은 당일 10–13 의 '전날(19:00 이후)' 하위 섹션으로 묶이고(줄 마커 없음), 당일 19시 이후 작업은 익일로 이월된다 (§5).
- 보고서 줄의 요약은 **작업(산출물) 중심** — 검증 절차·증적 기록·캐시버스터 같은 **내부 진행 절차는 빼고**, 결정 기록 번호·feature id·내부 job 명 같은 **내부 약어는 일반 용어로 풀어** 출력한다 (TASK 번호만 유지 — §4.1).
- 시간대별 섹션에는 **제품 기능 개발만** 담고, 도구·스킬·템플릿 업그레이드·문서·발표자료·배포 인프라 등 **기능 개발 외 산출물은 최하단 `별첨 (기능 개발 외)` 섹션**으로 분리한다 (§4.2).
- 한 시간대 안에 **유사하거나 같은 범위(scope)의 TASK 가 2건 이상** 몰리면 flat 나열 대신 **카테고리 하위헤더**로 묶는다 (예: "그래프 렌더링 성능 개선", "그래프 상세 패널 개선"). 시간대를 넘나들며 묶지 않고, 1건뿐인 성격은 헤더 없이 단독 bullet 로 남긴다 (§4.3).
