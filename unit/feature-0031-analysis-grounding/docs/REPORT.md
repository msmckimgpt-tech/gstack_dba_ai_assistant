# Report

노드 분석 접지(T1) 슬라이스 구현 완료 — 통계 증거층(L0) + payload 주입(L1) + thin 판정 재정의.
단위 테스트 통과(`COMPOSE_PROJECT_NAME=repo make test`, FAILED 0 · ruff 통과), 적대 리뷰 진행 중.

## 배경 — 진단

사용자 진단("단발성 분석 후 유사 노드 재귀의 일차원 구조")을 라이브 PG 실측으로 확증했고,
그 위에서 더 근본적인 공백을 찾았다.

| 관측 | 수치 |
|---|---|
| 분석 완료 노드 | ~10,000 (커버리지 14.6%) |
| 월 LLM 콜(node_analysis) | 10,620 |
| summary 평균 길이 | 94자 |
| 컨텐츠 클러스터 | 727 (32자 라벨만, 요약 없음) |
| 분석 입력의 데이터 실측 | **0** |
| 대화 답변 경로의 분석 참조 | **0** |

즉 병목은 "재귀 구조"가 아니라 **입력 접지 부재**였다. 프롬프트가 명시적으로 "이름 규칙에서
가장 그럴듯한 의미를 추론하고 단정하라"고 지시하고 있었고, 그 결과 1만여 건의 추측이 정본
노릇을 하고 있었다.

## 리서치 요지 (전문: `docs/improvements/analysis-orchestration/RESEARCH.md`)

- **GraphRAG / LazyGraphRAG** — 계층 커뮤니티 요약이 전역 질의 토큰을 크게 줄인다. 다만 사전
  요약을 전량 만들 필요는 없다(LazyGraphRAG: 사전요약 0으로 동등 품질, 비용 700배↓).
- **DBAutoDoc(2025)** — 통계 기반 결정적 키 탐지 + LLM 정제가 LLM 단독 대비 FK 판정 F1 +23p.
  **이득은 통계에서 나오고 샘플값에서 나오지 않는다** — 본 cycle 의 설계 근거.
- **Anthropic multi-agent** — 성능은 오르지만 토큰 15배. 2026 프로덕션의 다수는 결정적 백본 +
  특정 스텝만 LLM.
- **LLM-as-judge** — 소형 판정자로 검증층을 붙이는 비용이 크게 낮아졌다(T3 근거).

## 사용자 요청에 대한 답 (요약)

- "오케스트레이터가 분석 AI 를 파견·집계하는 구조로 갈 수 있나?" → **집계는 채택, 파견은 이미 있다.**
  fan-out 은 결정적 큐로 구현돼 있어 LLM 오케스트레이터로 바꾸면 토큰 15배와 비결정성만 얻는다.
  LLM 이 값어치를 내는 자리는 계획이 아니라 집계(L2)와 검증(T3)이다 — ADR-0031-02.
- "더 좋은 구조가 있나?" → **있다. 다만 요약보다 접지가 먼저다.** 접지 없이 상위 요약을 얹으면
  추측을 압축해 더 권위 있게 만들 뿐이고, 나중에 접지를 넣으면 요약을 전량 재생성해야 한다 —
  ADR-0031-01.

## 구현 (T1)

1. **L0 증거 수집** — `metadata_stats.py` 신규. 카탈로그(Stage 0) → 표본 100(Stage 1) →
   표본 1,000(Stage 2) → 정밀(Stage 3). 승격은 하루 1단계 + 주간 시간창 상한 + 운영자 knob.
   `ds` 예산 게이트 위에서 fail-soft.
2. **저장** — alembic 0050 additive 2 테이블. `value_pattern` CHECK 제약이 원시값 적재를 거부한다.
3. **L1 주입** — `_build_payload` 에 `evidence` 블록. 증거가 없으면 키 자체가 없어 종전과 동형.
4. **프롬프트** — Evidence-first 규칙 신설(증거 우선, 표본임을 명시, 원시값 요구 금지),
   untrusted-data 대상에 `evidence` 추가, caveats 에 증거 기반 위험 근거 부여.
5. **thin 재정의** — 길이 → 항목 충족도. 하한 기본값 120 → 20.

## 구현 중 확정한 설계 변경

- **문자열 min/max 배제** — 설계 초안(`RESEARCH.md` §11.3)에는 `min_text`/`max_text` 가 있었는데,
  그것이 사실상 원시 샘플 1건이고 이름·이메일 컬럼에서 곧 PII 임을 확인해 배제했다. 길이 분포 +
  패턴 클래스로 대체했고 RESEARCH.md 도 정정했다 — ADR-0031-03.
- **thin 하한 20자** — 처음 40자로 잡았으나 테스트가 반증했다: 계약대로 쓴 한국어 한 문장이
  ~28자라 40자 하한도 정상 분석을 걸러낸다. 실측에 맞춰 20자로 내렸다.
- **수집 스케줄러 미도입** — 분석 흐름이 대상을 정한다(ADR-0031-05). 쓰이지 않을 통계를 모으는
  낭비가 없고, 이미 페이싱된 경로의 부하 특성을 그대로 물려받는다.
