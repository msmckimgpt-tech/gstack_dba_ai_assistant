개발 배경 · 왜 이 일을 했나

"기능은 갖췄는데, 실제로 잘 쓰기가 아직 어렵다"

상황 (지난 기간까지)

  • 자연어 어시스턴트, MySQL＋MSSQL 다중 연결, 그룹 대화, 무중단 배포 토대까지 갖췄습니다.
  • 데이터베이스 메타데이터(테이블·컬럼 뜻)는 이제 막 그래프로 보기 시작한 단계였습니다.

문제 (이번에 풀 것)

  • 답의 속도·깊이를 사용자가 조절할 수 없고, 운영값은 바꾸려면 재배포가 필요했습니다.
  • 공유하면 대화 전체가 노출돼 민감 구간을 가릴 수 없었습니다.
  • 수천 개 테이블은 여전히 평면 목록이라 관계·의미 파악이 어려웠고, AI 운영 상태를 한눈에 볼 화면이 없었습니다.
그래서 이번 기간의 목표 — (1) 답을 필요에 맞게 조율하고, (2) 안전하게 나눠 쓰며, (3) 지식이 스스로 쌓이게 하고, (4) 대규모 데이터베이스를 지도처럼 탐색하며, (5) 운영자가 AI를 한눈에 관제하고, (6) 그 모든 게 끊김 없이 돌게. 아래는 사용자가 화면을 만나는 순서로 설명합니다.

1. 답을 조율한다 (추론 강도·운영값 설정) 신규

같은 질문도, 필요에 맞게 "빠르게" 또는 "깊게"

1배경·문제

모든 질문이 똑같은 양의 '생각'으로 처리돼, 간단한 조회는 느리고 어려운 분석은 더 깊이 팔 수 없었습니다. 운영값(응답 대기시간 등)은 바꾸려면 재배포가 필요했습니다.

2화면 흐름
질문 입력›＋ 메뉴 · 추론 강도›낮음·일반·높음·매우높음›대화별 저장

운영자는 관리 콘솔 시스템 > 설정에서 대기시간·모델별 생각 예산을 즉시 조정.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

사용자 선택권 + 안전. 상용 어시스턴트처럼 강도를 고르되, '일반'은 아무것도 바꾸지 않게 설계했습니다 — 그래야 선택기를 안 건드린 대화가 더 똑똑한 모델의 기본값을 잃지 않습니다(조용한 성능 강등 방지).

5기대 효과 개발·검증 완료

간단한 질문은 빠르게, 어려운 질문은 깊게. 운영값은 재배포 없이 조정. 실제 화면 검증(실 Windows)까지 통과했습니다.

2. 안전하게 나눠 본다 (공유 범위 지정) 신규

대화의 "보여줄 구간"만 나누고, 나머지는 완전히 가립니다

1배경·문제

대화를 공유하면 처음부터 끝까지 전부 노출됐습니다. 앞부분에 민감한 데이터·다른 계정 정보가 있어도 가릴 수 없었고, 참여자가 나중에 "앞 대화 보여줘"라고 AI를 속여 캐낼 위험도 있었습니다.

2화면 흐름
말풍선 ☰ 메뉴›여기부터/여기까지 공유›공유·초대·복제›가린 구간은 어디서도 안 보임
3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

보안 최우선. 가린 구간을 화면에서만 숨기는 게 아니라 AI가 읽는 데이터 자체에서 빼버렸습니다(물리 배제) — 없는 것은 아무리 캐물어도 나오지 않습니다. 오류가 나면 무조건 차단(안전 우선), 재공유로 범위를 넓히는 것도 막았습니다.

5기대 효과 실화면 검증 예정

민감 구간 유출 없이 부분 공유. 기능·보안 개발 완료(적대적 보안 리뷰로 초기 누출 1건을 찾아 봉인). 실제 화면 시각검증은 배포 후 확인 예정입니다.

3. 스스로 똑똑해지는 지식 (용어·코드값 자율수집) 이어받음

대화에서 배운 뜻을, 검토를 거쳐 지식으로 쌓습니다

1배경·문제

회사 고유 용어와 코드값(예: 상태 1=결제완료)을 사람이 일일이 등록해야 했습니다. 지난 기간에 용어 사전 수단은 갖췄지만, 후보가 여기저기 흩어져 관리가 번거로웠습니다.

2선순환 흐름
대화·답변›AI 후보 제안›채택 인박스›관리자 검토·채택↻더 정확한 답

신뢰도 높은 후보는 자동 등록, 낮으면 검토 큐로 — 나쁜 지식 오염 방지.

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

자율성 + 오염 방지. 지식은 답변에 직접 쓰이므로 자동 학습을 일부러 막아왔지만, 전수 기록·되돌리기·사람 검토를 붙여 안전하게 자율수집을 열었습니다. 코드값 사전은 검증된 용어 사전과 같은 방식으로 추가.

5기대 효과 일부 실화면 검증 예정

손이 덜 가면서 지식이 쌓여 답 정확도에 기여. 개발 완료(용어 사전은 실화면 검증 통과, 코드값·채택 인박스는 배포 후 확인 예정).

4. 데이터베이스를 '지도'로 탐색한다 (관계도 뷰) 이어받음·대폭 확장

수천 개 테이블을, 관계·역할·흐름이 보이는 지도로

1배경·문제

운영 데이터베이스는 테이블 8,000개 이상인데 화면은 평면 목록이라, 무엇이 무엇과 연결되고 각 테이블이 무슨 역할인지 알기 어려웠습니다. 게임 데이터베이스는 관계(외래키)가 거의 선언 안 돼 연결선조차 없었습니다.

2탐색 흐름 (영역별)
제품 카테고리›스키마 묶음›유사 그룹›테이블·컬럼›관계·함수 추적

역할 색상 · 실선(신뢰)/점선(추정) 관계 · 함수·프로시저 노드 · AI 능동 분석.

3변경 전 → 후
실제 화면 대신 개념 도식 · 실선=신뢰 관계, 점선=추정 관계
4왜 이 방향

탐색성 + 정직성. 관계가 없는 데이터베이스도 이름·구조로 관계를 추론하되, 추정(점선)과 신뢰(실선)를 구분해 과장하지 않습니다. 실제 대화·데이터로 스스로 교정(맞으면 실선, 틀리면 숨김). 배치는 흔들림 없는 결정론 방식을 택했습니다.

5기대 효과 핵심 라이브 검증 일부 확인 예정

낯선 데이터베이스도 구조·흐름을 눈으로 파악. 함수·프로시저 라이브 적재·핵심 상호작용은 실화면 검증 통과. 일부 후속 화면·의미 그룹 실채움·체감 속도(FPS)는 확인 예정.

5. AI를 한눈에 관제한다 (운영 현황 패널) 신규

AI가 지금 무엇을·얼마에·얼마나 빠르게 하는지 한 화면에

1배경·문제

AI가 여러 경로(대화·프롬프트 자동작성·메타데이터 자동완성·백그라운드 분석)에서 일하는데, 상태·비용·지연·건강을 한눈에 볼 화면이 없어 문제를 늦게 알아챘습니다.

2화면 흐름
관리 콘솔 · 감사›AI 운영 현황›상태·KPI·주의›활동 클릭 → 상세·대화 링크
3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

운영 편의 + 정직한 지표. 지연을 '답변 전체 시간'(길이에 좌우) 대신 '단계 사이 간격'으로 재정의해 진짜 신호를 봅니다. 계측이 안 되는 경로는 각주로 표시해 "총비용"을 오해하지 않게 했습니다.

5기대 효과 실화면·지표 축적 예정

문제를 빨리 발견·진단. 개발 완료(연결 품질 표시는 실화면 검증 통과). 패널 실화면과 재정의한 지연 지표는 배포 후 실트래픽으로 확인 예정.

6. 끊김 없이·스스로 회복한다 (안정성·인프라) 완료

배포하고 재시작해도, 사용자는 끊김을 느끼지 않게

1배경·문제

병합할 때마다 자동 재배포가 일어나 그때마다 잠깐 끊겼고(502), 데이터베이스 재시작도 오류를 냈습니다. 거대한 코드 한 파일(약 3만 줄)은 한 곳만 고쳐도 다른 곳이 깨질 위험이 있었습니다.

2동작 구조
분배기(로드밸런서)›웹 A / 웹 B 한 대씩 교체›DB 재시작=대기 후 완료›중단 0

거대 파일은 21개 모듈로 정리(겉보기 동작 그대로).

3변경 전 → 후
실제 화면 대신 개념 도식
4왜 이 방향

안정성·운영편의. 자동 배포가 잦으니 표준 분배기로 항상 최소 한 대는 정상이게. 코드 분할은 겉보기 동작을 안 바꾸는 방식으로 안전하게. AI도 실시간 대화는 항상 최선 모델로만(조용한 강등 차단).

5기대 효과 라이브 실증 후속

배포·재시작 중 중단 0 실증(부하 104건 정상 / DB 재시작 중 읽기·쓰기 오류 0건). 코드 정리 완료. 자동 롤백·일부 재배포는 검증 후속.

기대 효과 · 성과 종합

검증된 성과와, 앞으로 더 키울 발전 과제

검증됨 근거 있는 성과

  • 무중단 운영: 배포 중 부하 104건 전부 정상·접속 중단 0, DB 재시작 중 읽기/쓰기 오류 0건(단일 호스트 부하 시험).
  • 데이터베이스 지도: 함수·프로시저 2,201개 라이브 적재, 핵심 상호작용 실화면 검증 통과.
  • 답 조율·운영값 설정 실화면 검증 통과 — '일반=기본값 유지'로 조용한 강등 방지.
  • 서버 조회 속도: 이웃 관계 조회 약 60배(서버측 실측, 9.5초→0.15초).
  • 웹 코드 148경로 → 21모듈 정리 완료(겉보기 동작 불변).

발전 과제 앞으로 더 키울 영역

  • 실화면 시각검증 — 공유 범위·운영 관제 패널·지도 일부 후속 화면.
